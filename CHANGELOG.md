# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

No versioned releases have been cut yet. The app is pre-release; this file will grow as milestones land. Entries are dated; each is one concise line describing a feature, foundation shift, or substantive fix.

## [Unreleased]

- 2026-04-25: Refactored `/account` into a three-tab layout ("Profile & preferences", "Account & security", "Danger zone") with URL-synced state (`?tab=`), vertical `TabsList` on desktop + horizontal on mobile, lucide tab icons. Installed `@monark/avatar`, `@monark/tabs`, `@monark/sonner`, `@monark/theme` via shadcn CLI. Ported `monark/ui/styles/theme.css` (brand orange `oklch(0.723 0.168 59.48)` + 5-hue chart palette) directly into `globals.css` because the published registry's `theme.json` lags the local source-of-truth. Added heading font-weight + letter-spacing rule from the theme spec. `<Toaster />` wired into the root layout; timed "saved" spans replaced with toasts across profile / password / email-change / totp / danger-zone. Profile avatar now uses `<Avatar />` + `<AvatarFallback />` instead of a hand-rolled div. Trimmed `font-mono` out of product UI; kept on dev overlay surfaces and on opaque tokens (TOTP base32 secret, recovery codes).
- 2026-04-25: Extracted `TrustedDeviceCard` to `services/web/src/components/trusted-device-card.tsx` with a reusable, schema-agnostic prop shape (label, userAgent, first/lastSeenAt, lastSeenIp, country, totpVerifiedAt, isCurrent, onRevoke, size, labels). Uses lucide `Laptop` / `Smartphone` / `Tablet` glyphs auto-detected from the UA string, outlined card with muted glyph chip, TOTP-verified badge, optional "this device" pill, and destructive revoke slot. Both `/account` trusted-devices section and the dev overlay panel now consume this. Intent: lift to `@monark/ui` as `trusted-device-card` once dogfooded.
- 2026-04-25: Added avatar upload to `/account`; `avatars` Supabase Storage bucket declared in `supabase/config.toml` (public-read, 2 MiB cap, JPEG/PNG/WebP only), SQL migration `20260425000000_avatars_bucket_rls.sql` adds `storage.objects` RLS so authenticated users can only insert/update/delete under `avatars/<auth.uid()>/*`, `uploadAvatarAction` / `removeAvatarAction` server actions route through the cookie-authenticated SSR Supabase client (no secret-key crossing), profile section gains a circular preview + upload/replace/remove controls. Server-side sharp crop + resize + WebP conversion deferred; uploads stored as-is up to 2 MB.
- 2026-04-25: Added email change flow to `/account`; `requestEmailChangeAction` verifies current password through a non-persisting Supabase client then calls `supabase.auth.updateUser({ email })` so Supabase owns SMTP; `/auth/confirm?type=email_change` is now a branch of the existing route that calls the new `users.syncEmail` tRPC mutation to mirror the new address into our shadow `User.email` and emits `user.email-changed` (with `previousEmail` + `newEmail`), then force-signs-out and redirects to `/signin?emailChanged=1`. Profile section exposes a "Change email" inline form. Duplicate-email / same-email / bad-password branches surface i18n errors. `PendingEmailChange` schema kept for future admin flows but unused in the self-serve path.
- 2026-04-25: Added account deletion + 14-day grace to `/account`; `/account/delete` page lists what the flow does (soft-delete of memberships, anonymize contributions, audit retention, 14d cancel window) and requires typing the user's email to confirm, `users.requestAccountDeletion` stamps `deletedAt = now` and emits `user.deletion-requested` (with `deletionCompletesAt`), action signs the user out locally and redirects to `/signin?deletionScheduledAt=<iso>`. Danger-zone card on `/account` flips to an amber "Deletion scheduled" banner while `deletedAt` is set with a one-click "Cancel deletion" (`users.cancelAccountDeletion` clears the stamp + emits `user.deletion-canceled`). Hard-delete cron (anonymize + `supabase.auth.admin.deleteUser`) deferred to the ops scheduler pass.
- 2026-04-24: Added `/account` profile + security page as the post-sign-in landing (signin / signup / email-confirm / totp-verify all redirect here now). Sections: profile (display name blur-save, locale toggle that persists via `users.updateProfile` + updates the `NEXT_LOCALE` cookie, read-only email), password change (current-password verified through a non-persisting Supabase client, then `auth.updateUser` rotates the session cookie, emits `user.password-changed`), TOTP (full enroll / QR / recovery-codes / regenerate / disable flow, mirrors the dev overlay in a proper card), trusted devices (list + revoke). `users.updateProfile` tRPC mutation added (emits `user.profile-updated` with `changed` array), `auth.notifyPasswordChanged` mutation added so the web layer doesn't cross the tier boundary. Avatar upload, email change, and account deletion deferred.
- 2026-04-24: Added auth-totp MVP to `@monark/auth`; `TotpSecret` + `RecoveryCode` Prisma models with AES-256-GCM-encrypted secrets (`TOTP_ENCRYPTION_KEY` env var on api) and bcrypt-hashed 10-code recovery set, `otplib.authenticator` with ±1 window, `beginTotpEnrollment` / `confirmTotpEnrollment` / `verifyTotpCode` / `verifyRecoveryCode` / `regenerateRecoveryCodes` / `disableTotp` / `getTotpStatus` / `requiresTotpChallenge` / `markDeviceTotpVerified` helpers, `auth.totp.*` tRPC sub-router, `totp.enabled` / `totp.disabled` / `totp.recovery-code-used` events, `auth.totp-trust-devices` (default on) + `auth.totp-required-admin` (default off) feature flags. Sign-in flow now routes through `/signin/totp` when a challenge is required: `monark_totp_pending` cookie + middleware gate redirect all protected routes until the code is verified; trusted-device `totpVerifiedAt` is stamped on success so subsequent sign-ins on that device skip the challenge. Dev overlay "totp" panel dogfoods enroll / recovery-codes / disable. `/account/security/totp` settings page, admin soft/hard-wall enforcement, 5/min rate limit, admin reset escape hatch, and stale-enrollment cleanup deferred.
- 2026-04-24: Added auth-trusted-devices MVP to `@monark/auth`; `TrustedDevice` Prisma model (cookieHash stored, raw cookie never persisted), `recognizeOrRegister` + `listTrustedDevices` + `revokeTrustedDevice` helpers, `auth.trustedDevices.{mine, recognize, revoke}` tRPC sub-router, `monark_device_id` cookie (HTTP-only, SameSite=Lax, 400d) set from signin / signup / email-confirm flows, `ua-parser-js`-derived "Chrome on macOS"-style labels, `trusted-device.added` + `trusted-device.revoked` events, `auth.trusted-devices` feature flag (default on) gates the recognition path. Security page UI, new-device notification email, per-device Supabase session revocation, IP-to-country resolution, and TOTP-skip consumer deferred.
- 2026-04-24: Dev overlay gained a "trusted devices" panel with per-device first/last-seen timestamps, IP, and inline revoke.
- 2026-04-24: Moved all web server actions off direct `@monark/*/server` imports; added `auth.signUp` / `auth.notifySignedIn` / `auth.notifySignedOut` / `auth.markOwnEmailVerified` / `auth.requestConfirmationResend` tRPC mutations and a vanilla `createServerTrpcClient` helper for server-actions / route-handlers, restoring the service-tier boundary. Added `AppError` → `TRPCError` translation middleware on `publicProcedure` so clients can branch on `error.data.code`.
- 2026-04-24: Fixed sign-in / sign-out state not reflecting in UI after server-action redirects; `TrpcProvider` now subscribes to Supabase `onAuthStateChange` and invalidates the React Query cache so session-dependent queries (users.me, rbac, trusted-devices, current-org) refetch with the new token without a manual reload.
- 2026-04-24: Added email-verification to `@monark/auth`; `signUpUser` switched to Supabase's public `auth.signUp` so a confirmation email is emitted (Mailpit locally), new `/auth/confirm` route handler exchanges the OTP and flips `User.emailVerifiedAt`, `/signup/check-email` waiting page with resend button (5/hour per-user cap via `EmailResendAttempt`), `requireVerifiedEmail(ctx)` guard, `EmailVerifiedEvent` emitted on successful confirm. Password reset, invite bypass, and the `auth.require-verified-email` soft-gate flag deferred.
- 2026-04-24: Added password-strength rules to `@monark/auth`; `checkPasswordOffline` enforces length ≥ 12 + 3+ character classes + no email/display-name substrings, `checkPassword` adds HIBP k-anonymity (degrades open on upstream failure), signup form renders live per-rule checkmarks, `signUpUser` rejects before the Supabase admin call, new `auth.checkPassword` tRPC mutation for blur-time feedback. zxcvbn score + shadcn `PasswordInput` primitive deferred.
- 2026-04-24: Added auth-login-password MVP (`@monark/auth` + Supabase integration); `signUpUser` orchestrator with compensating auth/DB rollback, `signIn`/`signOut` server actions in web, `auth.ping` + `auth.session` tRPC queries, Supabase SSR cookie helpers + middleware for session refresh, api-side token verification populating `ctx.userId` and `ctx.activeOrganizationId` via `supabase.auth.getUser(token)`, `@monark/auth`-owned `UserSignedUpEvent`/`UserSignedInEvent`/`UserSignedOutEvent`/`PasswordChangedEvent`, minimal `/signup` and `/signin` pages. Password reset, email-verification UX, TOTP challenge, referral wiring, and full auth-aesthetics styling deferred.
- 2026-04-24: Dev overlay gained an "auth" actions panel (sign up / sign in links + sign-out button).
- 2026-04-24: Added rbac (`@monark/rbac`); canonical `Role` Prisma enum (MONARK_ADMIN, ADMIN, DEVELOPER, AMBASSADOR, STUDENT), `RoleAssignment` table, `PERMISSIONS` matrix + `Permission` type, read-interface (`hasRole`, `hasPermission`, `getUserRoles`, `primaryRole`, `isLastAdmin`), guards (`requireRole`, `requirePermission`), write path (`assignRole`, `revokeRole`) emitting `rbac.role-assigned` / `rbac.role-revoked`, three `rbac.*` tRPC queries (`myRoles`, `myPrimaryRole`, `myPermissions`). Migration also flipped `Invite.role` and `FeatureFlagOverride.role` from `String` to the enum. Admin role-management UI deferred until auth lands.

CRUD, invites, switcher, and white-label deferred until auth + rbac land.
