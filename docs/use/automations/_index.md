# Automations

An automation is a flow you draw on a canvas: a trigger ("when this happens") wired to steps ("do these things"). Once it's on, it runs by itself on the server. Open **Automation** in the navigation rail; if it isn't there, automations aren't enabled for your organization.

Viewing, building, testing and switching flows on are separate permissions; a missing button means your role lacks it.

- [Build a flow](build-a-flow.md): create an automation and wire its steps together.
- [Choose a trigger](choose-a-trigger.md): start a flow from an event, a record change, a schedule, a web request, or by hand.
- [Use values from earlier steps](use-values-from-earlier-steps.md): fill a step's fields from the trigger or a previous step.
- [Branch, loop or pause a flow](branch-loop-or-pause-a-flow.md): take different paths, repeat steps for a list, wait, or handle a failure.
- [Test a flow](test-a-flow.md): run it once and see what each step did.
- [Turn a flow on or off](turn-a-flow-on-or-off.md): let it run by itself, pause it, or delete it.
- [Check past runs](check-past-runs.md): see whether recent runs succeeded and where one failed.

Every node and its fields are listed in [Automation nodes](../../reference/automation-nodes.md). How runs work behind the scenes is in [How automations run](../../concepts/automations.md).
