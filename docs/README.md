# Monark App Documentation

Internal documentation for the Monark App monorepo.

- [user-guide/](user-guide/) ; what the app does, written for the people using it. Covers signing in, your account, navigating the chrome, everything under `/admin`, the public API, and automation variables. No code, no scripts.
- [features-planning/](features-planning/) ; per-feature implementation specs. **Shipped** specs stay in the `phase-0`…`phase-3` folders as immutable historical records (each links to its live module README) ; **[proposed/](features-planning/proposed/)** holds designed-but-unbuilt features. See the [folder README](features-planning/README.md) for the shipped-vs-proposed index.
- [technical-documentation/](technical-documentation/) ; developer reference including the [platform overview](technical-documentation/platform-overview.md) (single as-is reference for every core capability + extension), [architecture & project structure](technical-documentation/architecture.md) (module system, boundaries, event bus, monorepo layout, tooling, scripts), the [development guide](technical-documentation/development.md) (setup, run, test), account-recovery runbook, the [test plan](technical-documentation/test-plan.md), [webhook secret resolver](technical-documentation/webhook-secret-resolver.md), the [Kanban module](technical-documentation/kanban.md), the [Wiki module](technical-documentation/wiki.md), the [block editor](technical-documentation/block-editor.md) (BlockNote — the `@monark/common/blocks` substrate, the create-once/mobile-IME contract, and the Ariakit/lib0/logger gotchas), the [Automation module](technical-documentation/automation.md) (and its [data-flow design](technical-documentation/automation-data-flow.md) for variables/references/wiring), the [secrets store](technical-documentation/secrets.md), the [Files module](technical-documentation/files.md), the [Data Model query language](technical-documentation/data-model-queries.md) (MonarkQL — filter tree, SQL compiler, text DSL), the [Achievements module](technical-documentation/achievements.md) (event-driven gamification — the registry-integrated conditions + durable award engine), the [chat + AI agent](technical-documentation/chat-agent.md) (in-process tools reusing the public-API routes, the confirm-each-write loop, provider abstraction), the [white-label guide](technical-documentation/white-label.md) (retargeting the starter for another business via the `@monark/branding` env seam), the [observability guide](technical-documentation/observability.md) (Sentry error tracking on api + web, DSN-gated), the [CI pipeline](technical-documentation/ci.md) (the GitHub Actions verify gate on `main` + `develop`, jobs, and the coverage-floor rules), the [deploy checklist](technical-documentation/deploy-checklist.md) (Render + Vercel + Supabase walkthrough), the [environments guide](technical-documentation/environments.md) (staging on `develop` + production on `main`, the branch→env deploy mapping), and other internal-tooling notes.
- [agents/](agents/) ; conventions for agents (and humans) working in this repo: [i18n](agents/i18n.md) (what to translate vs. keep as English registry strings), [user documentation](agents/user-doc.md) (how to write + place user-guide pages), [schema changes](agents/schema-changes.md) (base vs fragment, migrations, the migrate-dev GIN gotcha), [testing](agents/testing.md) (unit / integration testcontainers / e2e, coverage floors), and [module authoring](agents/module-authoring.md) (the add-a-module recipe + the four integration systems).
- [todo/backlog.md](todo/backlog.md) ; open follow-up items, dated. The CHANGELOG carries the history.
- [archive/](archive/) ; dated point-in-time records kept for history, not current state — currently the [2026-07-01 codebase audit](archive/audit-2026-07-01/README.md).
