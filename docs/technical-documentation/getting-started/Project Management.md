# Project Management

To ensure smooth collaboration, knowledge continuity, and effective delivery, all student projects partnering with Monark should adhere to the following standards.

### 1. Repository Management

1. Students must use repositories within Monark's GitHub organization.
2. All code must be maintained in our repositories to ensure continuity across semesters.
3. Students must not change the repository name, even if given access rights to do so.
4. Project handover documentation is required at the end of each semester, including setup instructions, architecture overview, and relevant resources.

### 2. Issue Tracking and Project Planning

1. All tasks must be created as issues in GitHub Projects to maintain transparency and accountability.
2. Progress should be tracked using the GitHub Projects board.
3. Decisions, discussions, and important context must be documented within issue threads for future reference.

### 3. Sprint Structure

1. 2-week sprint cycles are recommended for iterative development.
2. Sprint planning sessions should be held at the start of each sprint to define goals and priorities.
   1. Each task should be given a complexity score following a modified Fibbonacci sequence (0.5, 1, 2, 3, 5, 8, 13, 20), agreed uppon by students during sprint planning.
      1. We highly encourage splitting tasks above 5 in multiple tasks if possible and/or take the time to discuss it further as those are generally risky.
3. Demo sessions should occur at the end of each sprint to review progress and gather feedback.

### 4. Releases and Versioning

1. Each sprint should aim for a numbered release to showcase completed work.
2. Pull Requests should be used to ensure high-quality and progression clarity.
3. Semantic versioning is recommended for consistency and clarity.
4. Release notes must be documented, outlining new features, bug fixes, and known issues.

### 5. Monark Team Involvement

1. Monark team members will attend demo sessions whenever possible to provide guidance and feedback.
2. Monark acts as a product stakeholder, providing direction and strategic input.
3. Students remain responsible for sprint planning, execution, and delivery of their project.

### 6. Project Continuity

1. Comprehensive documentation must be maintained, covering setup, architecture, and usage.
2. Knowledge transfer sessions should be conducted before the semester ends to ensure smooth handovers.
3. Setup instructions must be kept current to allow future students to continue development without friction.

### 7. Balancing University Requirements

1. Flexibility is allowed based on university-specific requirements or academic schedules.
2. The level of Monark team involvement can be adjusted to accommodate course requirements.
3. Clear boundaries should be defined between student autonomy and areas where guidance from Monark is needed.
