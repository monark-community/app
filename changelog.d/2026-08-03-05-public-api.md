- 2026-08-03: Public API — **per-key permission ceiling for personal keys ("abstract sub-roles").** A personal API key can now be capped to a subset of the owner's _own_ permissions, picked from the RBAC catalog filtered to what they hold — not a new taxonomy, just RBAC narrowed down. New `ApiKey.fullAccess Boolean @default(true)` + `permissions String[]` (migration `20260803130000_add_api_key_permission_ceiling`) : `fullAccess=true` (default, backward-compatible) acts with the owner's full authority ; `fullAccess=false` caps the key to `permissions` (empty ⇒ deny-all, fails closed). It is only ever a **ceiling** — every request still runs the live RBAC floor against the owner via the caller, so a key can never exceed the owner's _current_ grants and **loses a permission automatically the moment the owner does** (a dead allowlist entry is surfaced in the UI, never a silent grant). Enforced at the facade against each route's declared `permission` ([mount.ts](monark/app/services/api/src/public/mount.ts)) so it **caps even an admin owner** ; the internal helper reads a route needs (e.g. resolving a model key→id) are checked against the owner, so a `record-read` key isn't broken by the schema read it implies. Picker reuses the shared `GroupedMultiSelect` fed by a new non-admin `rbac.myGrantablePermissions` query (the catalog filtered to `hasPermission` — admins see everything, members see only theirs) ([index.ts](monark/app/packages/rbac/src/server/index.ts)) ; the personal-key create dialog gains a Full-access / Limited toggle ([api-keys-section.tsx](<monark/app/services/web/src/app/(authed)/account/api-keys-section.tsx>)). `create` validates each selected permission is one the owner holds. Service-account keys are unaffected (`fullAccess=true` = the account's roles). `authenticateApiKey` + `RoutePrincipal` carry the ceiling. New tests : a limited key reads records but 403s on write _despite an admin owner_ + `/me` still works ([public-api.test.ts](monark/app/services/api/tests/integration/public-api.test.ts)), and the router stores/authenticates the ceiling + rejects an empty limited key ([service-accounts.test.ts](monark/app/packages/api-keys/tests/integration/service-accounts.test.ts)) — api-keys 21 + public-api 27 integration green ; typecheck (24/24) + `check:tiers`/`check:modules`/`check:i18n` clean ; migration applied. (Consistent with, not a reversal of, the earlier scopes removal : that deleted a coarse _parallel_ enum ; this stores real RBAC permission keys as a strict subset of the owner's, checked by the same RBAC.)
