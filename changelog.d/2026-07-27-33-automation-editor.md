- 2026-07-27: Automation editor — a node's config variables are now its input ports. Instead of one anonymous data handle, every config field on an action node renders as its **own labelled input port** on the left ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>) `FlowNode` + `PortRow`) — e.g. a Send-Email node shows `email` / `subject` / `body` ports — so you can wire an upstream node's output into any one variable (or type it in the config panel). Run order moved to a slim grey **execution-flow spine** on the node header (an entry handle on the left, a continue handle on the right ; branch nodes like Condition still list their named outputs as labelled rows), keeping sequencing visually separate from the primary-coloured variable inputs (legend relabelled Run order / Variable). A wired variable now **locks its panel editor** with a "Wired" badge + hint, since its value comes from the connection at run time. The engine ([engine.ts](monark/app/packages/automation/src/server/engine.ts)) resolves a `field:<key>` data link for **any** config field now, not only ones flagged `linkable` (the flag is retained as an author hint ; [contracts/nodes.ts](monark/app/packages/automation/src/contracts/nodes.ts)). New `automation.editor` i18n keys in en + fr (`fieldWired`, `fieldWiredHint`, relabelled `legend*` / `port*Hint` ; dropped the now-unused `portFlowIn/Out`). `typecheck` (web + automation) + `lint` + `check:i18n` (1574 keys × 2) + automation integration suite (14/14 against a testcontainer) green ; needs a live check that the port dots line up with their labels.
