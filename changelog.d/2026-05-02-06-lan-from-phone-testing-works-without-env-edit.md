- 2026-05-02: LAN-from-phone testing works without env edits. Five layers had to give for a phone hitting `http://10.0.0.42:3000` to function end-to-end:

  **1. Browser-side URL rewrite.** New [src/lib/dev-host-rewrite.ts](monark/app/services/web/src/lib/dev-host-rewrite.ts) takes any URL whose hostname is loopback (`localhost` / `127.0.0.1` / `::1`) and, when the browser is on a non-loopback host, swaps the hostname to whatever the browser is on while preserving port + protocol. Wired into [trpc-provider.tsx](monark/app/services/web/src/lib/trpc-provider.tsx) and [supabase/browser.ts](monark/app/services/web/src/lib/supabase/browser.ts). Pure no-op in production where the configured URLs aren't loopback ; in dev the phone hits the developer's machine for both api + Supabase instead of its own loopback. SSR / server actions skip the rewrite (they're inside the dev machine, `localhost` resolves correctly).

  **2. Per-request app URL for email links.** New [src/lib/request-app-url.ts](monark/app/services/web/src/lib/request-app-url.ts) reads the request's actual Host header (honouring `x-forwarded-proto` + `x-forwarded-host` for proxied prod) and returns `${proto}://${host}`. Used in [forgot-password/actions.ts](<monark/app/services/web/src/app/(anon)/forgot-password/actions.ts>) directly and forwarded through the [signup](<monark/app/services/web/src/app/(anon)/signup/actions.ts>) + [resend-confirmation](<monark/app/services/web/src/app/(anon)/signup/check-email/actions.ts>) actions to the api. The `auth.signUp` and `auth.requestConfirmationResend` tRPC mutations now accept an optional `appUrl` input that overrides the env-baked default ; falls back to `process.env.APP_URL` when unspecified (cron jobs, scripts).

  **3. CORS for LAN origins.** [services/api/src/server.ts](monark/app/services/api/src/server.ts) gains an `isAllowedOrigin` check : exact `WEB_ORIGIN` matches always pass, AND in `NODE_ENV=development` any RFC 1918 (`10.*`, `192.168.*.*`, `172.16-31.*.*`) or loopback origin is allowed. Production stays strict.

  **4. Supabase redirect allowlist for LAN IPs.** [supabase/config.toml](monark/app/supabase/config.toml) `additional_redirect_urls` now includes wildcards covering every private IPv4 range on port 3000 (`10.*.*.*`, `192.168.*.*`, `172.16.*.*`–`172.31.*.*`) so password-reset / signup-confirm `redirectTo` values minted from a phone's LAN IP are accepted by Supabase Auth.

  **5. Docs + .env notes.** [phase-0/project-scaffolding.md](monark/app/docs/features-planning/phase-0/project-scaffolding.md) + the two `.env.example` files document the LAN testing flow ; no env edits needed, just open `http://<dev-LAN-IP>:3000` from a device on the same Wi-Fi (firewall must allow ports 3000, 4000, 54321).

  Restart `pnpm supabase stop && pnpm supabase start` to pick up the new redirect-URL allowlist (config-file edits aren't hot-reloaded). Restart `pnpm dev` to pick up the api / web changes.
