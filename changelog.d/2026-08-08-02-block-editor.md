- 2026-08-08: Block editor — **Notion-style block editing (BlockNote) alongside rich text**, with block content stored as **JSON**. A new dependency-free `@monark/common/blocks` substrate (`blocksToText`, `checklistProgress`, `DocumentBlock`) is the server-safe seam every consumer shares ([blocks.ts](monark/app/packages/common/src/blocks.ts)). The web `BlockEditor` / `BlockView` ([block-editor.tsx](monark/app/services/web/src/components/fields/inputs/block-editor.tsx)) are client-only (`dynamic({ ssr:false })`), theme-aware, create-once + uncontrolled (edits stream out ; the editor never re-renders while typing — essential so mobile IME composition, i.e. Enter, isn't swallowed). **New Data Models `DOCUMENT` field type** (added to the core `DataFieldType` enum ; `20260808005048_add_document_field_type`) wired through the fields toolkit next to `richText`, which stays for compact inline HTML. **Wiki** body migrated to blocks (`WikiPage.content` → `Json` + a derived `contentText` for search ; `20260808010000_wiki_content_blocks`). **Kanban** card description migrated to blocks (`KanbanCard.description` → `Json` + `descriptionText` powering the query filter ; `20260808020000_kanban_card_blocks`), and the dedicated **subtasks field is retired** — a card's checklist now lives in its block body (`checkListItem` blocks) and the card-face progress bar derives from them via `checklistProgress` (`20260808030000_kanban_drop_subtasks` drops the column ; `KanbanSubtask` / `parseSubtasks` / the subtasks UI + change-event all removed). **Calendar event description stays rich text** (a block canvas is overkill for a short blurb — a deliberate coexistence line). Pre-release, so the column type changes reset existing bodies to empty rather than back-filling. Three integration notes worth recording: (1) a barrel import of `@monark/common` from a browser-reachable contracts file dragged the server pino logger (`process.stdout.isTTY`) into the client bundle — fixed by the `@monark/common/blocks` subpath ; (2) BlockNote's default Mantine UI does a bare `import { useEffectEvent } from "react"` that Next 15.5's vendored React lacks, so the editor uses the **Ariakit** renderer (`@blocknote/ariakit`) instead ; (3) a `pnpm patch` guards `lib0`'s unguarded `process.stdout.isTTY`.
