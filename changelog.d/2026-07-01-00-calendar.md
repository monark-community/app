- 2026-07-01: Calendar — archive parity for calendars (soft-delete → Archive + Restore). The calendar UI called soft-delete "Delete" with copy claiming events were "permanently removed … cannot be undone", and had no restore path. Added the missing capability : [data.ts](monark/app/packages/calendar/src/server/data.ts) gained `restoreCalendar` + an `includeDeleted` option on `listAccessibleCalendars`/`findCalendarById` ; the router ([index.ts](monark/app/packages/calendar/src/server/index.ts)) gained a `calendars.restore` procedure (gated on `calendar.delete`/`calendar.manage`) and an `includeDeleted` input on `calendars.list` (managers only). The Prisma `Calendar.deletedAt` column already existed, so no schema change. UI is self-contained in [calendar-sidebar.tsx](<monark/app/services/web/src/app/(authed)/calendar/calendar-sidebar.tsx>) : delete relabelled to **Archive** (non-destructive confirm, honest copy), plus a manager-only "Archived" section (its own `includeDeleted` query) with a **Restore** action — the three view files and `CalendarDef` are untouched. Manage-dialog delete relabelled to "Archive calendar". New `calendar.sidebar.{archiveCalendar,archiveConfirm*,archivedSection,noArchived,restoreCalendar,restore*}` i18n in both locales ; old `deleteCalendar`/`deleteConfirm*` keys now dead. Events keep soft-delete as-is (no natural list surface to expose restore ; deferred). Note : calendar is not in [modules.manifest.ts](monark/app/modules.manifest.ts) (in-progress module), so its entry in the generated `app-router.generated.ts` is hand-maintained ; `pnpm gen:routers` strips it until it's added to the manifest.
