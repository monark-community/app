- 2026-08-09: Global search — **the command palette is now truly global**, via an extensible core **search-source registry** (the same "register at boot, list at query time" pattern as event types / automation nodes). New `registerSearchSource` / `listSearchSources` + `SearchHit` / `SearchSource` in [@monark/common](monark/app/packages/common/src/search-registry.ts) (zero new deps for modules), and a new **core `@monark/search` module** owning `search.global` ([README](monark/app/packages/search/README.md)) — one procedure that fans out across every registered source in parallel, caps each, groups by module, and **isolates failures** (a throwing / permission-denied source is logged and contributes nothing, never failing the search). It has no dependency on the content modules. Five sources register at boot ([server.ts](monark/app/services/api/src/server.ts)): wiki, kanban, calendar, automation, and a **net-new cross-model data-record search** (`searchRecordsAcrossModels` — matches the denormalized `DataRecord.title` across every model the caller can `record-read`, model-level + row-level access, one query). Each source scopes itself (its own `requireOrg` + `requirePermission` / accessible-id resolution) and builds its href server-side. **Web**: the palette calls `trpc.search.global` once and renders groups generically ([global-search-dialog.tsx](monark/app/services/web/src/components/global-search/global-search-dialog.tsx)) — the five per-section `*-search-provider.tsx` components + the `SEARCH_PROVIDERS` array + `SearchResultsGroup` were retired (search no longer depends on which section you're in). A new module joins global search by registering one source at boot — no web or core edit. Decisions: global-by-default (retire contextual), include data records.
