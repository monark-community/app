- 2026-07-25: Admin forms — stopped asking users to hand-author machine identifiers. Removed the optional **`key`** inputs from the Data Model create form ([data-models-list.tsx](<monark/app/services/web/src/app/(authed)/admin/data-models/data-models-list.tsx>)) and the field create dialog ([field-editor-dialog.tsx](<monark/app/services/web/src/app/(authed)/admin/data-models/[id]/field-editor-dialog.tsx>)), and made the organization **`slug`** read-only in the org profile editor ([organization-detail.tsx](<monark/app/services/web/src/app/(authed)/admin/organizations/[id]/organization-detail.tsx>)). These identifiers are load-bearing (RELATION targets, `/data/models/[modelKey]` routing, per-model permission + event keys, org URLs) but were already server-derived and collision-safe (`findFreeDataModelKey` / `findFreeDataFieldKey` from the name/label; org slug at bootstrap), so letting a user type them was friction with a permanent-bad-choice downside for an immutable value. Keys/slugs stay **visible read-only** where they were (model editor subtitle, field row subtext, org slug field) so they remain discoverable. No server change: the tRPC create inputs keep `key`/`slug` optional-with-override, so migration/tooling can still set them explicitly. Dropped the now-dead i18n (`admin.dataModels.create.key*`, `…fieldDialog.key*`, `admin.organizations.detail.invalidSlug` + `placeholders.slug`; reworded `slugHint`), en + fr. `tsc` + `eslint` + `check:i18n` green.
