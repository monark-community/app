- 2026-08-16: Tooling — **changelog fragments became the source of truth** ; `CHANGELOG.md` is now a generated artifact. The previous model appended each PR's fragment into `CHANGELOG.md` and deleted it, which removed the merge conflicts but left the compiled file as the real record. Now every entry is a permanent file in [changelog.d/](changelog.d/README.md) and [tools/compile-changelog.ts](tools/compile-changelog.ts) rebuilds `CHANGELOG.md` wholesale from them (date descending, filename breaking ties), so the changelog is fully reproducible and a PR never touches the compiled file. The 411 historical entries were extracted into `YYYY-MM-DD-NN-<slug>.md` fragments, the `NN` preserving their original within-day order, with the static top of the file kept in `_header.md` ; extraction was verified by comparing every entry block as a multiset before and after (411 entries both sides, SHA-1 identical, nothing lost, altered, or duplicated). Two incidental cleanups fell out of the rebuild: five entries that had been appended out of date order are now correctly sorted, and the inconsistent blank-line separators (255 entries preceded by a blank line, 155 not) are uniform. `pnpm changelog:compile --check` reports whether the compiled file is stale without writing.
