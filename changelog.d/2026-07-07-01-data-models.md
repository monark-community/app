- 2026-07-07: Data models — each model auto-integrates into RBAC + webhooks as it's created. On create (refreshed on rename) a model now registers three per-model record permissions (`data-models.<key>-record-{read,write,delete}`) and three per-model event types (`data-models.<key>-record-{created,updated,deleted}`), grouped under `Data Model: <name>` in the `/admin/rbac` catalog and the webhook subscription picker ([registrations.ts](monark/app/packages/data-models/src/server/registrations.ts)). `requireModelAccess` now accepts the per-model permission OR the generic `data-models.record-*` (admins short-circuit both), so a role can be scoped to one model's records without the blanket grant; existing grants are unaffected. The engine keeps emitting the generic `data-models.record-*` event but tags it with the per-model type via a new generic `DomainEventBase.subscriptionAliases` field ([events.ts](monark/app/packages/common/src/contracts/events.ts)); the webhooks matcher ([data.ts](monark/app/packages/webhooks/src/server/data.ts), [subscribers.ts](monark/app/packages/webhooks/src/server/subscribers.ts)) now matches on `[type, ...aliases]`, routing the generic emit to a per-model subscription (per-model event literals can't join the codegen'd `DomainEvent` union). The in-memory registries are re-hydrated from the DB at api boot via `hydrateDataModelRegistrations` on the async boot path ([server.ts](monark/app/services/api/src/server.ts)), next to `syncFlagsToDatabase`. Notifications + feature-flags are a conscious N/A (the engine emits events; notification-worthy reactions belong to subscribing modules, and the change is additive/non-breaking so no gate). Also fixed a soft-delete regression from the org-required change: [20260707060000_data_models_key_unique_partial](monark/app/packages/db/prisma/migrations/20260707060000_data_models_key_unique_partial/migration.sql) swaps the plain `@@unique([organizationId, key])` back to a hand-written partial unique (`WHERE deletedAt IS NULL`), so a soft-deleted model frees its key for reuse as the data layer already assumes. New unit + integration coverage (per-model registration, alias routing); full gate green (gen, tsc 17/17, eslint 17/17, 233 unit + data-models/webhooks integration, tiers/modules/i18n).
