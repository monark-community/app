- 2026-09-08: Fixed an abandoned two-factor enrollment locking an account out of its own security settings. [`getTotpStatus`](../packages/auth/src/server/totp.ts) reported `enrolled: true` whenever a `TotpSecret` row existed, and `beginTotpEnrollment` writes that row the moment a QR is generated — so opening the enrollment card and walking away left a row with `activatedAt` null that every gate read as "this user has an authenticator". Changing a password, setting a first password, changing an email and unlinking a provider then all demanded a code the user could not produce, and `verifyTotpCode` could not have accepted one because the secret was never activated. `enrolled` now keys off `activatedAt`, matching `isTotpActive` directly beneath it; a test pins the two together at every stage. Nothing consumed the old shape — the account UI already derived `active = enrolled && activatedAt` — and a pending row is disposable, since the next enrollment replaces it.
- 2026-09-08: The "Set a password" button on Connected accounts now opens the password card's dialog instead of scrolling to it. It was an anchor to `#password`, which left the user looking at the right card but still a click from what they had asked for. The two cards are siblings under a server component, so the request travels through a search param plus a same-tab event ([set-password-request.ts](<../services/web/src/app/(authed)/account/set-password-request.ts>)) rather than lifted state; `/account/security?password=set` works as a deep link as a side effect, and the param is cleared once consumed so a refresh doesn't reopen a dismissed dialog.
