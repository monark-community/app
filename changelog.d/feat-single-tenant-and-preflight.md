- 2026-09-08: Tenancy — removed multi-tenancy support. The app is a single-tenant product ; [multi-instance.md](../docs/technical-documentation/multi-instance.md) already described serving many businesses as many instances rather than one multi-tenant deploy, and the `tenancy.multi-tenant` flag was the last thing pretending otherwise: default-off everywhere, carrying a second set of code paths and a second set of admin UI no deployment exercised. Gone are the flag (the only one in its namespace) and `registerOrganizationsFeatureFlags`, `mode` from `BootstrapStatus`, the branches in [bootstrap.ts](../packages/organizations/src/server/bootstrap.ts) / [read.ts](../packages/organizations/src/server/read.ts) / [auto-membership.ts](../packages/organizations/src/server/auto-membership.ts), the api boot hook's skip path, `provision-org`'s `already-multi-tenant` refusal, the `useIsSingleTenant` hook, and the org pickers it gated in the roles manager, webhooks manager, invite dialog and role-assign dialog (plus the webhook editor's informational org-scope row). `isSingleTenantBootstrapped` became `isBootstrapped` — with one tenancy mode the qualifier was noise, and the flag was only ever about whether the singleton org exists. A [migration](../packages/db/prisma/migrations/20260908010000_drop_multi_tenant_flag/migration.sql) drops the now-orphaned flag row and its overrides so they stop appearing in `/admin/feature-flags` as an unknown flag. The platform-vs-org webhook scope survives : that is a permission-tier distinction, not a tenancy one.

- 2026-09-08: Deployment — added [`tools/preflight`](../tools/preflight/README.md), a configuration gate that runs in front of the app. A misconfigured deploy otherwise fails late and unhelpfully : a blank `DATABASE_URL` surfaces as a Prisma stack trace on the first request, an unquoted `BRANDING_PRIMARY=#2563EB` silently resolves to an empty string, a `BRANDING_LOGO_SRC` pointing at a missing file is a broken image on the sign-in page. Preflight checks env vars (presence, shape, 32-byte at-rest keys, and that the Supabase secret key is not exposed as `NEXT_PUBLIC_*`), branding and its browser mirror, referenced assets, and whether the database and Supabase actually answer ; every failure prints a fix concrete enough to paste. `pnpm preflight` reports and exits ; `pnpm preflight --gate --port 3000 -- pnpm start` refuses to launch the app while anything fails and instead binds the port the app would have taken, serving the checklist with a `503` (and `GET /preflight.json` for pipelines) until the configuration is fixed, at which point it releases the port and execs the real command with no restart. It parses the `.env` files itself rather than reading `process.env`, which is the only way to tell "unset" apart from the unquoted-`#` quoting trap — from `process.env` those are indistinguishable and need opposite fixes. Node builtins only, so it can run in front of the app anywhere the app runs.
