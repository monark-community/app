- 2026-07-26: Automation — new **Core module** `@monark/automation` : event-triggered flows built on a visual node-graph editor, with a durable outbox + worker execution model and a node-type registry other modules extend. **Data model** (`// ── MODULE: automation ──` in [schema.prisma](monark/app/packages/db/prisma/schema.prisma), migration `20260725231737_add_automation`) : `Automation` (org-scoped, `triggerEventType` + `graph` JSON), `AutomationRun` (the outbox — `@@index([status, nextAttemptAt])`), `AutomationRunStep` (per-node observability). **Engine** : a wildcard event-bus subscriber ([subscriber.ts](monark/app/packages/automation/src/server/subscriber.ts)) matches every emit against enabled automations (org via `organizationId` or the actor's memberships, skipping `automation.*` to avoid loops) and enqueues one `PENDING` run each — cheap work only, never blocking `emit` ; a background worker ([worker.ts](monark/app/packages/automation/src/server/worker.ts)) claims runs atomically (`updateMany` guard, safe across processes), executes the graph in topological order recording a step per node ([engine.ts](monark/app/packages/automation/src/server/engine.ts), with `{{ trigger.x }}` / `{{ nodeId.y }}` interpolation), and retries with backoff (3 attempts) before dead-lettering — the same outbox+worker shape as `@monark/webhooks`. **Extension API** : `registerAutomationNodes("<module>", { … })` ([registry.ts](monark/app/packages/automation/src/server/registry.ts)) — any module contributes node types (config schema + server `execute`), mirroring `registerPermissions` ; a `nodeTypes.list` query projects only the serializable descriptor to the editor.
