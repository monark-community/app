- 2026-07-01: Color — one standard color input across the app. Every "pick a color" affordance was bespoke : Calendars had a swatch that opened the full `ColorPicker` in a popover, while Roles and Organizations had a bare hex `<Input>` + a static preview square and **no picker at all**. New shared [`ColorInput`](monark/app/services/web/src/components/ui/color-input.tsx) composes the existing [`ColorSwatch`](monark/app/services/web/src/components/ui/color-swatch.tsx) + [`ColorPicker`](monark/app/services/web/src/components/ui/color-picker.tsx) into a controlled swatch-opens-picker control with an editable hex field beside it (`swatchOnly` to drop the field ; a dashed swatch for the empty/unset state ; `defaultColor` seeds the picker when unset). Adopted it in [calendar-manage-dialog.tsx](<monark/app/services/web/src/app/(authed)/calendar/calendar-manage-dialog.tsx>), [role-editor.tsx](<monark/app/services/web/src/app/(authed)/admin/rbac/role-editor.tsx>), and [organization-detail.tsx](<monark/app/services/web/src/app/(authed)/admin/organizations/[id]/organization-detail.tsx>) — so Roles and Organizations gain the picker, and all three read the same. Added shared `common.save` + `common.chooseColor` i18n keys (en + fr ; the picker's Save/Cancel now go through i18n instead of the English defaults) and a `color-input` story to the [screenshot harness](monark/app/services/web/tools/screenshots/stories.tsx). No schema / RBAC / behavior change.
