- 2026-08-02: Data Models — **structured query language (MonarkQL) on the record list**, a GitHub / Notion / Linear-style filter system parallel to (and reusing) the classic filter menu, gated behind a new `data-models.query-language` flag (off by default). The canonical form is a **query tree** — predicate leaves + boolean groups — that both the menu and a new text query bar edit; the tree is the one thing the server runs. New [`contracts/query.ts`](monark/app/packages/data-models/src/contracts/query.ts): the `FilterNode` AST, the operator vocabulary, the field-type→operator taxonomy (`filterableKindOf` / `legalOps`, resolving FORMULA through its inferred result type), and a depth/count-bounded zod input schema. Deliberately **separate** from the FORMULA engine — a formula is a per-record compute (one scalar, in JS), a query is a set selector (a predicate over the table, compiled to SQL). New [`server/query-compiler.ts`](monark/app/packages/data-models/src/server/query-compiler.ts) compiles a tree to a boolean `Prisma.Sql` fragment, run by `listDataRecordsWithQuery` ([data.ts](monark/app/packages/data-models/src/server/data.ts)) — **raw SQL, not Prisma's structured JSON `where`**, for two reasons: text matching is case-insensitive (`ILIKE`), and comparisons hit the **expression indexes** `indexing.ts` builds (`(data->>'key')::numeric` / `::timestamptz`, GIN on arrays) that Prisma's `data:{path,gt}` form would miss. Field keys are interpolated as identifiers (safe: validated `^[a-z][a-z0-9_]*$` + immutable, the same guarantee the indexing DDL relies on); every value is a bound parameter. Keyset pagination (`updatedAt desc, id desc`, cursor resolved via subquery) and the record role-access predicate are preserved as SQL, so the compiled path is access-identical to the structured one. A text DSL ([`contracts/query-dsl.ts`](monark/app/packages/query/src/contracts/query-dsl.ts), `parseQuery` / `printQuery`) serializes the same tree — `status:open -assignee:present`, `priority:>3`, `tags:&red,blue`, `due:2026-01-01..2026-06-01`, implicit-AND / `OR` / parentheses — mirroring the formula engine's tokenizer → recursive-descent structure and round-tripping (parse∘print is identity on normalized trees). Web: a new **query bar** ([query-bar.tsx](monark/app/services/web/src/components/query/query-bar.tsx)) with context-aware autocomplete (field names → value options from the field metadata), live parse + inline error, wired into the record list beside the sorting/columns tools behind the flag ([records-list.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/records-list.tsx>), flag read in [page.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/page.tsx>)); `records.list` gained an optional `filter` tree alongside the legacy `fieldFilters`. `@monark/db` now value-exports `Prisma` for its raw-SQL helpers.
