- 2026-07-29: Security — **audit follow-ups (batch 2): hardening the DoS / abuse surfaces.** **Formula engine** ([formula.ts](monark/app/packages/data-models/src/contracts/formula.ts)): a max input length (10k chars) + a recursion-depth cap (64) so a very long or deeply-nested expression can't burn CPU / overflow the parser stack, and `FUNCTIONS` lookups now use `Object.hasOwn` so inherited Object props (`constructor`, `hasOwnProperty`, …) parse as a clean "unknown function" instead of resolving to a prototype method; the automation `transform` node caps its expression at 2000 chars ([transform.ts](monark/app/packages/automation/src/server/nodes/transform.ts)). **Outbound HTTP** ([@monark/common/http](monark/app/packages/common/src/http.ts)): `safeFetch` gained an opt-in `maxBytes` response cap — the body is streamed inside the timeout window and the request throws if it exceeds the cap, so a hostile receiver can't force an unbounded read; the returned `Response` is reconstructed with the bounded body so `.ok`/`.text()` still work. **Files** ([files/server/index.ts](monark/app/packages/files/src/server/index.ts)): creating a **public** bucket now requires SYSADMIN (`hasSysadminAssignment`, newly exported from [@monark/rbac/server](monark/app/packages/rbac/src/server/index.ts)) — an org-tier `files.manage-buckets` holder can only create private buckets, since a public bucket serves stable unauthenticated URLs; and `finalize` now enforces the real object size against `bucket.fileSizeLimit ?? MAX_FILE_SIZE`, so a policy-less bucket is still bounded at the hard ceiling in app code (the `fileSizeLimit` column is INT4, so the ceiling stays a runtime comparison rather than a stored default).
