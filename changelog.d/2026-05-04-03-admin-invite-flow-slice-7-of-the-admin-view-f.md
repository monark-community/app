- 2026-05-04: Admin invite flow (slice 7 of the admin view ; final slice). Four new admin-gated tRPC procedures on the organizations router under `organizations.invites.*` : `adminList({ organizationId })`, `adminCreate({ organizationId, email, role, appUrl? })`, `adminRevoke({ inviteId })`, and the auto-accept hook `consumePending` (auth-required, no admin gate ; the user is implicitly the target). Plus the underlying primitives [createInvite + acceptInviteByToken + consumePendingInvitesForUser](monark/app/packages/organizations/src/server/invites.ts). New tokens are 32 random bytes hex-encoded ; only the SHA-256 hash is persisted (`tokenHash` per the existing schema), the plaintext is returned exactly once at creation time so the email link can carry it. 14-day expiry. Acceptance is atomic in a single Prisma transaction : marks the row accepted, upserts the OrganizationMembership (handles "left then re-invited" edges), upserts the RoleAssignment using the existing `@@unique([userId, organizationId, role])` compound key. Email is sent through the existing `@monark/notifications/server` `sendMail` primitive with an inline template (no notify-registry registration since invitees aren't users yet — they have no User row to look up locale or prefs against ; defaults to English). `@monark/organizations` now depends on `@monark/branding`, `@monark/notifications`, and `@monark/users`. Auto-accept wired into three flows : the signin server action, the signup server action's auto-signin step, and the `/auth/confirm` route handler ; all three call `organizations.invites.consumePending` after the user lands authenticated, idempotent so retries don't duplicate. UI : [/admin/invites](<monark/app/services/web/src/app/(authed)/admin/invites/page.tsx>) is a three-card layout — Organization picker, "Send a new invite" form (email + role from ADMIN/DEVELOPER/AMBASSADOR/STUDENT, no MONARK_ADMIN since invites are org-scoped), and the pending list with per-row Revoke. Invite emails point at `/signup?invite=<token>` ; the signup form doesn't yet read the token (auto-accept by email match handles the actual mechanics post-confirmation). **i18n** (en + fr) : `admin.invites.{subtitle, noOrgs, createSuccess, createError, revokeSuccess, revokeError, orgPicker.*, create.*, pending.*}`.
