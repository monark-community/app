- 2026-05-03: Primary nav drawer is now driven by a registry instead of a hardcoded list. New [services/web/src/config/primary-nav.ts](monark/app/services/web/src/config/primary-nav.ts) exports a typed `PRIMARY_NAV: PrimaryNavEntry[]` that the application config edits to compose the drawer ; modules opt in by exporting their entry from a `web-nav` (or similar) sub-path and the import lands here. Order in the array IS the order in the drawer. The current starter ships an empty array — the drawer renders "No module registered" instead of the previous Monark-specific placeholder list (Activity / Calendar / Contribution / Projects / Governance / Rewards) which referenced features that don't exist in this codebase. **Each module is responsible for its own secondary nav** (sub-routes inside its own surface) ; the primary drawer is strictly top-level entries.

  Cleanups that came along : [primary-nav-menu.tsx](monark/app/services/web/src/components/primary-nav-menu.tsx) refactored to consume the registry + render the empty state ; [app-bar-title.tsx](monark/app/services/web/src/components/app-bar-title.tsx) stripped of the `/calendar`, `/contribution`, `/projects`, `/governance`, `/rewards` section-key mappings (the sections list now only carries the always-present app pages — account, account-sub-pages, admin) ; the wordmark inside the drawer header reads `{appName}` from i18n instead of the literal "Monark" ; **i18n** (en + fr) dropped `appBar.{sections.{calendar, contribution, projects, governance, rewards}, primaryNav.items.{activity, calendar, …}}` and added `appBar.primaryNav.{brandWordmark, empty}`.
