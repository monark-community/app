- 2026-07-28: Data Models — **File & Attachment field types**. Two new `DataFieldType`s let a record carry uploaded files : **`FILE`** (a single file, optionally format-constrained) and **`ATTACHMENTS`** (many files, optional MIME allow-list + max count) — migration `20260728210000_add_data_model_file_fields`. A field value is a soft `StoredFile.id` reference (single) or `string[]` (many) in `DataRecord.data`, mirroring RELATION ONE/MANY, so validation, GIN indexing, and cells reuse that path ([field-types.ts](monark/app/packages/data-models/src/contracts/field-types.ts), [indexing.ts](monark/app/packages/data-models/src/server/indexing.ts)). It builds entirely on the existing `@monark/files` service : a new client widget ([inputs/file-field.tsx](monark/app/services/web/src/components/fields/inputs/file-field.tsx)) uploads via the `useFileUpload` signed-URL flow and shows name / download / remove chips ; `files.byIds` (new query) hydrates chips and `files.downloadUrl` serves them ([files/server/index.ts](monark/app/packages/files/src/server/index.ts)). **Server-side reference validation** on record write resolves the referenced files and rejects any that aren't a READY file in the caller's org, of an allowed MIME type (exact or `image/*` wildcard), within the size cap, or over the count cap ([data.ts](monark/app/packages/data-models/src/server/data.ts) `validateFileReferences`) — a client can't stash arbitrary/cross-org ids. A single private bucket `data-model-files` is auto-provisioned at boot (`ensureDataModelFilesBucket`, best-effort in [server.ts](monark/app/services/api/src/server.ts)). Admin field editor gains the two types + a config block (allowed MIME types, max size MB, max count) ([field-editor-dialog.tsx](<monark/app/services/web/src/app/(authed)/admin/data-models/[id]/field-editor-dialog.tsx>)) ; new `fields.{uploadFile,uploading,downloadFile,badFileFormat,fileTooLarge}` + `fieldDialog.types.{FILE,ATTACHMENTS}` + `config.{allowedFormats*,maxSizeMb}` i18n (en + fr). `@monark/data-models` gained a core→core dep on `@monark/files`. Covered by a new integration suite ([file-fields.test.ts](monark/app/packages/data-models/tests/integration/file-fields.test.ts), 10 cases : valid FILE/ATTACHMENTS ; rejects non-existent / PENDING / cross-org / disallowed-MIME / oversize / over-count ; and validates on update). Deferred (per [spec](monark/app/docs/features-planning/phase-3/data-models-file-fields.md)) : record-scoped file access (org-gated in v1), orphan GC, "has attachment" filtering. `pnpm gen` + `typecheck` (db + data-models + files + api + web) + `eslint` + `check:tiers`/`check:modules`/`check:i18n` (1769 × 2) green ; migration + integration suite to run with `db:migrate:dev` + `test:integration` (Docker).
