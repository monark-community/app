- 2026-05-29: DB-side expiry on `TrustedDevice`. Before this, the browser cookie's 400-day `Max-Age` was the only signal that walked a device out of trust — the row itself lived forever and any cookie that somehow outlived its `Max-Age` (manual restore, browser bug, attacker-copied cookie) would still grant trust on lookup. New `expiresAt TIMESTAMP NOT NULL DEFAULT (now() + INTERVAL '400 days')` column on [packages/db/prisma/schema.prisma](monark/app/packages/db/prisma/schema.prisma) + index for the planned sweep cron. Migration [20260529170000_add_trusted_device_expiry](monark/app/packages/db/prisma/migrations/20260529170000_add_trusted_device_expiry/migration.sql) backfills existing rows from `lastSeenAt + INTERVAL '400 days'` (devices last seen 2+ years ago land already-expired, ready for the sweep). Code-side : new `DEVICE_TRUST_TTL_MS` constant in [packages/auth/src/server/trusted-devices.ts](monark/app/packages/auth/src/server/trusted-devices.ts) mirrors the cookie's `Max-Age` ; `recognizeOrRegister` sets the row's `expiresAt` on create + slides it forward on every recognized sign-in (matching the cookie's sliding refresh) ; every "is this device still trusted" query (`recognizeOrRegister` lookup, `listTrustedDevices`, `findCurrentDeviceId`, `shouldChallengeTotp`, `markDeviceTotpVerified`) now filters by `expiresAt: { gt: new Date() }`. Sweep cron + `/account/security` UI surface filed in [backlog](monark/app/docs/todo/backlog.md#trusted-devices) — schema gives us the cut now, cron + UI close the loop in a follow-up.
