- 2026-05-08: Test backfill against the test plan. Three new suites land against gaps the plan flagged ; the authorization + structured-logging surfaces now have direct coverage instead of relying on the integration suites that exercise them as a side effect.
  - **`@monark/common` logger redaction** ([packages/common/tests/log.test.ts](monark/app/packages/common/tests/log.test.ts)). Drives a real pino instance configured with the production `REDACT_PATHS` against a captured Writable destination, asserts each credential-flavoured key (password / token / secret / cookie / hash variants) renders as `[REDACTED]`, and pins the `*.field` wildcard's "one level deep, structured payloads only" semantics so a future contributor doesn't add a root-level credential and assume it's redacted. Also covers the request-header path (`req.headers.authorization`, `cookie`, `set-cookie`, `x-supabase-auth`, `x-api-key`, `x-csrf-token`, `proxy-authorization`) and a "lookalike key" guard (`passwordless`, `tokenized`, `secretly` pass through unchanged because the matcher is exact, not substring). `REDACT_PATHS` exported from `log.ts` so the test can validate the production list directly.
  - **`@monark/common` tRPC code mapping** ([packages/common/tests/trpc.test.ts](monark/app/packages/common/tests/trpc.test.ts) + [packages/common/src/trpc.ts](monark/app/packages/common/src/trpc.ts)). Locks in `APP_TO_TRPC_CODE` : `not_found → NOT_FOUND`, `unauthorized → UNAUTHORIZED`, `forbidden → FORBIDDEN`, `validation_error → BAD_REQUEST`, `conflict → CONFLICT`, plus the "every domain error class's code lands on the map" snapshot guard so a new AppError subclass can't ship without a corresponding tRPC code. The mapping table is exported (was a private const) ; the middleware itself stays the canonical source. Tested directly against the table because vite-node's per-relative-path module caching breaks `instanceof AppError` across the test/source boundary — production runs through a single import path and works correctly. The full middleware behavior is implicitly covered by every integration suite that throws an AppError through a real tRPC procedure.
  - **`@monark/rbac` read-layer integration** ([packages/rbac/tests/integration/read.test.ts](monark/app/packages/rbac/tests/integration/read.test.ts)). The two load-bearing authorization short-circuits get direct coverage : (1) SYSADMIN holders implicitly hold every permission across every org regardless of the requested orgId, (2) ADMIN holders implicitly hold every permission within their org and don't leak across org boundaries. Also covers `hasPermission` falling through to `RolePermission` rows for custom roles + non-admin users, the `ValidationError` thrown for malformed permission keys, `hasRoleKey` + the "ADMIN check requires orgId" programming-error gate, `getUserRoles` deduping across platform/org tier, `isLastAdmin` for the "block last admin leaving" surface, and `adminAssignmentSummary` for both SYSADMIN + ADMIN paths. 14 cases across 7 describe blocks, runs against the shared Postgres testcontainer.
