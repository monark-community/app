- 2026-05-07: Webhook secret store defaults to file-backed in non-production + delivery-detail event-type rendering polish.
  - **File-backed by default in dev.** [packages/webhooks/src/server/secret-store.ts](monark/app/packages/webhooks/src/server/secret-store.ts) auto-engages a `FileBackedStore` when `NODE_ENV !== "production"`, defaulting to `<api cwd>/.cache/monark-webhook-secrets.json`. Means secrets survive `pnpm dev` restarts out-of-the-box ; previously the in-memory store cleared on every restart and every endpoint failed with "no plaintext secret available" until rotated. Override path with `MONARK_DEV_WEBHOOK_SECRETS_FILE`. Production still defaults to in-memory ; the env var is honored there too but logs a warning since plaintext-on-disk is rarely the right production answer.
  - **Gitignored.** Added `.cache/` to [.gitignore](monark/app/.gitignore) so the per-process secret file doesn't leak into version control.
  - **Existing endpoints need a one-time rotate.** Endpoints created before this change have no plaintext stored anywhere. Visit `/admin/webhooks/<id>` and click "Rotate secret" once ; the rotation lands the new plaintext in the file-backed store immediately and every delivery from then on signs cleanly.
  - **Delivery detail event-type styling.** [services/web/src/app/(authed)/admin/webhooks/[id]/deliveries/[deliveryId]/delivery-detail.tsx](<monark/app/services/web/src/app/(authed)/admin/webhooks/[id]/deliveries/[deliveryId]/delivery-detail.tsx>) now renders the event type in `font-mono` (signaling it's a technical identifier, not a missing translation) and shows the registered description from `webhooks.listEventTypes` as a subtitle below. Operators get both the wire-level type (`user.signed-in`) and the operator-friendly meaning ("A user authenticated successfully…") in one glance. The deliveries list rows already used mono ; this aligns the detail page header with that convention.
