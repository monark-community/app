- 2026-08-05: Discord — **new extended module `@monark/discord`: Discord action nodes for automations** (an _automation integration_, `integrates: "@monark/automation"`; flag-gated `discord.enabled`, default off). The second integration on `@monark/integration-kit` — and a deliberate contrast to GitHub: **write-only, no triggers.** Discord has no inbound event webhooks (real-time events come over a Gateway WebSocket a bot holds open; the only inbound HTTP is Ed25519-signed slash-command Interactions), so this MVP covers the dominant use case — automations posting to Discord — with **no events, no inbound endpoint, and no tRPC router** (a router-less module; `check:modules` requires no integration suite for it). Six nodes ([nodes/](monark/app/packages/discord/src/server/nodes)): `send-message` (bot token → channel), `send-webhook-message` (a channel webhook URL, no bot), `edit-message`, `add-reaction`, `list-messages`, `get-channel`. Bot calls go through the kit's `createRestClient` — which gained a configurable **auth scheme** (`authHeader`, so Discord's `Bot <token>` works alongside GitHub's default `Bearer`; backward-compatible) — and the webhook-URL send validates the URL to a discord.com host ([isDiscordWebhookUrl](monark/app/packages/discord/src/contracts/discord.ts)) on top of `safeFetch`'s SSRF guard. The credential is a secret referenced per node (bot token or webhook URL), so there's no connection UI. Registered `discord.enabled` + the nodes at api boot; the palette shows them under a `discord` category (chat-bubble icon). 4 unit tests + the kit's existing suite green. This validates the kit: the whole integration is a fraction of GitHub's size, and the only shared-code change was the one auth-scheme generalization. `typecheck` (discord/api/web) + `lint` + `check:tiers`/`check:modules` (19 modules) green.
