- 2026-07-29: Security — **audit remediation across the automation, files, and outbound-HTTP surfaces** (findings from a full-branch security review). **(H1) Cross-tenant record tamper/delete**: the automation Update/Delete Record nodes called the data-layer mutators with a caller-supplied `recordId` and no org scoping — an author with `record-write`/`-delete` in their org could mutate or hard-delete any record by id (another org's, or one they're row-level-restricted from). Both nodes now resolve the record and enforce `record.organizationId === ctx.organizationId` **and** `isDataRecordRoleAccessible` (mirroring the tRPC router) via a shared `requireOwnerAccessibleRecord` ([nodes/data.ts](monark/app/packages/automation/src/server/nodes/data.ts)); `isDataRecordRoleAccessible` is now exported from [@monark/data-models/server](monark/app/packages/data-models/src/server/index.ts). **(H2) Cross-tenant user actions**: the automation user nodes (`user-get`, `user-set-active`, `user-update-profile`, `user-set-metadata`) acted on an arbitrary `userId` with only the owner's org-level permission checked — they now require the target to be a member of the run's org via a new `requireTargetInOrg` (backed by `isMember`, now exported from [@monark/organizations/server](monark/app/packages/organizations/src/server/index.ts)); `user-get` is scoped so it can't be a cross-org directory oracle. **(H3) SSRF**: [@monark/common/http](monark/app/packages/common/src/http.ts) now rejects `https://` to a literal private/loopback/link-local/reserved IP (incl. `169.254.169.254` metadata + IPv4-mapped IPv6), fails **closed** on an unset `NODE_ENV`, sets `redirect: "manual"` so a benign first hop can't 302 into an internal target, and adds a production DNS-resolution guard in `safeFetch`; the webhooks delivery worker also stops following redirects ([worker.ts](monark/app/packages/webhooks/src/server/worker.ts)). **(M2) File MIME/size spoofing**: `files.finalize` now overwrites the client-declared `contentType` with storage's observed type and re-validates size + MIME against the bucket policy (deleting the stray object on violation), so a "PDF-only" field can't be fed HTML/SVG ([files/index.ts](monark/app/packages/files/src/server/index.ts), [data.ts](monark/app/packages/files/src/server/data.ts) `markFileReady`). **(Low)** `setSecret` is now an atomic `upsert` (no P2002 race). New regression tests: two cross-org automation guards (record delete + user disable both refused) and SSRF unit cases (literal-IP rejection, fail-closed `NODE_ENV`). Deferred (tracked, lower-priority): `FileBucket` org-scoping (needs a schema migration), HTTP-trigger replay/rate-limit, a formula length/depth cap, PENDING-file sweep, DNS-rebind TOCTOU pinning. `pnpm typecheck` (repo-clean) + lint + `check:tiers`/`check:modules`/`check:i18n` + affected suites (common 62, secrets 9, automation 25, files 11, webhooks 68+38) green.
