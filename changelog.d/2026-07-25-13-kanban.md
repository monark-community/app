- 2026-07-25: Kanban — a new board view (sibling to the calendar), Phase 1. Added the `@monark/kanban` extended module: an org owns multiple named **boards**, each with configurable **columns** (Backlog / Todo / In Progress / Review / QA / Done by default) and drag-and-drop **cards**. Like the calendar, it owns its own Prisma models directly in [schema.prisma](monark/app/packages/db/prisma/schema.prisma) under a `// ── MODULE: kanban ──` banner (`KanbanBoard` / `KanbanBoardRoleAccess` / `KanbanColumn` / `KanbanCard`, migration `20260725200201_add_kanban`) ; column + card ordering use an integer `position` in gaps of 10 with a full-list reorder transaction (the `data-models` house pattern), and `moveCard` re-columns + reindexes the target. The module ships contracts (types + a real `KanbanEvents` union), a server layer ([data.ts](monark/app/packages/kanban/src/server/data.ts) + the [`kanbanRouter`](monark/app/packages/kanban/src/server/index.ts) whose every mutation guards with `requirePermission(ctx, "kanban.<key>", org.id)` and emits a domain event), pure-React client primitives ([client/ui](monark/app/packages/kanban/src/client/ui)), and the wired drag-and-drop web view ([services/web/src/app/(authed)/kanban](<monark/app/services/web/src/app/(authed)/kanban>)) built on `@dnd-kit`. **Big-4 wiring**: RBAC (`kanban.{view,create,edit,delete,manage}`), the event bus (`kanban.board-created` / `column-created` / `card-created` / `card-updated` / `card-moved` / `card-deleted`), and webhooks (free via `registerKanbanEventTypes()`) are all live ; `register*` helpers wired into [server.ts](monark/app/services/api/src/server.ts), nav entry + `kanban` i18n namespace (en + fr) added. Notifications (card-assigned) and a `kanban.board` feature-flag gate are the deferred Phase 2. `pnpm gen` + `tsc` (web + api + kanban) + `eslint` + `check:i18n` + `check:tiers` + `check:modules` green.
