- 2026-05-29: Integration test isolation hardening. Diagnosed orphan org rows (`ff-org-a`, `ff-org-b`, `test-org-webhooks`) sitting in the dev DB — left over from [packages/feature-flags/tests/integration/is-enabled.test.ts](monark/app/packages/feature-flags/tests/integration/is-enabled.test.ts) and [packages/webhooks/tests/integration/data.test.ts](monark/app/packages/webhooks/tests/integration/data.test.ts), both of which seed orgs in `beforeAll` with no matching `afterAll` cleanup. Anything that bypassed `vitest.integration.config.ts`'s `globalSetup` (IDE extension picking the unit config, ad-hoc `vitest run`) hit whatever `DATABASE_URL` was in the env — usually the dev Supabase. Fix landed in two layers : (a) new [packages/test-utils/src/assert-test-db.ts](monark/app/packages/test-utils/src/assert-test-db.ts) setupFile aborts the run with a clear error if `DATABASE_URL` doesn't contain the testcontainer marker `/monark_test` (the path component baked in by `startTestDb`'s `.withDatabase("monark_test")`) ; wired into all 7 `vitest.integration.config.ts` files via `setupFiles: ["@monark/test-utils/assert-test-db"]` and exported from `@monark/test-utils/package.json`. (b) `afterAll` cleanup in both leaking suites so the testcontainer exits clean even when the assertion is bypassed. Re-ran both suites after the fix : 30 + 35 tests still green, dev DB still has the single legit `monark` org row.
