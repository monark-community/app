- 2026-08-07: Twitter/X — **new extended module `@monark/twitter`: X (Twitter) action nodes for automations** (an _automation integration_, `integrates: "@monark/automation"`; flag-gated `twitter.enabled`, default off). The fourth integration on `@monark/integration-kit`, and **write-only** like Discord but for a different reason: X has no accessible inbound event webhook (real-time delivery is Enterprise-only Account Activity), so there are no triggers, no events, no `/hooks` route. Three nodes ([nodes/tweets.ts](monark/app/packages/twitter/src/server/nodes/tweets.ts)): `post-tweet`, `reply`, `delete-tweet` — the write set the free API tier allows. **The novel piece is auth:** X posts on a user's behalf only with OAuth 1.0a user context — four static credentials (consumer key/secret + access token/secret) used to HMAC-SHA1-**sign every request**. There's no static header, so it doesn't fit the kit's `createRestClient` (whose `authHeader` returns a fixed string) — a third outbound client shape after GitHub's bearer and Telegram's token-in-path. A small **pure signer** ([oauth1.ts](monark/app/packages/twitter/src/server/oauth1.ts): `percentEncode`/`signatureBaseString`/`oauth1Signature`/`buildAuthHeader`) computes the per-request signature; [client.ts](monark/app/packages/twitter/src/server/client.ts) signs + calls the v2 API over the shared SSRF-guarded `safeFetch`, reusing the kit's `pickString`. Kept the signer in the module (not the kit) until a second OAuth 1.0a provider justifies promoting it. **Connection:** four credentials stored per-org in `@monark/secrets` via a `twitter.connection.{status,connect,disconnect}` router ([router.ts](monark/app/packages/twitter/src/server/router.ts), gated on `twitter.manage`) + an `/x` settings page ([x-settings.tsx](<monark/app/services/web/src/app/(authed)/x/x-settings.tsx>)); `connect` is store-only (no live verify — X's free tier restricts the read endpoint that would validate creds, so the first post-tweet run surfaces auth errors instead). Nodes read the credentials directly (`ctx.getSecret`), no per-node token fields. Plus a `PRIMARY_NAV` entry (`AtSign` icon; lucide has no brand X glyph). No new tables. Tests: 5 unit (OAuth 1.0a signer — exact base-string pinning + an independent `node:crypto` HMAC cross-check of the signing wiring) + 2 integration (connection RBAC deny + connect→status→disconnect round-trip; store-only so no network mock). `pnpm gen` + `typecheck` (twitter/api/web) + `lint` + `check:tiers`/`check:modules` (21 modules) / `check:i18n` (2159 keys) / `check:mcp` all green. Note on limits: the X API is paywalled — the free tier covers posting/deleting, reading + search need a paid tier and aren't modelled.
