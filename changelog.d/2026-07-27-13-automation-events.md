- 2026-07-27: Automation / Events — **event triggers now advertise their payload fields**, so a flow author sees exactly what information a triggering event carries (who, when, which record …) instead of guessing at `{{ trigger.* }}` paths. The domain-event registry gained an optional per-event `fields` metadata list (`{ key, type, description }`) alongside its description, plus `COMMON_EVENT_FIELDS` (`occurredAt` / `type`) and `eventFieldsFor(type)` that merges the two ([event-registry.ts](monark/app/packages/common/src/event-registry.ts)). Every core module's `server/event-types.ts` (auth, users, feature-flags, organizations, rbac, notifications, data-models, automation, kanban) now declares its events' fields — e.g. `totp.disabled` exposes `userId` + `triggeredBy`. The automation `eventTypes.list` procedure returns the merged fields ([router.ts](monark/app/packages/automation/src/server/router.ts)), and the editor's Event Trigger inspector renders a new **Outputs** section listing each field with its type, description, and a click-to-copy `{{ trigger.<key> }}` token ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>) `TriggerOutputs`). Metadata only ; it doesn't validate emitted payloads. `pnpm gen` + `typecheck` + `lint` + `check:i18n` green ; new en/fr keys under `automation.editor.outputs*`.
