- 2026-07-05: Calendar — a freshly created event now appears without a page refresh. The day / week / month views refetched events after a create / update / delete by calling `utils.calendar.events.listForDay.fetch(range)`, but `fetch` = `queryClient.fetchQuery`, which honours the app's 30s default `staleTime` ([trpc-provider.tsx](monark/app/services/web/src/lib/trpc-provider.tsx)) and so returned the _cached_ (pre-mutation) events without hitting the server — the new event only showed after the query went stale or the page reloaded (most visible right after creating a new calendar, since that whole flow happens well inside 30s). Swapped the three post-mutation `fetch(range)` calls in [day-view.tsx](<monark/app/services/web/src/app/(authed)/calendar/day-view.tsx>), [week-view.tsx](<monark/app/services/web/src/app/(authed)/calendar/week-view.tsx>), and [month-view.tsx](<monark/app/services/web/src/app/(authed)/calendar/month-view.tsx>) for `invalidate(range)`, which marks the query stale and force-refetches the active observer regardless of `staleTime`. `tsc` + `eslint` + 222 tests green.
