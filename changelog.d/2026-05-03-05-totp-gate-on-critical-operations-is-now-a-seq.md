- 2026-05-03: TOTP gate on critical operations is now a sequential dialog instead of an inline field. Critical-action forms (change password, change email) had a TOTP `<InputOTP>` shoved into the form alongside the new value + confirmation, which made the form feel like a security checklist and discouraged completion. New shared [`<TotpConfirmDialog>`](monark/app/services/web/src/components/totp-confirm-dialog.tsx) component takes the friction off the main path : non-enrolled users hit Submit and the action runs ; enrolled users hit Submit, the dialog opens, they enter the 6-digit code, the action runs with the code in hand. Server-side rejections (`invalidTotpCode`, `totpRequired`) surface inside the dialog so the user can retry without losing their form input ; non-TOTP errors close the dialog so the user can adjust the form fields the toast pointed them at. Refactored consumers : [password-section.tsx](<monark/app/services/web/src/app/(authed)/account/password-section.tsx>) + [email-change-form.tsx](<monark/app/services/web/src/app/(authed)/account/email-change-form.tsx>). Sign-in TOTP page stays full-page (different context, full-screen layout makes sense there) ; the dialog only replaces the inline-on-form pattern. **i18n** (en + fr) : new `account.totp.dialog.{label, verify, verifying, cancel, default.{title, description}, passwordChange.{title, description}, emailChange.{title, description}}`.
