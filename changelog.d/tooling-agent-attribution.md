- 2026-08-16: Tooling — **machine-account attribution for agent work**, so agent PRs are reviewable. Agents authenticated as the repo owner, which meant every agent PR was authored by the owner and therefore un-approvable (GitHub blocks self-approval) ; agents now run as a dedicated `monark-agent` account with a scoped token (push + PR, no admin), so their PRs can be reviewed and approved normally. Added [.github/CODEOWNERS](.github/CODEOWNERS) routing review to the owner, which also makes a "require code owner review" branch rule meaningful — an agent cannot satisfy it by approving itself. Added [agent-attribution.yml](.github/workflows/agent-attribution.yml), which fails any PR opened by the machine account that contains commits authored by a human ; that mismatch is what an agent falling back to the owner's stored credentials looks like. Its limits are documented in the workflow itself: agents run as the owner's OS user and can reach their keyring, so this is detection, not prevention — the only real boundary would be running agents as a separate OS user.
