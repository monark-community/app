- 2026-08-03: Public API — **dropped the scope layer ; authority is now 100% RBAC.** The API-key `scopes` allow-list was a parallel taxonomy bolted on top of RBAC — redundant for our use case (OAuth-style third-party delegation, where scopes earn their keep, is deferred). Removed `API_SCOPES` / `ApiScope` / `assertScope` / the `x-required-scope` OpenAPI field / the `ApiKey.scopes` column (migration `20260803120000_drop_api_key_scopes`) / the scope pickers in both key-create dialogs. A key now acts as its **principal** and inherits that principal's roles, full stop : a **user key** = the creator's rights ("a headless me") ; a **service-account key** = the machine principal's admin-assigned roles. **Least-privilege is done by choosing the principal** — need a read-only key, create a service account with a read-only role — not by ticking scopes. The facade drops `assertScope` (the per-procedure `requirePermission` via the caller was always the real gate) and advertises each route's required RBAC permission as `x-required-permission`. Also removed the obsolete `projects:read` scope : projects are polymorphic Data Model records, so there is never a separate projects endpoint. `authenticateApiKey` now returns `{ apiKeyId, userId, organizationId }` (no scopes). The v1 account key-create dialog and the v2 service-account key-mint dialog are now just name + expiry, each with a note explaining what the key can do ([api-keys-section.tsx](<monark/app/services/web/src/app/(authed)/account/api-keys-section.tsx>), [service-account-panel.tsx](<monark/app/services/web/src/app/(authed)/admin/service-accounts/service-account-panel.tsx>)). Tests updated to match — the facade's least-privilege case is now the more honest **read-only service account → 403 on write** ([public-api.test.ts](monark/app/services/api/tests/integration/public-api.test.ts)), and a new **disabled-owner → 401** case covers the owner-alive check. Governance unchanged and reaffirmed : `api-keys.manage` (personal) and `api-keys.manage-service-accounts` (org) stay distinct, default-off — minting a long-lived credential is a governance decision, not an escalation (a key never exceeds its principal). Design note appended to [public-api.md](monark/app/docs/features-planning/phase-3/public-api.md). api-keys 19 + public-api 25 integration tests green ; typecheck (all packages bar unrelated in-flight dev-overlay work) + `check:tiers`/`check:modules` + eslint clean.
