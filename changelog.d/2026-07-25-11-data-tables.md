- 2026-07-25: Data tables — the Data section now uses a deterministic full-height layout, so a list's table fills the viewport and scrolls internally with a single scrollbar (no page scroll, no blank strip, no flicker). Earlier attempts had the shared [`DataTable`](monark/app/services/web/src/components/patterns/data-table/data-table.tsx) self-measure a height cap against the viewport ; that was fragile (a stale one-shot `docTop`, a reserved `pb-20` reappearing under the table as a second scrollbar, and a `scrollHeight`-based reservation that fed back into a runaway flicker). Replaced measurement with a CSS flex height chain in the Data shell, gated to the app's desktop breakpoint (`xl`, where the vertical rail replaces the horizontal tab bar) : [`data/layout.tsx`](<monark/app/services/web/src/app/(authed)/data/layout.tsx>) becomes a `xl:h-[100dvh]` flex column whose `<main>` is the single bounded scroll region (`xl:flex-1 xl:min-h-0 xl:overflow-y-auto`), the records page ([page.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/page.tsx>)) is `flex flex-col xl:h-full` whose table wrapper is `xl:flex-1 xl:min-h-0` ([records-list.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/records-list.tsx>) passes `tableClassName`), and `DataTable` gained a **`fillParent`** prop ([types.ts](monark/app/services/web/src/components/patterns/data-table/types.ts)) that at `xl+` takes `h-full` of its (already-bounded) parent and scrolls internally, skipping all measurement. A taller detail/form page under the same `<main>` scrolls `<main>` itself — still one scrollbar. **Below `xl` (phones / tablets)** everything falls back to plain block flow so the page scrolls naturally : the secondary tab bar's hide-on-scroll and the mobile URL-bar collapse keep working, and the `flex-1`/`h-full` classes are `xl:`-gated so they can't collapse to zero against the unbounded mobile parent. `DataTable` keeps its self-measuring mode as the default for window-scrolling sections (admin, etc.) that haven't adopted the shell yet, so this change is scoped to the Data section ; those can opt in to `fillParent` under the same pattern later.
