- 2026-05-01: Notification template variable enrichment. New [packages/notifications/src/server/enrich.ts](monark/app/packages/notifications/src/server/enrich.ts) replaces the old `stringifyVars()` in dispatch and computes the full template-var map: every Date field gets a locale-formatted `${key}Formatted` companion via `Intl.DateTimeFormat`, and every kind picks up `appUrl`, `accountLink`, `securityLink`, `revokeLink`, `signInLink` derived from `process.env.APP_URL` (defaults to `http://localhost:3000`). Per-kind derivations live in an exhaustive switch ; today only `auth.new-device` needs one (`deviceWhere = country · ip`, with a localised "Unknown location" / "Lieu inconnu" fallback when both are missing). Templates that referenced `occurredAtFormatted`, `seenAtFormatted`, `completesAtFormatted`, `securityLink`, `accountLink`, `revokeLink`, `deviceWhere` were rendering literal `{{ tokenName }}` strings before this fix because dispatch only stringified the raw payload ; they now resolve correctly. 11 new unit tests in [tests/enrich.test.ts](monark/app/packages/notifications/tests/enrich.test.ts) cover Date formatting, locale switching, APP_URL trailing-slash normalisation, and the new-device fallbacks.
