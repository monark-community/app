- 2026-05-04: Account-deletion flow tightened end-to-end. Five gaps closed in one pass : (1) the `/account/delete` page is gone ; the typed-email confirmation now lives in a [`<DeleteAccountDialog>`](<monark/app/services/web/src/app/(authed)/account/delete-account-dialog.tsx>) launched from the danger tab, which keeps the destructive surface inline with the rest of the danger-zone affordances and removes the only `/account/<sub-route>` that didn't carry tab state. (2) Post-signout the deletion-scheduled banner on `/signin?deletionScheduledAt=…` now formats the date through `useLocale()` + `[locale, "en"]` fallback instead of the runtime default, matching the email-change banner's pattern. (3) Sign-in into a deletion-pending account now lands on `/account?tab=danger` (banner + Cancel button visible immediately) ; [signin/actions.ts](<monark/app/services/web/src/app/(anon)/signin/actions.ts>) reads `users.me` after `notifySignedIn` and forwards if `deletedAt` is set. (4) During the 14-day grace window the user is locked into a limited-access shell : the [`(authed)/layout.tsx`](<monark/app/services/web/src/app/(authed)/layout.tsx>) gate redirects every non-`/account` path to `/account?tab=danger` (reads the resolved pathname via a new `x-pathname` request header set in [middleware.ts](monark/app/services/web/src/middleware.ts), since Next 15 layouts don't expose `pathname` directly) ; [account-shell.tsx](<monark/app/services/web/src/app/(authed)/account/account-shell.tsx>) filters the tab rail to `profile + danger` only ; [profile-section.tsx](<monark/app/services/web/src/app/(authed)/account/profile-section.tsx>) flips every input/button to `disabled` and shows an amber `readOnlyBanner` linking back to the danger tab so the user understands _why_ fields are locked. (5) The 14-day cleanup is now wired : `processExpiredDeletions()` (in `@monark/auth/server`) was already correct but had no caller ; new `POST /cron/process-account-deletions` endpoint on [services/api/src/server.ts](monark/app/services/api/src/server.ts) authenticates via `Authorization: Bearer $CRON_SECRET` and runs the sweep. Deliberately not on the web service since the eslint policy forbids `@monark/*/server` imports there ; any HTTP scheduler (Vercel Cron, GitHub Actions, k8s CronJob, EasyCron) can hit the endpoint. **i18n** (en + fr) : new `account.profile.readOnlyBanner.{title, subtitle, cta}` ; dropped `appBar.sections.deleteAccount`.
