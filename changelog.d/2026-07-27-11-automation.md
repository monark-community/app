- 2026-07-27: Automation — **Manual** and **HTTP** trigger nodes (loops deferred). Trigger matching happens at enqueue time by comparing `Automation.triggerEventType` to the event type, and the subscriber ignores `automation.*` events — so both new triggers store a **bus-ignored sentinel** event type ([contracts/triggers.ts](monark/app/packages/automation/src/contracts/triggers.ts): `automation.manual` / `automation.http`) and never fire from a platform event ; no schema migration. The server derives that sentinel from the graph's trigger node on save (`resolveTriggerEventType`, [router.ts](monark/app/packages/automation/src/server/router.ts)). **Manual trigger** ([nodes/manual-trigger.ts](monark/app/packages/automation/src/server/nodes/manual-trigger.ts)) runs only via Run now. **HTTP trigger** ([nodes/http-trigger.ts](monark/app/packages/automation/src/server/nodes/http-trigger.ts)) is fired by an inbound `POST /hooks/automation/:id` — a new Express route on the API service ([services/api/src/server.ts](monark/app/services/api/src/server.ts)) mirroring the cron-token pattern, but auth is a **per-automation secret** verified in constant time ([http-trigger.ts](monark/app/packages/automation/src/server/http-trigger.ts) `handleHttpTrigger`); the request body becomes the trigger payload (`{{ trigger.body.* }}`). The secret is generated server-side via a new `automations.newHttpSecret` mutation and shown, with the URL, in a dedicated editor section ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>)); the node face drops the "no event" line for triggers that have no event to pick. New `automation.editor.http*` i18n (en + fr). 3 new integration tests (manual run, HTTP right/wrong secret + body exposure, disabled-automation reject) — **20/20** integration + 9 validator unit ; `typecheck` (web + automation + api) + `lint` + `check:i18n` (1635 keys × 2) green.
