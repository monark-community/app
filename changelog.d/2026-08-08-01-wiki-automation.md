- 2026-08-08: Wiki × Automation — **wiki action nodes for automations** (the write half of the integration ; the trigger half was already free via the wiki's registered domain events). `packages/wiki/src/server/nodes.ts` registers three nodes under the `wiki` namespace via `@monark/automation`'s `registerAutomationNodes` (wired at api boot in [server.ts](monark/app/services/api/src/server.ts)): **`wiki.create-page`** (optional parent + plain-text body), **`wiki.update-page`** (title / icon / body), **`wiki.delete-page`** (soft-deletes the subtree, returns the count). They mirror the built-in Data Record nodes exactly — resolve the automation owner, gate on the owner's own `wiki.create/update/delete` permission (`hasPermission`, so a node can't do what its owner couldn't in the UI), call the wiki data layer directly, and **emit no wiki events** (so a flow can't re-trigger itself). Plain-text bodies become blocks via a new pure `textToBlocks` in [@monark/common/blocks](monark/app/packages/common/src/blocks.ts). `@monark/automation` is a **core** module, so this is a normal extended→core dependency (no `integrates` needed). Now automations can both react to wiki changes and act on the wiki. Tests: `textToBlocks` unit + `wiki-nodes.test.ts` (create/nest/body, cross-org + no-owner rejection, update, subtree delete) against a testcontainer.
