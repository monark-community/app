- 2026-09-08: RBAC / Data Models: **record scopes are now authored in the role editor**, and an unreadable relation says so instead of hanging. Scopes previously had no UI ; `/admin/rbac` → a role → **Record scopes** ([role-scopes-section.tsx](<services/web/src/app/(authed)/admin/rbac/role-scopes-section.tsx>)) now lists every database that role can read, with its current limit and the same `QueryChipBar` the record list uses, so the query language is learned once. Edit-mode only (a scope hangs off a role id, so there is nothing to attach it to until the role exists) and it saves immediately rather than joining the role form's dirty state, mirroring `RecordAccessSection` for the per-record ACL ; built-in ADMIN is excluded, since it bypasses every scope and the section would be a control that does nothing. The scope wire format changed to MonarkQL **text** in both directions: `scopes.set` now parses server-side against the model's real fields, so a typo is an error at save time rather than a query that breaks later, and the list procedures return canonical printed text. That was forced by a real constraint worth recording, since returning `Prisma.JsonValue` pushes a recursive type through tRPC's client inference and trips `TS2589` in the web app ; text is also simply what a caller wants to render or re-edit. New `scopes.listForRole` lets the editor render in one request instead of one per database. Separately, an **unreadable relation now reads as "Restricted"** ([relation-field.tsx](services/web/src/components/fields/inputs/relation-field.tsx)): relation ids live on the record but resolving each to a label goes through the permission-checked record procedures, so a viewer can hold a record linking to one they may not read (model permission, per-record ACL, or a scope). Those chips sat on "Loading…" forever, reading as a broken UI rather than a boundary ; they now render with an outline tone and a tooltip, still shown rather than hidden, because the viewer should know something is attached without learning what it is and dropping it silently would under-report the record's links. A whole-batch failure (network, not permissions) leaves the ids pending rather than mislabelling them. 3 component tests (verified to fail without the fix) plus 3 new integration tests covering save-time field validation and the empty-scope rejection.
