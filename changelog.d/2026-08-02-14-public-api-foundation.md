- 2026-08-02: Public API (foundation) — **`@monark/api-keys`** core module, the credential layer the public REST API will authenticate with. Hashed, scoped, org-pinned API keys : `mint` returns a `mrk_<base64url(32)>` plaintext exactly once and stores only its SHA-256 hash (a `@unique` column), matching the invite / webhook / trusted-device pattern ([data.ts](monark/app/packages/api-keys/src/server/data.ts)). `authenticateApiKey(plaintext)` verifies a key and resolves it to `{ userId: ownerUserId, organizationId, scopes }` — rejecting unknown / revoked / expired / wrong-prefix keys and dropping unknown scopes — which the (next-milestone) public-API facade turns into the `{ userId, activeOrganizationId }` context the existing RBAC guards already consume, so **v1 keys act as their owning user and can never exceed that user's grants** (zero RBAC schema change). Keys are **org-pinned** and carry a coarse **scope** allow-list (`API_SCOPES`) that only ever narrows the owner's permissions. A management router (`apiKeys.{list,create,revoke}`, gated by a new `api-keys.manage` permission, never returns the hash) backs the forthcoming key-management UI ; emits `api-keys.key-created` / `-revoked` (webhook-subscribable, never carrying the secret). New `ApiKey` model ([prisma/api-keys.prisma](monark/app/packages/api-keys/prisma/api-keys.prisma), FK+cascade to `Organization` + `User`, migration `20260802120000_add_api_keys`). `register*` wired at api boot. Also scaffolded **`@monark/public-api`** (the REST + OpenAPI facade — next milestone ; its integration suite is an acknowledged gap for now).
