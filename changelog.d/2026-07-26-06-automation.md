- 2026-07-26: Automation — conditional branching (a **Condition** node + engine active-handle gating). The engine ([engine.ts](monark/app/packages/automation/src/server/engine.ts)) now gates each node on its incoming edges' **source handles**: a node runs only if it's the trigger or an already-executed upstream node activated the handle feeding it, otherwise its step is recorded `SKIPPED` and its own outputs never fire — so a whole un-taken branch prunes. Nodes activate all outputs by default (linear flows unchanged) or call `ctx.activateOutputs([...])` ([registry.ts](monark/app/packages/automation/src/server/registry.ts)). The new [Condition node](monark/app/packages/automation/src/server/nodes/condition.ts) compares an interpolated value (`eq` / `neq` / `contains` / `gt` / `lt` / `gte` / `lte` / `truthy` / `empty`) and activates its `true` or `false` output. The React Flow editor ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>)) renders one id'd source handle per output (so edges carry `sourceHandle`), with labels for multi-output nodes. New integration spec proves the taken branch runs and the other is `SKIPPED` (7/7 against a testcontainer). `typecheck` (automation + web) + `lint` (automation) green.
