- 2026-05-07: Webhook subscription picker rewrite + mock receiver + e2e + secret-store overhaul. Closes the operator-friction gap on the morning's webhook admin UI.
  - **Event-type registry as the 6th extension point.** [packages/common/src/event-registry.ts](monark/app/packages/common/src/event-registry.ts) ships `registerEventTypes(module, types)` + `listEventTypesByModule()`. Each domain module registers its events with operator-facing descriptions at api boot ([packages/auth/src/server/event-types.ts](monark/app/packages/auth/src/server/event-types.ts), [packages/feature-flags/src/server/event-types.ts](monark/app/packages/feature-flags/src/server/event-types.ts), notifications / organizations / rbac / users mirrors). Wired in [services/api/src/server.ts](monark/app/services/api/src/server.ts) next to the other `register*` calls. Total : 31 event types registered ; `webhook.*` events intentionally skipped because the wildcard subscriber filters them to avoid recursion.
  - **`webhooks.listEventTypes` tRPC procedure.** Returns the merged registry grouped by module, gated on the rbac `webhooks.read` permission. Powers the new picker.
  - **Subscription picker** ([services/web/src/app/(authed)/admin/webhooks/subscription-picker.tsx](<monark/app/services/web/src/app/(authed)/admin/webhooks/subscription-picker.tsx>)). Replaces the previous free-text + advanced-mode rows with a categorized expansion-panel surface that mirrors the RBAC role-editor's permission picker exactly : bordered container, one Collapsible per module with a tri-state header checkbox + chevron + `selected/total` count chip, individual event rows as bordered labels with mono key + plain-language description. Tri-state behavior writes a single prefix subscription (`rbac.`) when every event in the module shares a common dotted prefix ; falls back to N exact subscriptions when they don't (the auth module's mixed `user.` / `trusted-device.` / `totp.` events). Pre-existing custom subscriptions that aren't in the registry surface as removable chips at the top so operators can clean them up. Advanced free-text mode removed entirely — the picker covers every legitimate case.
  - **`tools/webhook-receiver.ts` mock receiver.** Standalone Node HTTP server that captures incoming POSTs at `/hook`, exposes the captures as JSON via `/inbox`, and optionally validates HMAC signatures (`--secret <plaintext>`) or fails the first request once (`--fail-once`) for retry-loop testing. Run via `pnpm webhook-receiver --port 4123` for manual smoke testing while developing webhook receivers ; the e2e harness boots it as a child process.
  - **e2e spec** [services/web/tests/e2e/admin-webhooks.spec.ts](monark/app/services/web/tests/e2e/admin-webhooks.spec.ts). Boots the receiver in `beforeAll`, signs in as the seeded admin, drives /admin/webhooks → New endpoint → ticks the `rbac` group tri-state → Create → triggers `rbac.role-created` by creating a custom role → polls the receiver's `/inbox` until the matching capture lands → asserts the `Webhook-Signature` header is `v1=<hex>`, `Webhook-Delivery-Idempotency-Key` is present, and the body's `data.roleKey` matches the created role. Cleanup deletes the role + the endpoint so re-runs are idempotent. Helper at [services/web/tests/e2e/helpers/webhook-receiver.ts](monark/app/services/web/tests/e2e/helpers/webhook-receiver.ts) handles the child-process spawn + healthz poll + waitForCapture utility. Gated behind `E2E_FULL_STACK=1`.
  - **Secret-store refactor.** [packages/webhooks/src/server/secret-store.ts](monark/app/packages/webhooks/src/server/secret-store.ts) replaces the read-only `setWebhookSecretResolver()` with a `SecretStore` interface (put / get / delete) plus a default in-memory implementation that the router populates on every create + rotate (and clears on delete). Means out-of-the-box dev / single-process deploys work end-to-end without wiring an external secret store. An opt-in file-backed implementation (set `MONARK_DEV_WEBHOOK_SECRETS_FILE=<path>` outside production) survives `pnpm dev` restarts. Production deploys still swap the store via `setWebhookSecretStore()` for AWS Secrets Manager / Vault / GCP / Azure ; the seam is the same.
