- 2026-07-28: Automation — **Scheduled (cron-like) trigger**. A new `Schedule` trigger node runs a flow on a recurring schedule : **interval** ("every 20 minutes"), **daily** ("every day at 09:00"), **weekly** ("every 2 weeks on Wed"), **monthly by date** (a day-of-month, or the last day), and **monthly by weekday** ("the second Wednesday at 08:00"). **Backend is UTC** — a library-free, DST-proof `nextFireTime(schedule, after)` engine ([contracts/schedule.ts](monark/app/packages/automation/src/contracts/schedule.ts), `AutomationSchedule` zod union) — with an indexed `Automation.scheduleNextRunAt` column ([base.prisma](monark/app/packages/db/prisma/base.prisma), migration `20260728135512_automation_schedule`) kept in sync on every save/enable (`syncScheduleNextRunAt`, idempotent for an unchanged future schedule). A **scheduler** ([scheduler.ts](monark/app/packages/automation/src/server/scheduler.ts) `runDueSchedules`) claims due rows, enqueues a `PENDING` run the existing worker drains, and advances to the next fire via an atomic compare-and-set (`claimScheduledFire`) — so a fire enqueues **exactly one** run across overlapping ticks / worker processes. Driven by the worker loop ([worker.ts](monark/app/packages/automation/src/server/worker.ts)) plus a `/cron/run-automation-schedules` fallback endpoint ([services/api server.ts](monark/app/services/api/src/server.ts)). The trigger stores the bus-ignored `automation.schedule` sentinel (like manual/HTTP), and exposes `{{ trigger.scheduledFor }}` / `{{ trigger.firedAt }}`. **Editor**: a new `schedule` config-field type renders a [`ScheduleBuilder`](<monark/app/services/web/src/app/(authed)/automation/[id]/schedule-builder.tsx>) (kind picker + kind-specific controls + a live "next run" preview) that works in the **viewer's local timezone**, converting to/from UTC at the storage boundary (rolling the weekday across midnight so it stays correct) — new `automation.editor.schedule.*` i18n (en + fr). 5 schedule-engine unit tests (all four example patterns + day-of-month edges) + a scheduler integration test (enable sets next-run, scheduler enqueues + advances exactly once, run executes) — **23/23** integration + engine unit green ; `pnpm gen` + automation/web/api `typecheck` + `lint` + `check:i18n` (1758 × 2) green. Follow-up : a per-user timezone preference (the editor uses the browser timezone today) and an anchor picker for "every N weeks/days".
