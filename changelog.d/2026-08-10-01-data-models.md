- 2026-08-10: Data models — **voting + discussions** (record engagement on the public board). Two per-model toggles ([base.prisma](monark/app/packages/db/prisma/base.prisma) `DataModel.votingEnabled` / `discussionsEnabled`, migration [20260810184213](monark/app/packages/db/prisma/migrations/20260810184213_data_record_engagement/migration.sql)) turn on upvoting and threaded comments on a model's records; both surface on the `/f/[token]` board, gated by the existing `data-models.public-forms` flag. **Engagement is never anonymous**, so no cookie/visitor substrate was needed: the identity is a real principal. **Voting** (`DataRecordVote`) accepts a logged-in user _or_ a board invite; the one-vote rule is the DB `@@unique([dataRecordId, voterKey])` where `voterKey = "user:<id>" | "invite:<id>"`, and the board gains a `sort: "top"` ranking by vote `_count`. **Discussions** (`DataRecordComment`) are **user-only** (a logged-in `User` authors them — no anonymous/invite comments), **auto-published**, with admin moderation — `hidden` (kept, not shown publicly) + soft `deletedAt` (author or `manage-forms` admin); bodies are tag-stripped on write (no stored HTML). Data layer is a new form-agnostic [engagement.ts](monark/app/packages/data-models/src/server/engagement.ts) (so the authed record view can reuse it later); new token-authorized procedures `forms.public.{vote,voteState,comments.{list,post,remove,setHidden},canModerate}` ([router.ts](monark/app/packages/data-models/src/server/router.ts)), all batched (no N+1) and rate-limited. New `data-models.record-commented` event → a notification to the record's watchers ([record-watch-subscriber.ts](monark/app/packages/data-models/src/server/record-watch-subscriber.ts) + a new IN_APP kind).
