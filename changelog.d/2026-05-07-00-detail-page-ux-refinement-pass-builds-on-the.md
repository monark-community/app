- 2026-05-07: Detail-page UX refinement pass. Builds on the prior card-less standardization with a shared page header + an editable user banner + an explicit save model on org settings, plus a Danger-Zone card wrapper that lifts irreversible actions out of the rest of the page.
  - **Shared `<PageHeader>` primitive** ([services/web/src/components/page-header.tsx](monark/app/services/web/src/components/page-header.tsx)). Renders the page-level `h1` + optional subtitle + a back-button affordance that lives in the left gutter on `xl+` viewports (absolute-positioned so the title's vertical anchor doesn't shift between sibling pages) and falls back to an inline link on narrow screens. Adds a bottom `<Separator />` by default. Used by `/admin/webhooks/[id]` (editor + tabs nav + deliveries list + delivery detail), `/admin/rbac/roles/[id]`, `/admin/organizations/[id]`. `<AccountPageHeader>` now delegates to it so heading hierarchy is uniform.
  - **Shared `<UserBanner>` hero** ([services/web/src/components/user-banner.tsx](monark/app/services/web/src/components/user-banner.tsx)). Full-bleed banner image (or brand gradient) with a `from-transparent from-50% to-background` fade, avatar + display name + optional badges aligned to the banner's bottom edge. Mirrors the user-menu drawer's identity treatment so the same visual identity treatment lands in both places. Optional `edit` prop wires up file pickers + Replace/Remove dropdowns + hover overlays so the banner can be the editing surface itself ; the caller stays in charge of upload mutations + crop dialogs (self-service crops 1:1 / 3:1 ; admin uploads skip the crop step). Both `/account/profile` (ProfileSection) and `/admin/users/[id]` (AdminProfileForm) now render UserBanner as their hero ; the embedded banner editors that used to live inside those forms are gone, and AdminProfileForm's redundant "Profile / Edit display info" `PageSection` wrapper is dropped.
  - **`/admin/organizations/[id]` switches from on-blur autosave to an explicit Save / Cancel footer** ([organization-detail.tsx](<monark/app/services/web/src/app/(authed)/admin/organizations/[id]/organization-detail.tsx>)). Save sits right-most ; Cancel sits to its left. Both are disabled until at least one field actually changed (dirty-check vs. the source row). The mutation only ships fields that diverge from the baseline, so audit-log entries don't churn for round-trips. New `admin.organizations.detail.{save,saving,cancel,backAria}` i18n keys.
  - **Shared `<DangerCard>` + `<DangerRow>`** ([services/web/src/components/danger-card.tsx](monark/app/services/web/src/components/danger-card.tsx)). Card-bordered wrapper for irreversible actions ; tone variant flips between red (`danger`, default) and amber (`warning`, used for the in-grace-cancel surface). Each row inside is a `<DangerRow>` with title + description on the left and the action button on the right. Applied to the webhook editor's rotate-secret + delete pair, `/account/danger` (delete account / cancel scheduled deletion), and `/admin/users/[id]`'s Danger Zone (request deletion + hard delete + grace-period cancel). New `account.danger.{deleteDescription,cancelDescription}` + `admin.users.dangerZone.cancelDescription` i18n keys.
  - **`/account/profile` skips `<AccountPageHeader>` entirely** since the UserBanner serves as its hero. Other account tabs (security, notifications, danger) still render AccountPageHeader.
  - **i18n cleanup**. Em-dashes scrubbed from prose across en.json + fr.json (replaced with `;` / `:` / `,` per context, per the project's prose-style rule). Org detail subtitle drops the "Edits are saved on blur" copy now that the form gates on Save.
  - **Net effect.** `pnpm typecheck` clean. The same heading hierarchy + visual rhythm now anchors every detail page across the admin + account surfaces ; destructive actions are visually carded so they read as distinct from the editing surface above them ; the user-identity treatment is one component everywhere it appears.
