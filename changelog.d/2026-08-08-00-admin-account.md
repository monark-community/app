- 2026-08-08: Admin / Account — fixed unreachable content on tall pages (e.g. the Data Model editor, Account Security) at every breakpoint, not just mobile. `<body>` is globally `overflow-y-hidden` (the earlier "table pages scroll internally" work), so every section needs its own bounded-height + `overflow-y-auto` region or content taller than one screen is simply unreachable — `admin/layout.tsx` and `account/layout.tsx` never got that treatment (unlike `data/layout.tsx`, though its version is only `xl:`-gated) and had no scrolling container at all. Both now wrap their shell in an unconditional `flex h-[calc(100dvh-57px)] flex-col overflow-hidden`, matching the already-correct `wiki/layout.tsx` pattern, with `<main>` as the one `min-h-0 flex-1 overflow-y-auto` scrolling region ; `PageLayout`'s sidebar `aside` is `position: fixed` so it's unaffected either way. Fixing this surfaced a second bug : the shared [`SecondaryTabsBar`](monark/app/services/web/src/components/secondary-tabs-bar.tsx) (mobile horizontal tab strip) is `sticky top-14`, calibrated for sitting directly in the page's own scroll flow — nested inside the new bounded wrapper, its sticky reference becomes that wrapper (whose top edge sits _after_ the AppBar, not at the true page top), so `top-14` double-counted the AppBar's height and the bar rendered overlapping the content below it. Added an opt-in `pinned` prop : a plain static row (no sticky, no scroll-driven hide/reveal) for shells like admin/account where the bar already sits outside the one scrolling region and structurally never needs to stick or hide ; `data/layout.tsx`'s mobile usage is untouched (unaffected, since its wrapper is `xl:`-only). `tsc` + `eslint` + 279 web tests green ; verified end-to-end with Playwright at desktop and iPhone-13 viewports (scrollable-container detection + bounding-box measurements before/after, confirming both the reachability fix and the overlap fix).
