- 2026-05-04: Admin RBAC UI (slice 6 of the admin view). Two new admin-gated tRPC procedures on the rbac router : `rbac.adminAssignRole({ userId, role, organizationId?, reason? })` and `rbac.adminRevokeRole({ assignmentId, reason? })`. Both call into the existing `assignRole` / `revokeRole` server primitives ; the underlying functions already validate the role/orgId pairing (MONARK_ADMIN is platform-only, every other role requires an orgId), so the procedures just gate on rbac and pipe the actor through as `grantedById` / `revokedById` so the audit events carry the right attribution. `@monark/rbac` now has `zod` in its workspace deps. UI : new [admin-roles.tsx](<monark/app/services/web/src/app/(authed)/admin/users/[id]/admin-roles.tsx>) replaces the read-only Roles card on the user detail page ; lists existing assignments with a Revoke button per row, and an "Assign new role" form below that pivots on role selection (MONARK_ADMIN hides the org dropdown and forces `organizationId: null` ; every other role surfaces the org dropdown fed by the same `organizations.adminList` query the orgs page uses, capped at 100 items pre-typeahead). [/admin/rbac](<monark/app/services/web/src/app/(authed)/admin/rbac/page.tsx>) gets a real (if minimal) page that points operators to the per-user surface ; a global "all assignments" overview is a future enhancement. **i18n** (en + fr) : `admin.users.roles.*` (assignment list + add form + toasts) and `admin.rbac.{subtitle, perUserTitle, perUserSubtitle, perUserCta}`.
