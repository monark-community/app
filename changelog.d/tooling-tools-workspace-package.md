- 2026-09-08: Tooling — promoted `tools/` to a workspace package (`@monark/tools`) so its scripts are covered by the same gate as the rest of the repo. Several of them — [check-tiers](../tools/check-tiers.ts), [check-modules](../tools/check-modules.ts), [check-i18n](../tools/check-i18n.ts), [check-public-api-mcp](../tools/check-public-api-mcp.ts), [check-migrations](../tools/check-migrations.ts) — **are** the CI gates, and an untested gate has the worst failure mode available to it : a bug doesn't turn the build red, it silently stops enforcing. `tools/` previously sat outside `pnpm-workspace.yaml`, so turbo never saw it and a test file placed there would not have run at all, locally or in CI. It now carries a `package.json` + [vitest config](../tools/vitest.config.ts) like every other package, and `pnpm test` includes it. The preflight `.env`-parser tests moved off Node's built-in runner onto vitest (the bespoke `pnpm test:preflight` script is gone with it), and [tools/lib/names.ts](../tools/lib/names.ts) — which decides the identifiers `gen-events` / `gen-routers` / `gen-module` write into generated files — picked up its first coverage. No coverage floor is configured : [merge-coverage.ts](../tools/merge-coverage.ts) only walks `packages/` and `services/`, so this package is outside the merged report by construction and a floor would never be evaluated.
