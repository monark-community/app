- 2026-07-27: Kanban — a card's **description is now a rich-text (WYSIWYG) editor** instead of a plain `<textarea>`. The card editor ([card-editor.tsx](<monark/app/services/web/src/app/(authed)/kanban/card-editor.tsx>)) reuses the shared TipTap [`RichTextEditor`](monark/app/services/web/src/components/fields/inputs/rich-text-editor.tsx) from the fields toolkit (headings, bold/italic/strike/code, lists, blockquote, links) with its toolbar strings from `useFieldStrings().labels.richText`, so no new i18n. The value is sanitized HTML (same format the Data Models `richText` fields store) ; existing plain-text descriptions load fine (rendered as a paragraph). The card `description` input caps on [`cards.create` / `cards.update`](monark/app/packages/kanban/src/server/index.ts) were raised 2000 → 20000 chars to fit the HTML markup. No schema change (the column stays `String`) ; the card face doesn't render the description, so there's no read view to update. `tsc` (web + kanban) + `eslint` green. A new board's six seeded columns now carry a progression palette (grey Backlog → blue Todo → amber In Progress → purple Review → cyan QA → green Done) so the header dots read as a pipeline out of the box instead of all grey. `DEFAULT_COLUMNS` (name + colour) in [contracts/types.ts](monark/app/packages/kanban/src/contracts/types.ts) is the single source of truth (`DEFAULT_COLUMN_NAMES` derives from it) and `createBoard` ([data.ts](monark/app/packages/kanban/src/server/data.ts)) seeds the colour alongside the name; the `BoardColumn` header dot already rendered `color`. Existing boards keep their columns' current colour (recolour per-column via the header `…` → Edit). Header layout is now **grip → colour dot → name** ([board-column.tsx](monark/app/packages/kanban/src/client/ui/board-column.tsx)): the reorder grip sits at the far left but **collapses its own width when hidden** ([kanban-board-view.tsx](<monark/app/services/web/src/app/(authed)/kanban/kanban-board-view.tsx>)), so at rest the colour dot reads as flush-left and the grip reveals to its left on hover / touch without leaving a reserved gap. The board's **loading skeleton** was rebuilt to match the flat column style (full-height, no-gap columns with divider borders + an underlined dot-and-name header, replacing the old raised/rounded/gapped placeholder) so nothing shifts when the board loads; a `kanban-skeleton` screenshot story covers it.
