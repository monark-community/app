- 2026-05-02: Dev-LAN diagnostics + one-shot Windows setup script. Two new things to make "phone hits dev PC" work without guesswork :

  **`/dev-diagnostics` page** ([dev-diagnostics/page.tsx](monark/app/services/web/src/app/dev-diagnostics/page.tsx) + [client](monark/app/services/web/src/app/dev-diagnostics/dev-diagnostics-client.tsx)). Returns 404 in production. Open it from the device that's having trouble (typically the phone) at `http://<dev-host>:3000/dev-diagnostics`. Shows the browser's current host, the configured + resolved URL for each service (web / api / Supabase), fetches each one, surfaces the actual error + a hint when something fails ("Connection failed before the server responded — likely Windows Firewall / api not bound to 0.0.0.0 / wrong network", or for Supabase, "containers bind to 127.0.0.1 by default — set up portproxy + firewall rule"). Strictly-dev so it doesn't leak any reachability info in production builds.

  **`tools/dev-lan-setup.ps1`** ([dev-lan-setup.ps1](monark/app/tools/dev-lan-setup.ps1)). Idempotent Windows PowerShell script that auto-detects the dev machine's LAN IP (or accepts `-LanIp 10.0.0.208`), opens Windows Firewall on the **Private** profile only (never public Wi-Fi) for ports 3000 / 4000 / 54321, sets up a `netsh portproxy` from `<LanIp>:54321 → 127.0.0.1:54321` so phones can reach Supabase (which Docker only binds to loopback), and runs `Test-NetConnection` against each port to verify. Tear down with `-Remove`. Replaces the multi-step manual "first netsh, then maybe firewall, then maybe restart Docker" the previous CHANGELOG entry described.

  **`rewriteForCurrentHost` now logs in dev** ([dev-host-rewrite.ts](monark/app/services/web/src/lib/dev-host-rewrite.ts)) — when the URL actually swaps, a `console.info("[dev-host-rewrite] http://localhost:4000 → http://10.0.0.208:4000")` line lands in the browser console so you can verify the swap from your phone (Safari / Chrome both surface this on a remote-debug session).
