- 2026-07-25: Data models — **adding or editing a `FORMULA` field now backfills existing records**, fixing formula columns rendering empty in the record table. Compute-on-write only ran on record writes, so any record that predated a formula field (or predated an expression change) had no stored value — the form preview computed it live and looked fine, but the data table (which shows the _stored_ value) rendered a dash. New `recomputeModelRecords(dataModelId)` in [data.ts](monark/app/packages/data-models/src/server/data.ts) re-evaluates every record's formulas in place (skipping records whose output is unchanged, so a no-op re-save writes nothing) and refreshes a formula-backed title ; `createDataField` calls it after adding a `FORMULA` field and `updateDataField` after a formula's expression changes. Two integration specs (backfill on add, re-backfill on expression change) ; full formula suite (9) green against a real Postgres testcontainer. RBAC/events/notifications/webhooks/flags unchanged (rides the existing schema-edit permission ; a bounded admin-time recompute).
