- 2026-07-27: Automation — value-source nodes no longer need a flow-in wire. A **Constant** / **Transform** is a pure value source with no real input dependency, so it shouldn't have to be threaded into the execution sequence just to run. They now declare `inputs: []` and render **no control-flow input handle** ([constant.ts](monark/app/packages/automation/src/server/nodes/constant.ts), [transform.ts](monark/app/packages/automation/src/server/nodes/transform.ts) ; the editor's `FlowNode` only draws the flow-in for nodes that have control inputs, [automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>)). The engine's `executionOrder` ([engine.ts](monark/app/packages/automation/src/server/engine.ts)) now **pulls a data-source into the run automatically**: any node feeding a `field:` port of a reachable node is added to the execution set and ordered before its consumer, even with no control edge into it — so wiring a Constant's output into a downstream field is enough to make it run. Integration spec updated to a source Constant with no control edge feeding two fields (15/15 against a testcontainer). `typecheck` (web + automation) + `lint` green.
