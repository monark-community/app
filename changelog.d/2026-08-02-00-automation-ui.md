- 2026-08-02: Automation / UI — **variable chip input.** A `{{ … }}` reference in a config field now renders as an atomic, styled **chip** amid free-editable text, instead of raw braces — the automation editor's message/text fields and every variable-mode field read like prose with pills, and a single Backspace removes a whole token. New generic (no automation coupling) `VariableInput` in the shared UI package ([variable-input.tsx](monark/app/packages/components/src/ui/variable-input.tsx), documented in the [package README](monark/app/packages/components/README.md)): a `contentEditable` surface kept _uncontrolled_ while typing (so the caret never jumps) that serializes back to a plain string through `onChange` and only rebuilds its DOM when `value` changes from the outside; chips are `contentEditable=false` spans, paste comes in as plain text, and a `resolveToken(raw) → { label, invalid }` prop lets the caller name a chip and flag a dead reference without the component knowing the token grammar. It exposes a `VariableInputHandle` on focus so the inspector's picker inserts a chip at the caret (the old string-slice insertion is gone). The automation editor ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>)) swaps its text / textarea / variable-mode inputs for `VariableInput`, builds a `resolveToken` that maps `{{ steps.<slug>.… }}` to a friendly "step name.path" and marks a missing step invalid, and threads the focus handle through `ConfigPanel` → `ConfigField`. The pure `tokenizeValue` / `serializeEditor` helpers are exported and their round-trip verified headless (mixed tokens, newlines, trailing chips, `<br>`). `@monark/components` + `web` typecheck + lint + `check:i18n` green.
