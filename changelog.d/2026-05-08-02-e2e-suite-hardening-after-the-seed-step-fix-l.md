- 2026-05-08: e2e suite hardening. After the seed-step fix landed earlier today, the next CI run surfaced two more failure classes in the e2e job. Pragmatic fixes for both, plus diagnostic logging so the next bounce-loop reveals which gate is firing.
  - **Mailpit ECONNREFUSED** ([services/web/tests/e2e/signup-happy-path.spec.ts](monark/app/services/web/tests/e2e/signup-happy-path.spec.ts)). The signup-happy-path spec was the only one still pointing at `helpers/mailpit.ts` ; CI runs `supabase start` which boots **Inbucket** on 54324, not Mailpit on 8025, so every clear/poll call hit `connect ECONNREFUSED ::1:8025`. Converted the spec to use `helpers/inbucket` (matching the rest of the email-using e2e suite : forgot-password, signup-confirm). Adjusted the mailbox-clear call to take `email` (Inbucket's per-mailbox API vs Mailpit's global flush) and the body fields from `message.HTML` / `message.Text` to the Inbucket-helper-shaped `message.html` / `message.text`. The Mailpit helper file stays for local dev stacks that swap it in, just unused in CI.
  - **Sign-in bounce loop** ([services/web/playwright.config.ts](monark/app/services/web/playwright.config.ts) + [services/web/src/app/(authed)/layout.tsx](<monark/app/services/web/src/app/(authed)/layout.tsx>)). Nine specs failed on the same pattern : signed in successfully → landed on `/account` → immediately bounced to `/signin`. Best hypothesis after reading the gate code without trace access : `pnpm dev` runs `api` and `web` in parallel via turbo, and the previous Playwright config waited only on `http://localhost:3000` to come up. The api can still be booting when web responds, so the seeded sign-in's tRPC calls (trusted-device `recognize`, totp `isChallengeRequired`) intermittently fail and the (authed) layout's `isCurrentDeviceTrusted` then bounces the request through `/auth/sign-out-stale` → `/signin`. Two changes : (1) Playwright's `webServer` now blocks on both `http://localhost:3000` AND `http://localhost:4000/health` before tests launch — the second entry uses `reuseExistingServer: true` so it waits on the api's healthcheck without trying to start a second `pnpm dev`. (2) The (authed) layout now writes a `[(authed)/layout] redirect: <reason>` line to stderr when `MONARK_AUTH_GATE_DEBUG=1`, exposing whether the bounce came from the bootstrap gate, the `getUser`/`getSession` check, or the trusted-device check ; the env var is set on the e2e job. If the api-readiness wait closes the bounce-loop, the debug logging stays out of the test output ; if not, the next failure reveals which path actually fires and we can target the real fix.
