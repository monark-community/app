- 2026-09-08: Tooling — **changelog fragments must be named `YYYY-MM-DD-NN-<slug>.md`, and a guard now enforces it**. 22 fragments had landed with no date prefix at all, which was not agent sloppiness: [CLAUDE.md](CLAUDE.md) and [changelog.d/README.md](changelog.d/README.md) both told authors to write `<branch-slug>.md`, while all 412 historical entries used the dated form. Since `CHANGELOG.md` compiles in (date DESC, filename ASC) order, an undated name sorts by whatever its slug starts with and lands arbitrarily among that day's entries. The docs now specify one convention for every fragment, old and new, and the 22 outliers were renamed to the date their own entry declares. [tools/check-changelog.ts](tools/check-changelog.ts) enforces the name and that its date matches the entry's `- YYYY-MM-DD:` line, running in two places so a bad name never gets far: at commit time through `lint-staged` on staged `changelog.d/*.md` (the commit is rejected and the message prints the exact `git mv`, with the next free `NN` already worked out), and in CI's `repo-checks` job as the authoritative gate. The rule is a pure module in [tools/lib/changelog-naming.ts](tools/lib/changelog-naming.ts) covered by [tools/tests/changelog-naming.test.ts](tools/tests/changelog-naming.test.ts), which also asserts every committed fragment conforms so the directory cannot drift back. A repeated `NN` on one date is deliberately a warning rather than a failure: two branches cannot see each other's choice, so failing would strand every open PR the moment the second merged, and the filename still breaks the tie deterministically. Those tests needed somewhere to run — `pnpm test` is `turbo run test`, which only reaches workspace packages and `tools/` is not one — so `pnpm test:tools` ([vitest.tools.config.ts](vitest.tools.config.ts)) joins the pre-PR gate in [.claude/agentkit.config.json](.claude/agentkit.config.json) alongside `pnpm check:changelog`.
