- 2026-07-27: Automation editor — live test-run visualization + execution log. Pressing **Play** (Run now) now animates the flow: the editor polls the run ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>), `runs.getById` with a status-gated `refetchInterval`) and **reveals its steps one at a time** (~450ms each, up to the steps that have arrived) so even a run that finished in a single poll walks through step-by-step. Nodes light up by status via a `RunVizContext` the custom node reads — amber pulse for the currently-executing node, emerald for succeeded, red for failed, dimmed for skipped — and the edge into the active node glows amber (`AutomationEdge`). A docked **Execution log** panel (`RunLogPanel`) at the bottom of the canvas streams each step (status dot, node name, duration, output / error, auto-scrolled), shows the run status (Running / Succeeded / Failed / Waiting for a delay), and closes to clear the overlay. Polling keeps running while the run is `PENDING`/`RUNNING`, so a Delay's suspend→resume is reflected live. New `automation.editor` i18n (`executionLog`, `statusRunning/Succeeded/Failed`, `runWaiting`, `closeLog`), en + fr. `typecheck` (web) + `lint` + `check:i18n` green.
