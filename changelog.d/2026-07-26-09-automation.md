- 2026-07-26: Automation — expanded the built-in node library from 3 to 12, covering the communication / data / RBAC / user surfaces. **Communication** : added **Send Email** ([nodes/send-email.ts](monark/app/packages/automation/src/server/nodes/send-email.ts), raw `sendMail` to an address, distinct from the user-keyed Notification node). **Data** : **Create / Update / Delete / Find Record** ([nodes/data.ts](monark/app/packages/automation/src/server/nodes/data.ts)) against `@monark/data-models` (resolve model by key, JSON payload). **RBAC** : **Assign / Remove Role** ([nodes/rbac.ts](monark/app/packages/automation/src/server/nodes/rbac.ts), by role key, via `assignRole`/`revokeRole`). **User** : **Get User** (by id/email) + **Set User Metadata** ([nodes/user.ts](monark/app/packages/automation/src/server/nodes/user.ts)). Every privileged node re-checks that the automation's **owner** holds the underlying capability at run time (`requireOwnerPermission` in [nodes/shared.ts](monark/app/packages/automation/src/server/nodes/shared.ts) — data writes need `data-models.record-*`, role changes need `rbac.assign-role`, metadata needs `users.write-metadata-for-module-*`), so a flow can't escalate beyond its author ; a run with no owner is denied. Added `@monark/data-models` + `@monark/users` as (core-tier) deps. New integration specs prove a data-create node writes a record (admin owner passes) and that the owner re-check fails a node when the owner lacks the permission (6/6 against a testcontainer). Note: user profile / deactivate / create nodes are still blocked on `@monark/users/server` exporting no write ops (creation lives in `@monark/auth`). `typecheck` + `lint` + `check:tiers` green.
