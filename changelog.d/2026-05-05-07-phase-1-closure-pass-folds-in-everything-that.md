- 2026-05-05: Phase-1 closure pass. Folds in everything that landed since the last CHANGELOG entry without its own line ; phase-2 starts on a clean slate.
  - **Account section moved to real route segments.** `/account?tab=profile|security|notifications|danger` retired in favour of `/account/profile`, `/account/security`, `/account/notifications`, `/account/danger`. New shared layout at [account/layout.tsx](<monark/app/services/web/src/app/(authed)/account/layout.tsx>) hosts the AppBar + sidebar chrome ; per-tab pages export their section content. New client [account-sidebar.tsx](<monark/app/services/web/src/app/(authed)/account/account-sidebar.tsx>) drives off `usePathname()` instead of `?tab=` query state. Deletion-grace lockdown enforced server-side at the layout (allow-list of `/account`, `/account/profile`, `/account/danger` ; everything else redirects to `/account/danger` while in grace). Notifications inbox moved to its own top-level `/inbox` so the path didn't clash with the preferences tab. Every redirect target across the app updated to match : `(authed)/layout.tsx`, `(anon)/signin/actions.ts`, `admin/layout.tsx`, `profile-section.tsx`. Email templates (`auth/totp-{enabled,disabled}.ts`, `auth/new-device.ts`, `account/deletion-scheduled.ts`) + the `accountLink/securityLink/revokeLink` defaults in [enrich.ts](monark/app/packages/notifications/src/server/enrich.ts) now point at the new paths. **i18n** (en + fr) : new `appBar.breadcrumb.{profile, security, danger}`.
  - **Notifications + Apps + UserMenu became right-side drawers.** The bell popover and the apps launcher popover both swapped to `<Sheet>` overlays matching the user-menu pattern. The notifications drawer adds Unread/All tabs, "Mark all as read", per-row dropdown with mark-read/mark-unread/dismiss, and per-kind icons (`KeyRound` / `Laptop` / `ShieldCheck`/`Off`/`Alert` / `AtSign` / `TriangleAlert` / `CheckCircle2`). Pagination via `useInfiniteQuery`. New `notifications.markUnread` tRPC procedure. The standalone `/inbox` page deleted ; the drawer is the canonical surface now. Notification template inapp bodies rewritten to give context instead of repeating the timestamp (the relative-ago in the drawer made the date redundant). User-menu drawer added a banner-backed identity header (user's profile banner / brand-gradient fallback) with the avatar overlap pattern.
  - **Account-action forms moved to modals.** Email change, password change, and the three TOTP flows (enroll / disable / regenerate) now live in `<Dialog>` surfaces instead of inline expansions on the security page. TOTP enroll became a 2-step wizard (scan → verify) with a "Back" return path. The secret in the "Can't scan?" disclosure renders in a copy-button-equipped codeblock matching the recovery-codes view.
  - **Admin RBAC role editor moved to its own pages.** `/admin/rbac/roles/new` (create) and `/admin/rbac/roles/[id]` (edit / delete) replaced the modal editor ; the manager list (`/admin/rbac`) now has a search input, click-the-whole-card-to-navigate rows, and a chevron pointer for visual uniformity with `/admin/users` + `/admin/organizations` (those two also gained chevrons in the same pass). New `rbac.adminGetRole` tRPC procedure for the by-id lookup. The role key is no longer surfaced in either the list or the editor — derived from the name on create. Permission editor : tri-state checkboxes per category, search across keys + descriptions, auto-expand of matching categories while searching.
  - **User-detail roles trimmed.** Assignments render as flex-wrap of removable chips (color-tinted via `Role.color`, X-icon to revoke) with a dashed `+ Add new role` outline chip that opens a small assign dialog ; previously the form lived inline below a separator and pushed the page down on every visit. The sysadmin card on `/admin/rbac` dropped its CLI-instruction footer ; "Since {date}" capitalised properly.
  - **Mobile-aware breadcrumb + non-navigable hrefs.** The AppBar breadcrumb shows only the current segment on `< sm` viewports ; full chain shows on `sm+`. New `ALWAYS_NON_NAVIGABLE_HREFS` (`/admin`) + `SINGLE_TENANT_NON_NAVIGABLE_HREFS` (`/admin/organizations`) sets render those crumbs as muted spans instead of links so the user doesn't waste clicks on pure redirects. New `<RoleNameCrumb>` resolves cuids on `/admin/rbac/roles/[id]` paths.
  - **Email shell rendering fixed.** `renderString(EMAIL_SHELL, …)` was passing a stripped vars object so `{{ appName }}` / `{{ logoUrl }}` / `{{ brandPrimary }}` rendered as literals across every notification email — wordmark, logo, and footer all broken. Fix in [dispatch.ts](monark/app/packages/notifications/src/server/dispatch.ts) spreads the full `vars` into the shell render. The totp-disabled template was reshaped at the same pass to align with the `new-device` footer pattern (muted trailing paragraph at 24px top margin, no border, `#a1a1aa` 13px). Backlog has a snapshot test follow-up.
  - **Dev overlay current-org panel works in single-tenant.** Root fix at the platform layer : `getCurrentOrg` now falls back to the singleton when the session has no `active_organization_id` claim and the deploy is single-tenant. `@monark/organizations` gained `@monark/feature-flags` as a workspace dep. Multi-tenant write path is still missing — flagged in backlog.
  - **Phase-1 cleanup before phase-2.** Dropped four placeholder feature flags (`voting`, `contributions.quantification`, `referral.external-sync`, `onboarding.v2`) ; tests in [packages/feature-flags/tests/](monark/app/packages/feature-flags/tests/) refactored to assert the live flags instead. User-menu drawer cards stripped to neutral "Coming soon" placeholders (no rank labels, no achievement-square grid). Notification preferences UI trimmed to SECURITY + ACCOUNT categories ; ACTIVITY + DIGEST stay in the Prisma `NotificationCategory` enum but the prefs zod schema rejects them so phase-2 can re-enable cleanly. Inbucket SMTP env updated in [services/api/.env](monark/app/services/api/.env) + .env.example to point at port 54325 (the actual listener) instead of 54324 (web UI). **i18n** (en + fr) : dropped `account.notifications.prefs.{categories.{ACTIVITY,DIGEST}, categoryDescriptions.{ACTIVITY,DIGEST}}`, dropped `appBar.userMenu.{achievements, ranks.*}`.
