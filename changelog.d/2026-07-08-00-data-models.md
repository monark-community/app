- 2026-07-08: Data models — record + model watchers with notifications (the engine's Notifications integration). A user can follow a single record (`DataRecordWatcher`) or a whole model (`DataModelWatcher`) — migration [20260708010000](monark/app/packages/db/prisma/migrations/20260708010000_add_data_watchers/migration.sql). On any `data-models.record-{created,updated,deleted}` event, a new subscriber ([record-watch-subscriber.ts](monark/app/packages/data-models/src/server/record-watch-subscriber.ts)) fans out an in-app `data-models.record-changed` notification (registered kind, IN_APP, opt-out-able — [notification-kinds.ts](monark/app/packages/data-models/src/server/notification-kinds.ts)) to the union of the record's + the model's watchers, minus the actor and minus anyone the record's row-level access hides it from. The record-deleted event now carries `recordTitle` (the row is gone by the time subscribers run on a hard delete). New tRPC `records.setWatch` / `isWatching` + `models.setWatch` / `isWatching` (gated on read access), and Follow/Following toggles in the record detail panel + full-page editor ([watch-buttons.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/watch-buttons.tsx>)) and the model list header. `@monark/data-models` now depends on `@monark/notifications` (both core). New i18n (`data.records.watch.*`, en+fr). Integration coverage: watcher notified on change, actor excluded, model-watcher notified on create, no-access watcher excluded. Verified in the real UI (model + record follow persist across reload). Gate green (gen, tsc 17/17, eslint 17/17, unit + data-models(47) integration, tiers/modules/i18n).
