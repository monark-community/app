- 2026-07-05: Layout — page content now docks next to the sidebar instead of floating at the viewport centre. [`PageLayout`](monark/app/services/web/src/components/page-layout.tsx) previously kept its `mx-auto max-w-2xl` content centred on the whole _viewport_ while a `fixed` `w-72` rail sat in the gutter, so the content read as off-centre (a lopsided empty gap on the far side) and any full-bleed hero spilled under the rail. It now reserves each present rail's width (`xl:pl-72` / `xl:pr-72`) so the content centres in the region _between_ the rails ; pages with no rails stay viewport-centred. This fixes the reported `/account/profile` bug where the [`UserBanner`](monark/app/services/web/src/components/user-banner.tsx) hero extended under the account sidebar and its hover "edit" pen (centred on the full-viewport banner) landed left-of-centre of the visible area. The banner's viewport bleed was updated to match : below `xl` it still bleeds to the viewport, at `xl+` it spans the sidebar's right edge → viewport right edge (`w-[calc(100vw-18rem)]`, offset to start at 18rem), so the hero + pen align with the docked content. Applies to every `PageLayout` sidebar surface (account tabs + admin) ; the Data section already docked via `main`'s `xl:pl-78`. Verified with a `profile-banner-layout` screenshot fixture (content + banner centre on the region-right-of-sidebar axis, avatar aligned with the fields below). `tsc` + `eslint` green.
