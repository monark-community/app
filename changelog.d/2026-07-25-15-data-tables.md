- 2026-07-25: Data tables — bulk edit. The shared [`DataTable`](monark/app/services/web/src/components/patterns/data-table/data-table.tsx) gained opt-in multi-row selection (a leading checkbox column + header select-all, via a `selection` prop wired to TanStack row selection ; transient, never persisted with the layout — the select cell + checkbox stop click propagation so selecting never opens a row). A new [`BulkEditBar`](monark/app/services/web/src/components/patterns/bulk-edit-bar.tsx) shows a count + edit/clear bar when rows are selected and opens a **field-driven** edit dialog : pick one of the data model's editable fields (computed `formula` fields excluded), set a single value (reusing `AutoForm` for the per-type input + validation), and — when the selected rows currently hold different values for that field — confirm past an overwrite warning before applying to all. Wired into the generic records list ([records-list.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/records-list.tsx>)), so it lights up for every Data Model. Backend: new [`records.bulkUpdate`](monark/app/packages/data-models/src/server/router.ts) (`{ ids, data }`, ≤500 ids, same overlay applied per row through `updateDataRecord`'s merge+revalidate+recompute, one `record-updated` event per row) gated by a **new, separate** `data-models.record-bulk-write` permission ([permissions.ts](monark/app/packages/data-models/src/server/permissions.ts)) — required _in addition to_ per-model `record-write`, so bulk edit is grantable/revocable apart from single-record editing ; the UI hides the whole affordance when the caller lacks it. New `table.selectRow`/`selectAll` + `data.records.bulkEdit.*` i18n (en + fr) ; integration specs prove the deny-without-bulk, apply-to-all, and reject-cross-model paths. `gen` + `tsc` + `eslint` + `check:tiers`/`check:modules` + data-models integration tests green.
