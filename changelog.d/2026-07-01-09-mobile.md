- 2026-07-01: Mobile — stop wide content from blowing out the layout. The page-level safety net (`body { overflow-x: clip }`) already prevented a runaway horizontal scrollbar, but wide children (a `DataTable`, or a responsive grid missing a base `grid-cols-1`) were getting clipped instead of shrinking, because flex / grid children default to `min-width: auto`. Hardened the shared [`DataTable`](monark/app/services/web/src/components/patterns/data-table/data-table.tsx) root with `w-full min-w-0` so it always fits its parent and scrolls internally in any flex / grid context, and fixed the two responsive grids that lacked a shrinkable base column ([dev/fields gallery](<monark/app/services/web/src/app/(authed)/dev/fields/page.tsx>), [delivery-detail.tsx](<monark/app/services/web/src/app/(authed)/admin/webhooks/[id]/deliveries/[deliveryId]/delivery-detail.tsx>)) by adding `grid-cols-1` + `min-w-0`. Convention going forward : a `*:grid-cols-N` always pairs with a base `grid-cols-1`, and a flex / grid item holding wide content carries `min-w-0`. No behavior / i18n changes.
