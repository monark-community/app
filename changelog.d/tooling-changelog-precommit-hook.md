- 2026-08-17: Tooling — **`CHANGELOG.md` is regenerated by a pre-commit hook instead of pushed to `develop` by CI**, so `develop` can be branch-protected. The rebuild landed a day earlier as a workflow that committed straight to `develop` ; that meant a bot needed push access to the branch, and any ruleset gating `develop` (require-a-PR, or even require-status-checks, since no checks have run on a commit that doesn't exist yet) blocked it. GitHub Actions can't be granted ruleset bypass the way a custom app or a role can, so the automation and the protection were mutually exclusive. Now `lint-staged` runs [tools/compile-changelog.ts](tools/compile-changelog.ts) with a new `--stage` flag whenever a `changelog.d/*.md` file is committed, regenerating `CHANGELOG.md` and staging it so it travels in the same commit as the fragment that caused it ; `changelog:compile --check` joins CI's repo-checks job to catch commits made with `--no-verify` or without hooks installed, and the push workflow is deleted. The tradeoff is that two branches adding entries now both rewrite the generated file and conflict there ; resolution is `pnpm changelog:compile` plus staging the result, never a hand-merge. A custom merge driver was built to automate exactly that and then **rejected after testing**: git invokes the driver before it has placed the other branch's new fragment in the working tree, so it rebuilt from incomplete input and silently dropped an entry in a synthetic two-branch merge. `CHANGELOG.md` is marked `linguist-generated` in [.gitattributes](.gitattributes) so it collapses in review diffs.
