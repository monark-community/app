- 2026-07-05: Mobile detail panel — fixed the form still overflowing the screen ("pinch to see the whole width"). Root cause was a feedback lock in [`TableDetailLayout`](monark/app/services/web/src/components/patterns/table-detail-layout.tsx) : the mobile check used a media query, which reads the **layout viewport** (ICB) ; when the ICB blew out past 767px for even a transient on iOS, the check flipped to "desktop", switched the panel to the transform-based `slide-in-from-right` variant (`translateX(100%)`, off-screen), and that locked the layout viewport open — so the form's `@lg` container query fired and it went two-column and overflowed. Fixed by driving the mobile decision off `visualViewport.width` (the true screen width, immune to ICB blow-out) instead of a media query / `innerWidth`, and by pinning the mobile panel's `maxWidth` to that visual width so the panel and its form `@container` can never exceed the screen even if the layout viewport momentarily blows out. Verified under headless WebKit (iPhone emulation) : with the layout viewport force-blown to 1000px, the panel stays pinned at 390px and the form stays single-column. `tsc` + `eslint` + 222 tests green.
