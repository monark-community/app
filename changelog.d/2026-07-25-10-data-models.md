- 2026-07-25: Data models — the record title is a reserved convention, not an admin choice. Every model now auto-creates a required TEXT field with key `title` on creation ([createDataModel](monark/app/packages/data-models/src/server/data.ts) does it in a transaction); `DataRecord.title` is always that field's value, so the "which field backs the title" picker + "Use as title field" row action are gone from the schema builder ([model-editor.tsx](<monark/app/services/web/src/app/(authed)/admin/data-models/[id]/model-editor.tsx>)), the `title` field shows a read-only "Title" badge, and it can't be archived / deleted / retyped or made optional ([router.ts](monark/app/packages/data-models/src/server/router.ts) guards). Backend simplified: **dropped `DataModel.titleFieldId`** (column + relation + the `models.update` input field + its validation + the archive-nulling branch); `computeTitle(data)` now just reads `data.title` with no DB lookup or title-field pointer; `recomputeModelRecords` no longer special-cases a formula-backed title (a formula can't back the title anymore). Migration [20260725210000](monark/app/packages/db/prisma/migrations/20260725210000_data_models_reserved_title_field/migration.sql) backfills existing data (creates a `title` field per model lacking one; seeds `data.title` from the denormalized `DataRecord.title`) before dropping the column. Records list identifies the pinned primary column by `key === "title"` ([records-list.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/records-list.tsx>)); new shared `TITLE_FIELD_KEY` constant ([field-types.ts](monark/app/packages/data-models/src/contracts/field-types.ts)). Dropped the now-dead i18n (`editor.settings.titleField*`, `editor.fields.actions.makeTitleField`) and added `editor.fields.titleBadge`, en + fr.
