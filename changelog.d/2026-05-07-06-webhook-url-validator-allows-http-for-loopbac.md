- 2026-05-07: Webhook URL validator allows http:// for loopback / RFC 1918 hosts in development. Production stays https-only.
  - [packages/webhooks/src/server/router.ts](monark/app/packages/webhooks/src/server/router.ts) replaces `assertHttps()` with `assertSafeUrl()` that parses the URL and applies the same private-host shape the api's CORS layer already uses for cross-origin browser calls in dev (`localhost`, `127.0.0.1`, `[::1]`, `10.x`, `172.16-31.x`, `192.168.x`). Public hosts over plaintext http are always rejected ; production never accepts http regardless of host.
  - Client-side regex in [services/web/src/app/(authed)/admin/webhooks/webhook-editor.tsx](<monark/app/services/web/src/app/(authed)/admin/webhooks/webhook-editor.tsx>) loosened to `^https?://` (basic shape check) ; server is the source of truth on which combinations are allowed. The toast forwards the server error so operators see "URL must be https:// in production" or "http:// is allowed in development only for loopback or private (RFC 1918) hosts" exactly.
  - i18n urlHint in `en` + `fr` mentions the dev allowance. URL scheme rules documented in [packages/webhooks/README.md § URL scheme rules](monark/app/packages/webhooks/README.md#url-scheme-rules) and the smoke check in [docs/technical-documentation/webhook-secret-resolver.md](monark/app/docs/technical-documentation/webhook-secret-resolver.md) now uses `pnpm webhook-receiver` on `http://127.0.0.1:4123/hook`.
