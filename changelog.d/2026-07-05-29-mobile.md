- 2026-07-05: Mobile — detail panels opened via a deep link no longer blow out the viewport. `TableDetailLayout` gated its mobile-vs-desktop `Sheet` variant on the shared `useIsMobile`, which is `false` on the first render (SSR-safe) and only settles in an effect. When a panel was already open on that first render — a deep link like `/data/projects?project=<id>` (industry chip links, global search, primary-column hrefs all produce these) — it briefly rendered the desktop `side="right"` variant, whose `slide-in-from-right` transform paints off-screen on a phone and permanently expands the layout viewport (the "everything's zoomed out, pinch to see the full width" bug), and it opened as a right-side sheet instead of the full-screen modal. The admin panels dodged it only because they're opened by tapping a row _after_ mount. Fixed by resolving mobile up front with a local `usePanelIsMobile` that reads `matchMedia` in its lazy initializer ([table-detail-layout.tsx](monark/app/services/web/src/components/patterns/table-detail-layout.tsx)) — safe from hydration mismatch because the panel is a client-only portal never present in the SSR HTML, so it can't disagree with the server. Panels now render the transform-free full-screen `full` variant from the first paint ; verified headlessly that a deep-linked panel is full-width (`inset-0 w-full`, doc width == viewport) at 150ms with no hydration warning. The shared `useIsMobile` is untouched (calendar SSRs against it). `tsc` + `eslint` green.
