- 2026-07-25: Tables — empty states now explain _why_ a list is empty and offer the right next step. Before, every table's empty message keyed off the search box alone, so a too-restrictive filter (with no search) wrongly showed `No results for ""`. New shared [`TableEmptyState`](monark/app/services/web/src/components/patterns/table-empty-state.tsx) + `tableEmptyReason({ hasSearch, hasFilters })` classify the emptiness into four reasons — **no-data** (nothing created → offers the Create/Invite CTA), **no-search** (bad search → offers _Clear search_), **no-filters** (over-restrictive filters → _Clear filters_), **no-search-filters** (both → _Clear search & filters_) — each with its own icon, message, and one next-step button. Constrained-empty copy + clear-action labels come from a shared `table.empty.*` i18n namespace (en + fr) via the [`useTableEmptyLabels`](monark/app/services/web/src/lib/use-table-empty-labels.ts) hook, while the genuinely-empty title stays each screen's own "No X yet" copy. Propagated to **every** list — data-model records, admin users / roles / webhooks (+ deliveries) / organizations / data-models — reusing the filter-menu `activeFilterCount` (detect active filters) and `clearAllFilters` (the clear action) so per-screen wiring is a few lines. Pruned the now-dead per-screen `emptySearch` keys (6 × en/fr). Verified with a `table-empty-state` screenshot story (all four reasons) ; `tsc` + `eslint` + 236 web tests + `check:i18n` (en/fr parity) green.
