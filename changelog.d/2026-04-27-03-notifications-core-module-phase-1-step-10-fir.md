- 2026-04-27: Notifications core module (Phase 1 step 10) ; first cut. **Package**: new `@monark/notifications` workspace package with `/server`, `/client`, `/contracts` exports and a Phase 1 README. Registered in `modules.manifest.ts` as a core-tier module ; auto-wired into the app router via `pnpm gen:routers` and into `DomainEvent` via `pnpm gen:events`. **Schema**: `Notification` + `NotificationPreference` models + `NotificationChannel` (`IN_APP`, `EMAIL`) and `NotificationCategory` (`SECURITY`, `ACCOUNT`, `ACTIVITY`, `DIGEST`) enums under the new `// ── MODULE: notifications ──` banner in [packages/db/prisma/schema.prisma](monark/app/packages/db/prisma/schema.prisma) ; migration at [migrations/20260427150000_add_notifications](monark/app/packages/db/prisma/migrations/20260427150000_add_notifications/migration.sql). **Dispatch**: `notify(kind, recipient, data)` resolves the user's locale + per-(category, channel) prefs (force-on for SECURITY × EMAIL when `requiredEmail`), de-dupes within a 60s window keyed by `sha256(data)`, renders the kind's TS template module wrapped in the brand `EMAIL_SHELL` partial, persists a `Notification` row per channel, transports via `sendMail` (nodemailer behind `SMTP_URL`, falls back to log-only), and emits `notification.created` / `notification.delivery-failed`. Never throws ; failures land on `failedAt` + `failureReason` so triggering actions can't be rolled back by a notification problem. **Templates**: 7 Phase 1 kinds (`auth.new-device`, `auth.password-changed`, `auth.totp-enabled`, `auth.totp-disabled`, `account.email-changed`, `account.deletion-scheduled`, `account.deletion-canceled`), each with en + fr slots + html + text + inapp surfaces. Shared brand chrome in [\_partials/email-shell.ts](monark/app/packages/notifications/src/templates/_partials/email-shell.ts) reuses the orange header band, Monark wordmark, brand-orange CTA and footer from the Supabase confirmation template ; new emails are "fill in the body slot." **Subscribers**: `registerNotificationSubscribers()` listens to `trusted-device.added`, `user.password-changed`, `totp.enabled`, `totp.disabled`, `user.email-changed`, `user.deletion-requested`, `user.deletion-canceled` and forwards each to `notify()`. **Mailer relocation**: `mailer.ts` + `new-device-email.ts` moved out of `@monark/auth/server` into the notifications package ; `@monark/auth` no longer depends on `nodemailer`. The api boot now calls `registerNotificationSubscribers()` instead of `registerNewDeviceEmailListener()`. **tRPC**: `notifications` router with `unreadCount`, `list` (cursor-paginated), `markRead`, `markAllRead`, `dismiss`, plus `preferences.get` (returns resolved category × channel cells with `forced` flag), `preferences.set`, `preferences.reset`. **UI** ([services/web](monark/app/services/web)): header bell at `/account` (popover with unread badge in brand red `#EF3620`, recent 6, mark-all-read, "Open inbox" link ; polls every 60s + on focus), full inbox at [/account/notifications](monark/app/services/web/src/app/account/notifications/page.tsx) (cursor pagination, all/unread filter, per-row dismiss), and a fourth tab on `/account` (`?tab=notifications`) hosting [NotificationsSection](monark/app/services/web/src/app/account/notifications-section.tsx) — table of category × channel toggles with SECURITY × EMAIL pre-disabled and a "Reset to defaults" action.
