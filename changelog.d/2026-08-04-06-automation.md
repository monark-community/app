- 2026-08-04: Automation — added a **Data Record** trigger node so a flow can fire on records of one specific Data Model instead of every model. It stores a `dataModelKey` (the existing model picker) + `operation` (created / updated / deleted) ; on save the editor maps the operation to the real `data-models.record-<op>` bus event, so matching still uses the indexed `triggerEventType` column, and the new `eventScopeMatches` filter in [subscriber.ts](monark/app/packages/automation/src/server/subscriber.ts) applies the model filter on top — only records in the chosen model enqueue a run, while a generic Event Trigger on a record event still fires for all models (back-compatible). The trigger→event derivation, previously inlined in three spots in [automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>), is now one `triggerEventTypeForNode` helper. New node [data-record-trigger.ts](monark/app/packages/automation/src/server/nodes/data-record-trigger.ts) + `DATA_RECORD_TRIGGER_TYPE` / `dataRecordEventType` in [contracts/triggers.ts](monark/app/packages/automation/src/contracts/triggers.ts) ; the `required` model + operation are enforced by the existing graph validator, and node labels stay English registry strings (no i18n). `tsc` + `eslint` + 52 automation unit tests (incl. a new `eventScopeMatches` suite) green.
