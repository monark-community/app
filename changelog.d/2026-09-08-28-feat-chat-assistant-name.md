- 2026-09-08: Chat — the assistant's name is now **configurable per organization**, not just per deploy. `CHAT_ASSISTANT_NAME` was the only lever since 2026-08-04 ; [config.ts](packages/chat/src/server/config.ts) now resolves the name in three layers — per-org override → `CHAT_ASSISTANT_NAME` → the shipped default `Chrysa` (named for _chrysalide_) — and every consumer reads the resolved value, so the system prompt ([agent.ts](packages/chat/src/server/agent.ts)) and the web companion always agree. The override is an organization **metadata sidecar** row (`module: "chat"`, `key: "assistant-name"`) rather than a column on `Organization` : one unindexed string nobody filters or sorts on, so no migration and no core-schema change. Admins set it from the organization profile form ([organization-detail.tsx](<services/web/src/app/(authed)/admin/organizations/[id]/organization-detail.tsx>)), which now saves across two backing stores behind one dirty-gated save bar ; the field is served by a chat-owned `chat.branding.get` / `.set` pair gated on `organizations.update-settings`, and emits the new `chat.assistant-name-changed` domain event so integrations can mirror a rename. All of it sits behind the new `chat.org-branding` flag (default **off**), which gates resolution as well as the form — flipping it off reverts every org to the deploy name without clearing a stored value. Also fixes a branding leak in [chat-provider.tsx](services/web/src/components/chat/chat-provider.tsx), which hardcoded `"Chrysa"` as its in-flight fallback and so flashed the Monark brand on first paint even on a deploy that had renamed its assistant ; it now falls back to the translated generic noun. Adds `@monark/feature-flags` to the chat package's declared dependencies (it was already importing it, the only module in the repo not declaring it). `pnpm agent gate` green.
