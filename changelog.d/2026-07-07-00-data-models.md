- 2026-07-07: Data models — per-model RBAC + webhook entries are now multi-tenant-safe. The per-model permissions / event types stay globally registered (so `isKnownPermission` + grant-time validation pass, and a same-named model key across orgs correctly maps to one shared, org-enforced permission), but are marked `orgScoped` and filtered at display time: the `/admin/rbac` catalog ([index.ts](monark/app/packages/rbac/src/server/index.ts)) and the webhook picker ([router.ts](monark/app/packages/webhooks/src/server/router.ts)) only show an org the org-scoped entries a registered visibility resolver reports for it. New generic hooks — `registerOrgScopedPermissionVisibility` / `orgVisiblePermissionKeys` ([permissions.ts](monark/app/packages/rbac/src/contracts/permissions.ts)) and `registerOrgScopedEventTypeVisibility` / `orgVisibleEventTypes` ([event-registry.ts](monark/app/packages/common/src/event-registry.ts)) — keep `@monark/rbac` + `@monark/common` ignorant of `data-models`; `registerDataModelVisibilityResolvers()` ([registrations.ts](monark/app/packages/data-models/src/server/registrations.ts), wired at boot in [server.ts](monark/app/services/api/src/server.ts)) returns exactly the caller-org's live models' keys, so one org never sees another org's model keys. Closes the multi-tenant caveat noted when per-model integration first landed. New integration coverage asserts the cross-org isolation + soft-delete-hides.
