- 2026-07-05: Notifications — broke notification preferences down to per-event email opt-in, mirroring the RBAC / webhook selectors. The `/account/notifications` UI ([notification-prefs.tsx](monark/app/services/web/src/components/notification-prefs.tsx)) dropped the two-switch-per-row (in-app + email) layout for the shared [`GroupedMultiSelect`](monark/app/services/web/src/components/patterns/grouped-multi-select.tsx) in checkbox mode : one email checkbox left of each event's label + description, collapsible category groups, search, and tri-state select-all. In-app delivery is no longer user-configurable (platform-controlled), so only email-capable kinds render ; `requiredEmail` security kinds show as checked + disabled with a "required" hint (a new minimal `isItemDisabled` predicate + `monoItems` group flag on the shared component ; the two callers now pass `onToggle(kind, enabled)` with the channel hardcoded to `EMAIL`). Added four new security notification kinds, each wired to a real trigger : `auth.signed-in` (opt-in, default-off, on every `user.signed-in`), `auth.device-revoked` (single-device sign-out receipt on `trusted-device.revoked`, skipping the per-row events of a bulk sweep), `auth.recovery-code-used` (forced, on `totp.recovery-code-used`), and `auth.recovery-codes-regenerated` (forced ; a **new** `totp.recovery-codes-regenerated` domain event now emitted from [`regenerateRecoveryCodes`](monark/app/packages/auth/src/server/totp.ts) + registered for webhooks). Registry augmentation, en/fr templates, defs, and `enrich` cases land in [packages/notifications](monark/app/packages/notifications) ; the bulk-suppression flag (`bulk?: boolean` on `TrustedDeviceRevokedEvent`, set by [`revokeAllTrustedDevices`](monark/app/packages/auth/src/server/trusted-devices.ts)) keeps a "revoke all" from firing N device-revoked emails alongside the one `auth.all-devices-revoked`. i18n (kind labels + per-event `kindDescriptions`, en + fr), the notifications + auth READMEs, and `pnpm gen:events` all updated. As part of this the shared [`GroupedMultiSelect`](monark/app/services/web/src/components/patterns/grouped-multi-select.tsx) — the one selector behind all three of the RBAC role editor, the webhook subscription picker, and notification prefs — absorbed the group count-chip format as a built-in default (`"{selected} / {total}"`), so the three sections dropped their duplicated, drifting count strings (`categoryCount` / `moduleSelectionCount` / `count`) and now read identically ; a new opt-in `secondaryPrefix` slot lets a row lead its description with a marker (used here for the `Required` badge on forced rows, so the reason the checkbox is locked sits right next to it).
