- 2026-05-02: Trusted-device cards show richer device info + suppress loopback noise. `TrustedDeviceView` now ships `deviceVendor`, `deviceModel`, `deviceType` ([packages/auth/src/server/index.ts](monark/app/packages/auth/src/server/index.ts)) parsed once server-side via the existing UAParser call ; mobile UAs typically populate vendor/model (Pixel 7, Samsung A54, iPad), iOS deliberately strips iPhone generation, desktop browsers leave them null. The card ([trusted-device-card.tsx](monark/app/services/web/src/components/trusted-device-card.tsx)) renders a "Device: {vendor} {model}" row when either field is present, picks the glyph from `device.type` (smartphone / tablet / TV / wearable / laptop fallback) instead of the old UA-string sniff, and dedupes vendor-prefix repetition ("Apple iPhone" stays "iPhone").

  Country now flows from hosting-platform edge headers ([recognizeDeviceAfterAuth](monark/app/services/web/src/lib/trusted-device-cookie.ts)) — Vercel `x-vercel-ip-country`, Cloudflare `cf-ipcountry`, CloudFront `cloudfront-viewer-country`, generic `x-country-code` ; first non-empty 2-letter ISO code wins, Vercel's "XX" sentinel is treated as missing. The `recognize` mutation accepts the new `country` input ; `recognizeOrRegister` persists to the column on create AND refreshes on every recognized sign-in (treating null as "no fresh signal" rather than "clear the field" so a roaming user's location keeps up without losing the last-known country when they hit a no-geo proxy).

  Loopback IPs (`::1`, `127.0.0.1`, `::ffff:127.0.0.1`) are now stripped to null at recognize time so the DB doesn't store `::1` for every dev sign-in. The card pairs that with a `process.env.NODE_ENV !== "production"` check : when both IP and country are absent in dev, the Location row renders an italic "Local development" label instead of being silently empty. In production, missing IP/country just collapses the row.

  Dev-overlay panel and /account section both pass the new fields through. **i18n** (en + fr): new `account.trustedDevices.fields.{location, localDev, device}` + `devOverlay.trustedDevices.fields.{location, localDev, device}` keys. The legacy `fields.ip` key stays for back-compat.

  No DB migration needed — the existing `country` + IP columns are already there ; this just starts populating them. Older rows where `country` was stored as null will fill in on the user's next sign-in.
