- 2026-07-01: Calendar — responsive, touch-first mobile experience. The calendar had zero responsive handling ; on a phone the 275px sidebar and the multi-column grids overflowed and every create/move/resize gesture was mouse-only. Below Tailwind's `md` (768px), the shell now collapses to **Day view only** — Week/Month render as Day via a new `effectiveView` while the URL's `?view=` is preserved so a wide viewport restores the choice, and the view switcher is hidden ([calendar-shell.tsx](<monark/app/services/web/src/app/(authed)/calendar/calendar-shell.tsx>)). The fixed sidebar becomes a horizontal calendar-toggle strip above the grid (mini date-picker dropped ; toolbar arrows navigate) via a `hidden md:flex` aside plus an `md:hidden` chip strip in [calendar-sidebar.tsx](<monark/app/services/web/src/app/(authed)/calendar/calendar-sidebar.tsx>), with [day-view.tsx](<monark/app/services/web/src/app/(authed)/calendar/day-view.tsx>)'s shell stacking `flex-col md:flex-row`. Tapping a chip toggles its calendar's visibility ; a **long-press** (450ms, cancelled by a scroll drag) opens a bottom `Sheet` drawer exposing the desktop `…` menu's edit / delete actions (reusing the existing delete `AlertDialog` and `editCalendar` / `deleteCalendar` i18n keys). Day columns are now `min-w-[85vw] md:min-w-[300px]` ([day-column.tsx](monark/app/packages/calendar/src/client/ui/day-column.tsx), [day-columns-area.tsx](monark/app/packages/calendar/src/client/ui/day-columns-area.tsx)) so one calendar fills the phone and extras scroll horizontally. Drag-to-move / drag-to-resize migrated from mouse-only to **Pointer Events** across the shared [day-event-block.tsx](monark/app/packages/calendar/src/client/ui/day-event-block.tsx) and both [day-view.tsx](<monark/app/services/web/src/app/(authed)/calendar/day-view.tsx>) / [week-view.tsx](<monark/app/services/web/src/app/(authed)/calendar/week-view.tsx>) document listeners, so gestures work under touch as well as mouse ; draggable surfaces carry `touch-none` and the resize handle is revealed on select / coarse-pointer devices. Tap-to-create is unchanged. On mobile the calendar forms also go full-screen for better use of the viewport and no longer autofocus a field on open (which would raise the keyboard before the form is visible) : a new opt-in `mobileFullScreen` prop on the shared [dialog.tsx](monark/app/services/web/src/components/ui/dialog.tsx) drives the Edit Calendar dialog ([calendar-manage-dialog.tsx](<monark/app/services/web/src/app/(authed)/calendar/calendar-manage-dialog.tsx>)), and the Create/Edit Event form ([new-event-popover.tsx](<monark/app/services/web/src/app/(authed)/calendar/new-event-popover.tsx>)) renders as an anchored `Popover` on desktop but a full-screen `Dialog` with a single-column layout on mobile (`onOpenAutoFocus` prevented, `useIsMobile`-gated so the wrapper is chosen once without a flash). The full-screen modals are a flex column with a left-aligned title header, a scrollable top-left content area, and a pinned bottom action banner built from the shared admin [`FormActionsFooter`](monark/app/services/web/src/components/patterns/form-actions-footer.tsx) (event delete pairs it with [`ConfirmDialog`](monark/app/services/web/src/components/patterns/confirm-dialog.tsx)), so the calendar forms read like the rest of the app's create/edit surfaces. New SSR-safe [`useIsMobile`](monark/app/services/web/src/hooks/use-is-mobile.ts) hook drives the behavioral view-switch and the modal wrappers. No new i18n strings, no RBAC / schema / data changes.
