- 2026-05-08: Coverage merge infrastructure. Unblocks the per-package `coverage.thresholds` gates that have been deferred since the test push started ; before this, the unit and integration runs each overwrote `coverage/lcov.info` so Codecov saw whichever ran last and the data-layer files (which only run under integration) showed near-0%. Per-package thresholds will get flipped on in a follow-up commit once the first merged CI run gives real baselines to set the floors against.
  - **Per-run subdirectories.** Every unit `vitest.config.ts` now sets `coverage.reportsDirectory: "coverage/unit"` ; every `vitest.integration.config.ts` sets `coverage.reportsDirectory: "coverage/integration"` and an explicit `include: ["src/**/*.ts"]` so the integration run reports against the same file set as the unit run (without it, coverage-v8 would only count files actually loaded during the integration suite, which artificially deflates the number). 9 unit configs + 7 integration configs touched ; `services/web` still uses `coverage/unit/` even though it has no integration counterpart, for merge-script discovery consistency.
  - **`json` reporter added to the shared base** ([vitest.shared.ts](monark/app/vitest.shared.ts)). Lands `coverage-final.json` per run — that's what the merge script reads ; `lcov` / `text` / `html` keep doing what they did. Centralised so neither the unit nor the integration override has to think about it.
  - **`test:integration:coverage` script per package.** Mirrors `test:coverage` for the integration config — `vitest run --config vitest.integration.config.ts --coverage --passWithNoTests`. Added to all 8 packages with an integration suite (auth / users / organizations / rbac / notifications / webhooks / feature-flags / services/api). Root-level `pnpm test:integration:coverage` runs `turbo run test:integration:coverage` so packages without the script `--passWithNoTests` cleanly. New `test:integration:coverage` task in [turbo.json](monark/app/turbo.json) declares `coverage/**` as the output the cache should track.
  - **`tools/merge-coverage.ts`** ([tools/merge-coverage.ts](monark/app/tools/merge-coverage.ts)). Walks `packages/*/coverage/{unit,integration}/coverage-final.json` + `services/*/coverage/{unit,integration}/coverage-final.json`, fuses each pair via `istanbul-lib-coverage`'s `createCoverageMap()`+`merge()`, writes the merged JSON to `coverage/coverage-final.json` and regenerates `coverage/lcov.info` via `istanbul-reports`'s `lcov` reporter (with `projectRoot: pkg.absPath` so the lcov SF lines stay relative — Codecov needs that). Skips packages with neither run cleanly. Prints a per-package summary table : lines / statements / functions / branches percentages alongside which sources contributed (unit, integration, or unit+integration), so a CI log scan tells you at a glance which packages are running which suites and what the merged number looks like. New root devDeps : `istanbul-lib-coverage`, `istanbul-lib-report`, `istanbul-reports` (already transitive via `@vitest/coverage-v8`, promoted to direct so `tsx` can resolve them) + the matching `@types/istanbul-*` packages. New `coverage:merge` root script.
  - **CI wiring** ([.github/workflows/ci.yml](monark/app/.github/workflows/ci.yml)). The `verify` job's "Test (integration)" step is now "Test (integration, with coverage)" running `pnpm test:integration:coverage` ; a new "Merge coverage (unit + integration)" step runs `pnpm coverage:merge` before the Codecov upload. The Codecov upload step still points at each package's `coverage/lcov.info` — the merge script overwrites that file with the merged version, so no upload-side change was needed.
  - **Net effect.** Codecov will start reflecting real merged numbers on the next CI run instead of unit-only numbers (which were near-0% for any file whose tests live under `tests/integration/`). The per-package threshold gates can now flip on against measured baselines. The per-run JSON files stay on disk under `coverage/{unit,integration}/` for diffing or re-merging without rerunning the suite.
