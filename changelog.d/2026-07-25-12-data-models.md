- 2026-07-25: Data models — records list filters by **any field**, not just archived status. Previously the polymorphic records list ([records-list.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/records-list.tsx>)) only had the active/deleted toggle. The filter menu now lists **every** field of the model, each opening a value sub-menu whose control matches the field type — text/URL/email/long/rich-text → contains, number → exact match, boolean → an "Any / Yes / No" picker, single-select (status-like) → a checklist that matches **any of one-or-more** chosen values, date/datetime → a day picker, multi-select → a checklist (matches any chosen value). Server side, `records.list` gained a `fieldFilters` input and [`listDataRecords`](monark/app/packages/data-models/src/server/data.ts) translates each into a Prisma predicate against the JSONB `data` column (`string_contains` for text/date, `equals` for number/boolean, `equals` OR-ed for single-select "any of", `array_contains` OR-ed for multi-select), ANDed with search + row-level access ([router.ts](monark/app/packages/data-models/src/server/router.ts)). FORMULA fields are filterable by their inferred result type ; RELATION is deferred (it needs an async id→label picker the `FilterConfig` union doesn't model yet). Neutral / empty values compose out (no-op), and changing a filter resets pagination. Select / multi-select filter options render with the field's **configured badge colors** (the same colored chips the value shows in the table + form), so a status' color is a visual reminder in the menu — `FilterOption.label` is a `ReactNode`, so the option carries a `<Badge>` while `searchText` keeps it typeahead-matchable. New `data.records.filter*` i18n (en + fr). Covered by 3 new records integration specs (text/number/boolean, select/multi-select-any, AND + neutral-pruning) — the full records suite (12) passes against a real Postgres testcontainer ; `pnpm gen` + `tsc` (web + data-models) + `eslint` + `check:i18n` green.
