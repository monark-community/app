- 2026-05-03: Trusted-device card date format follows the user's app locale + real device model on UA-reduced browsers.

  **Date localisation.** [trusted-device-card.tsx](monark/app/services/web/src/components/trusted-device-card.tsx) `formatRelative` was calling `toLocaleString(undefined, …)` which uses the browser's runtime locale (often the OS default) instead of the user's app preference. Threaded the next-intl `useLocale()` value into the formatter ; now a French-preferences user signing in from an English-OS browser sees French-formatted dates. Falls back to `["<locale>", "en"]` so an unrecognised locale still resolves to something sane.

  **Real device model via User-Agent Client Hints.** Modern Chrome / Edge on Android freeze the User-Agent's device-model field to literally `K` for privacy reasons (UA reduction) ; that's why the card displayed `Device: K` on a Pixel 7. Fix routes through three layers :
  - [middleware.ts](monark/app/services/web/src/middleware.ts) sends `Accept-CH: Sec-CH-UA-Model, Sec-CH-UA-Platform-Version, Sec-CH-UA-Full-Version-List` + `Critical-CH` + `Permissions-Policy: ch-ua-model=(self), …` so participating browsers start sending the real values on subsequent requests.
  - [trusted-device-cookie.ts](monark/app/services/web/src/lib/trusted-device-cookie.ts) reads the hints via `readClientHints()`, strips the wrapping quotes the spec mandates, passes them through the `auth.trustedDevices.recognize` mutation as a typed `clientHints` field.
  - New [`TrustedDevice.clientHints` JSON column](monark/app/packages/db/prisma/migrations/20260503100000_add_trusted_device_client_hints/migration.sql) persists `{ model?, platformVersion?, fullVersionList? }`. `recognizeOrRegister` writes on create + refreshes on every recognized sign-in (treating null as "no fresh signal" so a browser that stops sending hints doesn't wipe the model we already learned). [`toView`](monark/app/packages/auth/src/server/index.ts) now prefers `clientHints.model` over `parsed.device.model` and explicitly treats the literal `"K"` (the UA-reduction sentinel) as missing so we don't accidentally show that placeholder when no hints came through. Falls back to ua-parser-js on browsers that don't implement UA-CH (Firefox, Safari).

  **Apply the migration locally** : `pnpm --filter @monark/db db:migrate:dev --name add_trusted_device_client_hints`. Existing rows have `clientHints = null` and will populate on the user's next sign-in.
