- 2026-05-03: Forgot-password flow now requires TOTP for enrolled users — closes the "email compromise == full account takeover" gap. Previously the recovery-link path bypassed TOTP entirely : an attacker who got into the user's inbox (SIM swap → carrier reset → SMS code → email access) could reset the password without ever proving the second factor, undoing the entire purpose of having 2FA on the account. New gate in [`resetPasswordAction`](monark/app/services/web/src/app/auth/reset-password/actions.ts) reads `auth.totp.status` ; non-enrolled users skip the gate, enrolled users either supply a code or get the new `totpRequired` error code so the form can prompt for one. UI side [reset-password-form.tsx](monark/app/services/web/src/app/auth/reset-password/reset-password-form.tsx) routes through the same [`<TotpConfirmDialog>`](monark/app/services/web/src/components/totp-confirm-dialog.tsx) component the in-account password change uses (`scope="passwordChange"`) so the look + retry-on-error UX is identical. Lost-authenticator users still recover via the recovery-code path on `/signin/totp` ; users who lost both go through the out-of-band support path documented in the new [docs/technical-documentation/account-recovery.md](monark/app/docs/technical-documentation/account-recovery.md). **i18n** (en + fr) : new `auth.resetPassword.errors.{totpRequired, invalidTotpCode}`. The dialog itself reuses `account.totp.dialog.passwordChange.*` strings.
