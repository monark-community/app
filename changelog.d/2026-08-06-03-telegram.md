- 2026-08-06: Telegram — **new extended module `@monark/telegram`: Telegram trigger events + action nodes for automations** (an _automation integration_, `integrates: "@monark/automation"`; flag-gated `telegram.enabled`, default off). The third integration on `@monark/integration-kit`, and the one that exercises the **trigger** path a different way than GitHub: Telegram authenticates its inbound webhook with a **shared secret echoed in a header** (`X-Telegram-Bot-Api-Secret-Token`), not an HMAC over the body — so the kit gained `constantTimeEquals` and `defineInboundWebhook`'s `verify` callback slots it in unchanged. **Triggers:** connect calls Telegram's `setWebhook`, Telegram POSTs updates to `POST /hooks/telegram/:org` ([server.ts](monark/app/services/api/src/server.ts)), and the handler ([webhook.ts](monark/app/packages/telegram/src/server/webhook.ts)) verifies the header, maps a `message` update, and `emit()`s one of two `telegram.*` events ([events.ts](monark/app/packages/telegram/src/contracts/events.ts)) — `message-received` (plain text) and `command` (a `/command`, parsed to `{ command, args }` with the `@botname` suffix stripped). They join the `DomainEvent` union + register with `{{ trigger.* }}` field metadata ([event-types.ts](monark/app/packages/telegram/src/server/event-types.ts)). **Actions:** five nodes under the `telegram` namespace ([nodes/](monark/app/packages/telegram/src/server/nodes)) — send / edit / delete message, send photo, get chat. **Where it diverged from the kit:** Telegram's Bot API puts the token in the URL _path_ (no `Authorization` header) and wraps every response in a `{ ok, result, description }` envelope, so it doesn't fit `createRestClient` — [client.ts](monark/app/packages/telegram/src/server/client.ts) calls `safeFetch` directly (unwrapping `result`, surfacing `description` on error) while still reusing the kit's `pickString` / `pickNumber` + webhook helpers (the kit is a toolbox, not a frame). **Connection:** one canonical bot token per org (unlike GitHub / Discord's per-node token secret) — a flag-gated `/telegram` settings page ([telegram-settings.tsx](<monark/app/services/web/src/app/(authed)/telegram/telegram-settings.tsx>)) pastes the BotFather token and connects, and a **bespoke** `telegram.connection.{status,connect,disconnect}` router ([router.ts](monark/app/packages/telegram/src/server/router.ts), gated on `telegram.manage`) stores the token, mints the webhook secret, and registers/deregisters the webhook with Telegram in one call (so it doesn't use `makeConnectionSecretRouter`); nodes read the connected token directly (`ctx.getSecret`), no token field. Plus a `PRIMARY_NAV` entry (paper-plane `Send` icon; lucide has no brand Telegram glyph). No new tables (two `@monark/secrets` entries).
