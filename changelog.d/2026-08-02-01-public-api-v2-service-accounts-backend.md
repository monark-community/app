- 2026-08-02: Public API v2 (service-accounts backend) — org-owned **machine principals** whose keys act as the account, not a person ([public-api-service-accounts.md](monark/app/docs/features-planning/phase-3/public-api-service-accounts.md)). A service account is a **flagged `User` row** — new `User.kind` enum (`HUMAN` default | `SERVICE`) + `User.createdBy`, migration `20260802140000_add_user_kind` — so it flows through RBAC, memberships, `createdBy`, and events with zero polymorphic surgery ; the `ApiKey` model is unchanged (`ownerUserId` points at the machine row). New admin-gated `apiKeys.serviceAccounts` sub-router ([service-accounts.ts](monark/app/packages/api-keys/src/server/service-accounts.ts)) : `create` (mints a `svc_…`-id machine user + a membership + granted roles), `list`, `setRoles`, `disable`, `delete`, and nested `keys.{list,create,revoke}` — all behind a new `api-keys.manage-service-accounts` permission and the new `public-api.service-accounts` flag (off by default, independent of the v1 user-key surface so v2 ships dark). The **load-bearing safety work is the guards** that keep a machine row out of every human-only path : notification/email dispatch short-circuits on `kind = SERVICE` ([dispatch.ts](monark/app/packages/notifications/src/server/dispatch.ts)), and the admin Users list + every assignee/member picker (users, automation, kanban, calendar) filter `kind = HUMAN`. `authenticateApiKey` now also rejects a key whose owner is disabled/deleted (so disabling a service account instantly kills its keys — and this retroactively hardens v1 user keys too). New machine ids are minted with a `svc_` prefix (never a valid Supabase auth subject) and a reserved `@service.invalid` email. 6 new integration tests (create→machine-user shape, list, mint→**authenticate as the account**, disable→keys die, delete→cascade, flag gate) ; api-keys 14 integration + full unit suite + `typecheck` (23/23) + `check:tiers`/`check:modules`/`check:i18n` all green. The `/admin/service-accounts` UI is the remaining v2 increment.
