- 2026-08-09: **`@monark/achievements` — configurable, event-driven achievements (new extended module).** An admin defines badges and the _conditions_ that hand them out ; the engine watches the platform's domain-event bus and awards a user when their conditions are met, fully integrated with every core + extended module. **How it integrates**: a condition (`AchievementRule`) names any registered event type — the rule editor reads the **live event-type registry** ([router `eventTypes`](monark/app/packages/achievements/src/server/router.ts) → `listEventTypesByModule` + `eventFieldsFor`), so kanban `card-created`, data-models `record-created`, calendar, chat, … are all selectable with no per-module wiring — plus a `threshold`, a `subjectField` (which payload field names the recipient, default the `actorId` convention ; an array field like `assigneeIds` credits many), and an optional `match` (payload equality filters). **Durable awarding** (outbox + worker, mirroring automation): the wildcard [subscriber](monark/app/packages/achievements/src/server/subscriber.ts) persists a matching event to `AchievementOutbox` (cheap, never blocks the emitter) ; the [worker](monark/app/packages/achievements/src/server/worker.ts) (`startAchievementsWorker` / `achievementsTick`) claims due rows via a leased status-guarded update, increments `AchievementProgress` (upsert on unique `(ruleId, userId)`), and on crossing the threshold creates an `AchievementAward` (unique `(achievementId, userId)` → **awarded once**), emits `achievements.awarded`, and notifies the user — so a restart never drops a count, and SERVICE principals never earn. The award event sets `actorId = userId`, making achievements **chainable** ("earn 5 achievements") and loop-safe via the unique constraint. Pure [matcher](monark/app/packages/achievements/src/contracts/matching.ts) (type/payload/subject) is unit-tested in isolation. **Big-5**: RBAC (`achievements.manage` / `view`), event (`achievements.awarded`), notifications (earned kind, en+fr), webhooks (free), flag (`achievements.enabled`, default off). Schema: 5 models in a new [fragment](monark/app/packages/achievements/prisma/achievements.prisma), migration `20260809010000_add_achievements` ; cascade flows through `Achievement → Organization`, `userId`s are soft refs. **Web**: `/admin/achievements` (CRUD achievements + conditions, with event-type / subject / match-field pickers driven by the live registry) and a user **`/achievements`** gallery (earned badges + progress bars + locked catalog), each behind the flag ; primary-nav + admin-tab entries (flag-gated). Boot-wired in [server.ts](monark/app/services/api/src/server.ts). Tests: 6 matcher unit + 4 end-to-end integration (threshold → award once, `@`-style payload match gating, SERVICE-user skip, subscriber enqueue gating) against a real testcontainer ; README + dev doc. `pnpm gen` + typecheck (achievements/api/web) + eslint + `check:i18n` (2242 keys) + `check:tiers` / `check:modules` (24 modules) all green.
