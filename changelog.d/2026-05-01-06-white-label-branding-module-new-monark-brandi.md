- 2026-05-01: White-label branding module. New [`@monark/branding`](monark/app/packages/branding/) (tier=core) is the single source of truth for product identity ; downstream teams retarget the starter to a new product by editing one TS module (or per-deployment via `BRANDING_*` / `NEXT_PUBLIC_BRANDING_*` env overrides) and the change propagates to every surface that previously hardcoded "Monark". Fields: `appName`, `tagline`, `supportEmail`, `totpIssuer`, `fromEmail`, `appUrl`, `brandPrimary`, `brandAccent`, `logoSrc`. Wired into: TOTP authenticator-app label ([totp.ts](monark/app/packages/auth/src/server/totp.ts) reads `BRANDING.totpIssuer`), SMTP envelope fallback ([transport/email.ts](monark/app/packages/notifications/src/server/transport/email.ts) reads `BRANDING.fromEmail`), email shell + every email template ([\_partials/email-shell.ts](monark/app/packages/notifications/src/templates/_partials/email-shell.ts) + every `{en,fr}` body uses `{{ appName }}` + `{{ brandPrimary }}` interpolated through `enrichVars`), i18n catalogs (every literal "Monark" replaced with `{appName}` placeholder ; [i18n/request.ts](monark/app/services/web/src/i18n/request.ts) injects `defaultTranslationValues: { appName, supportEmail }` so call sites don't need to thread the value), `<BrandLogo>` (renamed from `MonarkLogo` ; renders `BRANDING.logoSrc` + `alt={BRANDING.appName}`), and the NProgress bar (CSS now reads `var(--brand-primary)` + `var(--brand-accent)` from inline-style custom properties on `<html>` set in the root layout). Module package + README + workspace registration in `modules.manifest.ts`.
