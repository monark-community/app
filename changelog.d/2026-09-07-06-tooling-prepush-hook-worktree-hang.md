- 2026-09-07: Tooling: **fixed the `pre-push` hook hanging forever in a git worktree**, which silently blocked the one workflow [CLAUDE.md](CLAUDE.md) mandates. Git sets `GIT_DIR` (to `<main>/.git/worktrees/<name>`) when it runs a hook ; `pnpm lint` shells out to `turbo`, which spawns ~20 `git` child processes for its cache fingerprinting, and those children inherited `GIT_DIR` and blocked indefinitely. The symptom was a `git push` that never returned, with `turbo` sitting at ~3s CPU and a fan of idle `git` processes behind it ; three abandoned process clusters from separate sessions were found on one machine in a single day. Measured in a linked worktree: with `GIT_DIR` inherited the hook never completes (killed at 90s+, and observed hung past 10 minutes) ; with it unset the same lint is **1.8s, 34/34 tasks green**. [package.json](package.json)'s `simple-git-hooks.pre-push` now runs `env -u GIT_DIR -u GIT_WORK_TREE -u GIT_INDEX_FILE -u GIT_PREFIX pnpm lint`, so the gate still runs in full ; it just runs against the worktree instead of the hook's git environment. Note the hook file itself lives in the **main** checkout's `.git/hooks` and is shared by every worktree, and `simple-git-hooks` cannot write it from a linked worktree (`.git` there is a file, not a directory), so this takes effect after a `pnpm install` (or `pnpm prepare`) in the main checkout.
