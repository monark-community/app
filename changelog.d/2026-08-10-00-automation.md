- 2026-08-10: Automation — **For Each loops** (iterate a list, the engine's first control-flow structure beyond branching). A new `automation.for-each` node ([for-each.ts](monark/app/packages/automation/src/server/nodes/for-each.ts)) with two outputs — `each` (the loop **body**) and `done` (after) — resolves its `items` config to an array and runs the body sub-graph **once per item**, exposing the current element to the body as `{{ steps.<foreach>.item }}` / `.index` / `.count`; after the loop it continues on `done` with `{ items, count, results }`. Because a node can't run other nodes, this is **engine-level** ([engine.ts](monark/app/packages/automation/src/server/engine.ts)): `executionOrder` now computes each For-Each's body (the sub-graph reachable from `each` minus anything reachable from `done`) and **excludes body nodes from the top-level walk**; `executeGraph` runs the body internally per item with the same active-handle branch-gating as the main flow (a Condition inside a loop works), recording a run step per body-node-per-iteration (the run-step model has no per-node uniqueness, so repeats are fine). Refactored the per-step log buffer + control-adjacency/topo helpers out for reuse; all existing behavior (durable Delay suspend/resume, branch pruning, `{{ vars }}`, error-output) is unchanged. v1 limits, enforced at run time: no Delay/suspend inside a body (a body that suspends fails with a clear error), no nested For-Each, list capped at 1000; an uncaught body failure fails the whole loop (retry re-runs it from the first item). The editor needs no special work — it renders the two output handles + the `item`/`index`/`results` variables generically from the descriptor (`Repeat` icon added). Tests: a new `executionOrder` unit spec (body nodes excluded from the top-level order) + a full integration spec (body runs once per item in order with `item`/`index` in scope, the `done` branch runs after with `count`); automation **58 unit + 30 integration** green (incl. the untouched Delay/Condition/resume suites), `tsc` (automation + web) + `lint` clean. Follow-ups noted in the [README](monark/app/packages/automation/README.md): a save-time validator for the body limits (the graph validator is descriptor-driven, so it doesn't compute loop topology yet), and suspend-inside-loop.
