- 2026-05-04: Admin user management — read-only foundation (slice 2 of the admin view). Two new admin-gated tRPC procedures on the users router : `users.adminListUsers` (cursor-paginated list with case-insensitive email/displayName search, filters out already-anonymized `@monark.invalid` rows by default) and `users.adminGetUser` (single user + full role-assignment list across every org). Both gated by a new in-router `requireAdmin(ctx.userId)` helper that calls `adminAssignmentSummary` from `@monark/rbac/server` ; `@monark/users` now has `@monark/rbac` in its workspace deps. Rbac side added `getAllAssignments(userId)` + underlying `findAllActiveAssignments` since the existing `getUserRoles` only returns role names without org context, and the admin detail surface needs both. UI : [/admin/users](<monark/app/services/web/src/app/(authed)/admin/users/page.tsx>) renders a debounced search box + clickable list with avatar, name/email, and "Pending deletion" / "Disabled" badges (tRPC v5 `placeholderData: keepPreviousData` so rows don't blank out mid-typing) ; [/admin/users/[id]](<monark/app/services/web/src/app/(authed)/admin/users/[id]/page.tsx>) shows identity card, basic fields, and the role assignment list. Read-only for now ; profile edits + admin-initiated deletion ship in slice 3. **i18n** (en + fr) : `admin.users.{title, subtitle, searchLabel, searchPlaceholder, empty, emptySearch, loading, loadMore, badges.*, detail.*}`.
