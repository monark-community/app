- 2026-08-17: Tooling — **the changelog workflow now pushes as a GitHub App**, so `develop` can be branch-protected without breaking it. Rebuilding `CHANGELOG.md` on `develop` requires a bot with push access to that branch, and a protected branch only accepts pushes from an actor on the ruleset's bypass list — which accepts Apps but **not** GitHub Actions itself, so the built-in `GITHUB_TOKEN` can never be granted the exception. [changelog-compile.yml](.github/workflows/changelog-compile.yml) now mints an installation token with `actions/create-github-app-token` and uses it for both checkout and push, dropping `GITHUB_TOKEN` permissions to `{}` entirely. This keeps the property that matters: feature branches never touch the generated file, so they never conflict on it. The alternative considered and rejected was regenerating client-side in a pre-commit hook, which also frees `develop` but makes every branch rewrite `CHANGELOG.md` — with several agents in flight that conflicts on essentially every PR, trading a one-time setup for a permanent per-PR tax. A merge driver to auto-resolve those conflicts was prototyped and abandoned when testing showed git invokes it before the other branch's new fragment is in the working tree, so it rebuilt from incomplete input and silently dropped an entry. `CHANGELOG.md` is also marked `linguist-generated` in [.gitattributes](.gitattributes) so it collapses in review diffs.
