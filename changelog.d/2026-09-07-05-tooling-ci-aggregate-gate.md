- 2026-09-07: Tooling — **`ci-ok` is now the single required status check**, replacing the six per-job contexts branch protection used to require. A required context is matched by name against the checks a run actually reported, so a pull request whose branch predates a newly added job never reports it and GitHub waits forever on a check no run will ever produce. That is what stranded the entire Dependabot backlog when `migration-drift` was added on 2026-08-04: every visible check green, `mergeable_state: blocked`, no route out but rebasing each open PR. [.github/workflows/ci.yml](.github/workflows/ci.yml) now ends with a `ci-ok` job that `needs:` every leg (`lint-typecheck`, `repo-checks`, `migration-drift`, `unit-tests`, `integration-tests`, `coverage-upload`), runs under `if: always()` so it reports even when an upstream leg failed or was skipped, and fails unless every dependency's result is exactly `success` ; `failure`, `cancelled` and `skipped` all block the merge. With one stable context, adding, renaming, splitting or removing a leg is a pure edit to the workflow and in-flight PRs pick it up on their next run instead of being stranded. The rule is recorded in [CLAUDE.md](CLAUDE.md) alongside the pre-PR gate: new legs go in `ci-ok`'s `needs:` list, never into the ruleset.
