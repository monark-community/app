- 2026-08-09: `PageHeader` / `SectionShell` — closed out the mobile detail-bar de-duplication (previous entry) with two follow-up fixes to the leftover gap it left behind. (1) Every spacing wrapper in `PageHeader` switched from `space-y-*` to `flex flex-col gap-*` : Tailwind's `space-y` sibling-margin trick only checks the HTML `hidden` _attribute_, not a `hidden` _class_ (`display: none`) or `sr-only`'s `position: absolute`, so the now-invisible `<h1>` and the (also newly conditional) bottom `<Separator>` were still getting phantom margin around them ; `gap` correctly excludes out-of-flow/`display:none` children, so it collapses to zero automatically. (2) The `<Separator>` itself is now also hidden below `xl` whenever `backHref` is set, since the chrome detail bar's own `border-b` already divides the header from the content — a second rule right after an invisible title was just a stray line floating in dead space. (3) `SectionShell`'s `<main>` drops its top padding entirely (`pt-0`) on mobile specifically when a detail bar is registered (`xl:pt-8` unconditionally, and every other page keeps the full `pt-8`) — the detail bar already supplies its own padding + border as breathing room, and the collapsed `PageHeader`'s `space-y-6` gap to the first section is enough on its own, matching the exact rhythm every other section-to-section gap on the page already uses rather than introducing a second, different-sized gap. Net effect on the model editor (the page in the reported screenshot) : the dead-space-plus-stray-divider gap between the chrome and the first section is gone, and the first section now sits flush against the chrome at the same ~24px spacing as every other section boundary on the page. `tsc` + `eslint` + 279 web tests green ; verified with Playwright (before/after gap measurements on the reported page, desktop and no-detail-bar pages confirmed unaffected).
