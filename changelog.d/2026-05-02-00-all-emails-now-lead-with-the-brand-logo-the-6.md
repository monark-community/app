- 2026-05-02: All emails now lead with the brand logo + the 6-digit OTP block is centred. Three things landed :

  **Logo at the top.** [EMAIL_SHELL](monark/app/packages/notifications/src/templates/_partials/email-shell.ts) renders a 40×40 `<img src="{{ logoUrl }}">` above the wordmark, where `logoUrl` is composed in [enrichVars](monark/app/packages/notifications/src/server/enrich.ts) as `${appUrl}${BRANDING.logoSrc}` so each request hits a URL the recipient's mail client can actually fetch (works in dev with the Next-served `/monark-logo.svg`, works in prod with the public domain). Wordmark stays directly below the logo so brand identity is still readable when an image-blocking client (Outlook desktop, some Gmail) suppresses the `<img>`. Same logo + wordmark layout in the three Supabase-rendered templates ([confirmation.html](monark/app/supabase/templates/confirmation.html), [recovery.html](monark/app/supabase/templates/recovery.html), [email-change.html](monark/app/supabase/templates/email-change.html)) using `{{ .SiteURL }}/monark-logo.svg` for the same auto-tracking behaviour without needing access to the branding module.

  **6-digit OTP block centred.** Both the prompt label and the codeblock `<td>` get `align="center"` in all three Supabase templates (signup confirm + recovery + email change) ; previously left-aligned which read as visually orphaned next to the centred CTA button above. The mono token + `letter-spacing:0.3em` styling stays.

  **White-label friendliness audit.** Notification templates already use `{{ appName }}` + `{{ brandPrimary }}` for every brand-coloured surface (CTA buttons, header bar, wordmark) ; remaining literal hex codes (`#18181b`, `#3f3f46`, `#a1a1aa`, `#e4e4e7`, `#f4f4f5`) are the standard zinc-neutral ramp every product looks fine in, deliberately left as literals because email clients have spotty CSS-variable support. The three Supabase templates DO still hardcode `Monark` + `#F0870C` in multiple places — Supabase renders templates server-side and can't read `@monark/branding` at render time, so the [white-label retargeting checklist in `packages/branding/README.md`](monark/app/packages/branding/README.md) now explicitly calls these out as "edit by hand when retargeting" alongside the canonical brand-config edit.
