- 2026-04-27: API request logging cleaned up + secured. **`@monark/common` logger** ([packages/common/src/log.ts](monark/app/packages/common/src/log.ts)) now wraps pino with a `redact` allow-list (`req.headers.authorization`, `req.headers.cookie`, `req.headers['set-cookie']`, `req.headers['x-supabase-auth']`, `req.headers['x-api-key']`, `req.headers['x-csrf-token']`, `req.headers['proxy-authorization']`, plus payload-side `*.password`, `*.token`, `*.accessToken`, `*.refreshToken`, `*.access_token`, `*.refresh_token`, `*.tokenHash`, `*.secret`, `*.secretCipher`, `*.cookieValue`, `*.cookieHash`) ; values are replaced with `[REDACTED]` before any line is emitted. In dev (NODE_ENV != production AND stdout is a TTY) the logger now uses `pino-pretty` for coloured one-liners (level-coloured, ms-precision time, hostname/pid/service hidden) ; prod and CI / piped stdout still emit machine-parseable JSON. **API request logger** ([services/api/src/lib/http-logger.ts](monark/app/services/api/src/lib/http-logger.ts), new) replaces the bare `pinoHttp({ logger })` call ; one concise line per request (`POST /trpc/users.me 200 23ms`) at a status-coded log level (info 2xx/3xx, warn 4xx, error 5xx), so pino-pretty's level coloring lights up failures automatically. Bodies + full headers are no longer in the structured payload at all ; only `id`, `method`, `url`, `statusCode`, `responseTime` are kept. **Query strings stripped** before logging — tRPC GET queries encode their input as `?input=…`, which can carry call-time values like `cookieValue` (trusted-device lookup) ; we now log the path only, so the cookie hash never lands in any sink. **`/health` muted** to keep container probes / uptime checks from drowning real traffic. `x-request-id` honoured if the upstream sets it, otherwise a UUID. **Next config**: `pino` and `pino-pretty` added to `serverExternalPackages` in [next.config.ts](monark/app/services/web/next.config.ts) so the worker-thread transport (resolved via `require.resolve`) doesn't get statically bundled by webpack. `pino-http` is no longer imported directly from `services/api/src/server.ts` ; the wrapper module owns all pino-http config.
