- 2026-05-08: Seeded e2e test users on CI. The six remaining gated specs (account-deletion, password-change, signin-happy-path, admin-rbac-create-role, admin-users-invite, admin-webhooks) graduate from "skipped" to "executed" on every push.
  - **New `tools/seed-e2e-users.ts`** ([tools/seed-e2e-users.ts](monark/app/tools/seed-e2e-users.ts)). Provisions `e2e-user@monark.test` (regular) + `e2e-admin@monark.test` (built-in ADMIN scoped to the singleton org). Each pass : (1) `auth.admin.createUser` with `email_confirm: true` so the user can sign in without bouncing through verification ; (2) Prisma `User.upsert` keyed on the auth UUID so the row landings line up with everything that joins on `User.id` ; (3) for the admin user, `assignRole` against the `role_admin_builtin` row scoped to the singleton org. Idempotent at every layer — re-running on a healthy install is a no-op (existing auth user gets a password refresh ; existing User row gets the same upsert ; existing role assignment short-circuits via `alreadyActive`). Bootstraps the singleton org along the way so the ADMIN grant has somewhere to scope to ; the api process would do this at boot anyway, but Playwright doesn't start the api until after the seed step.
  - **CI workflow** ([.github/workflows/ci.yml](monark/app/.github/workflows/ci.yml)). New "Seed e2e test users" step in the `e2e` job, between `db:migrate` and `Install Playwright browsers`. The seed credentials live on the job-level `env` block — deterministic test passwords (the runner only listens on localhost and the stack is torn down at job end) strong enough to clear the password-rule validator.
  - **Net effect.** With this + the prior `E2E_FULL_STACK=1` + `INBUCKET_URL` flip, every gated e2e spec now actually runs : signup-confirm + forgot-password (no-seed flows) and the six seeded-user specs. Real regression in any of those — admin role grant via the UI, password-change with TOTP, account-deletion grace lockdown, webhook end-to-end delivery, etc. — fails the build instead of leaking to staging.
