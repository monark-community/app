- 2026-08-03: Query UI — **chip / token query editor (MonarkQL).** A tree-backed editor that renders each predicate as a removable **chip** whose value resolves to a human label — `Assignee: Ada Lovelace, Grace Hopper`, `Status: Active`, `Priority ≥ High` — instead of the raw ids the text bar showed (`assignee:<userId>`, `status:<columnId>`), and where the operator is **picked from a menu** ("is any of", "at least", …) so the hard-to-type comparison symbols (`>= <=`) are never typed. New shared [query-chip-bar.tsx](monark/app/services/web/src/components/query/query-chip-bar.tsx) — a **drop-in for `QueryBar`** (identical props ; it reads the same controlled `text` the parent owns, so saved views + deep links keep working). It chips a flat AND of leaves (the common shape) via the public `parseQuery`/`printQuery` round-trip ; an OR / nested / negated-text query it can't represent falls back to the embedded text bar, also reachable any time via the "edit as text" toggle. Value → label resolution dispatches by `FilterableKind` : fixed-set fields (select / multiSelect / orderedSelect) resolve id→name synchronously through `QueryFieldMeta.options`, `@variables` show their token, dates format, everything else is literal (relation async chips are a noted follow-up — relations aren't in the query language yet). The add/edit popover drives its value control off the operator's arity + the field kind (single-select / `MultiSelect` / `DatePicker` / number-or-text input), and offers `@me` for user-valued fields ; operator + chip strings come from the shared `query.*` i18n namespace (added `query.chip.*`, en + fr).
