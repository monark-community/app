- 2026-05-08: CI wall-time pass. Auto-CI runs were sitting at ~28 min per push ; trimmed to an estimated ~3:30–4 min by separating concerns and parallelising the verify gate.
  - **Playwright e2e moved to manual-trigger only** ([.github/workflows/e2e.yml](monark/app/.github/workflows/e2e.yml), [ci.yml](monark/app/.github/workflows/ci.yml)). The full e2e suite (browser install + `supabase start` + the suite itself) costs ~20 min on every push for what's primarily an auth / admin regression net ; the integration suites in the verify gate already cover every data-layer + tRPC contract surface. New workflow file under `workflow_dispatch` only — runs from Actions → E2E → Run workflow when an auth / admin PR needs the regression check. Browser install also dropped from `chromium firefox webkit` → `chromium` (the playwright config only runs Chromium ; pulling the other two with `--with-deps` was costing ~5 min for nothing). Saves ~21 min wall time off the auto-CI path.
  - **Verify gate split into 4 parallel jobs** ([ci.yml](monark/app/.github/workflows/ci.yml)). Was a single sequential job running lint → typecheck → unit → integration → merge → codecov. Now : `lint-typecheck`, `repo-checks` (codegen drift + module-tier rules), `unit-tests`, and `integration-tests` run in parallel ; a final `coverage-upload` job downloads the unit + integration artifacts, fuses them via the merge script, and uploads to Codecov. Wall time = `max(lint-typecheck, unit-tests, integration-tests, repo-checks)` + the upload job, instead of their sum. The integration leg dominates at ~3 min ; everything else clears in under 2 min, so the verify gate now closes in ~3:30 vs the old ~6 min. Coverage artifacts upload at the end of each test job and the merge job downloads both into the per-package `coverage/{unit, integration}/` shape that `tools/merge-coverage.ts` already expects, so no merge-script changes needed. Saves ~2:30 wall time off the verify path.
  - **Net.** Auto-CI on push / PR : ~28 min → ~3:30–4 min. The e2e workflow stays one click away in the Actions tab when needed, and devs run `pnpm test:e2e` locally before touching auth or admin flows. Integration coverage continues to run on every push so the threshold floors stay enforced.
