- 2026-07-05: Feature flags — fixed the dev-overlay panel showing no flags, and made it session-scoped. The panel computed its key list from a client-side `listFlagKeys()` ([feature-flags.tsx](monark/app/services/web/src/components/dev-overlay/panels/feature-flags.tsx)), but the flag registry is populated only by `registerFlags(...)` at api boot (server-side), so in the browser it was always empty — the panel queried `getMany({ keys: [] })` and `getFlags` short-circuits an empty list to `{}`, rendering nothing. Added an auth-gated [`featureFlags.getAllForSession`](monark/app/packages/feature-flags/src/server/index.ts) procedure that resolves _every_ registered flag at the caller's own session scope (`userId` + `activeOrganizationId`, derived from `ctx`, never trusted from input) and returns the resolved map ; the panel now derives its keys from that response and shows flags as they actually resolve for the logged-in user, rather than the previous empty-scope defaults (which the `/admin/feature-flags` page already covers). Updated the panel's scope note + added an `empty` string (en + fr) ; `pnpm gen:routers` re-run. `tsc` + `eslint` + feature-flags (21) + web (222) tests green.
