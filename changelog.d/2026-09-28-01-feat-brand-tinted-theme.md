- 2026-09-28: Branding / theming — brand-tinted surfaces derived from the primary color, with a per-org surface tint. Backgrounds, cards, muted surfaces, borders, inputs and text in [`globals.css`](services/web/src/app/globals.css) are no longer fixed zinc greys: each is computed from `--primary` with CSS relative color syntax, keeping its own lightness (so contrast holds for any brand) while taking the brand's hue and a small share of its chroma, so an orange brand gets warm cream and espresso surfaces and a blue brand cool ones. The strength is a multiplier, `--surface-tint` (0 neutral, 1 default, up to 2): set per deployment with the new `BRANDING_SURFACE_TINT` field in [`@monark/branding`](packages/branding/src/index.ts), and per organization with the new `Organization.surfaceTint` column ([migration](packages/db/prisma/migrations/20260928120000_add_organization_surface_tint/migration.sql)), which wins the same way `primaryColor` wins over `BRANDING_PRIMARY`. The organization page gets a tint slider next to the primary color; unsaved color and tint edits now live-preview across the whole app through [`useBrandPreview`](services/web/src/lib/brand-preview.ts) (reverted on cancel or leaving), and saving a brand change reloads so the server-rendered theme matches. `organizations.adminUpdate` accepts `surfaceTint`, `bootstrapStatus` returns `singletonSurfaceTint`, and `organization.updated` lists it in `changed`. Each theme now gets its own brand color : the root layout emits `--brand-light` / `--brand-dark` (plus foregrounds and accents) through the shared [`brandThemeVars`](services/web/src/lib/brand-theme.ts), and `globals.css` maps `--primary` to the active one. A color below 2:1 against a theme's background is adapted there by the new `adaptBrandColor` in [`@monark/common/color`](packages/common/src/color.ts) (lightness moved, hue kept, chroma eased, until 3:1), so black is lifted to `#606060` in dark mode and white darkened in light mode, while Monark orange and the default blue are untouched. New `Organization.primaryColorDark` and `primaryColorDarkMode` columns ([migration](packages/db/prisma/migrations/20260928130000_add_organization_primary_color_dark/migration.sql), [migration](packages/db/prisma/migrations/20260928140000_add_organization_primary_color_dark_mode/migration.sql)) let dark mode use the primary as is, adapt it (default) or use an exact color. The organization page stays short : a notice when the primary will be adjusted for accessibility, and an **Advanced options** section holding the optional **Dark theme color** (empty = adaptive) and the **Background tint** slider. `ColorInput` stays generic : it shows an unset value as a pipette ("pick a color") rather than a fake white swatch and gains an opt-in `clearable` "No color" action. `text-primary` renders as a contrast-safe `--primary-ink` in both themes (the brand capped at lightness 0.55 in light mode, raised to at least 0.7 in dark mode). `BRANDING_ACCENT` now applies only while `BRANDING_PRIMARY` is the primary in use : an org `primaryColor` also drives `--brand-accent`, so the notification badge and gradients follow the org brand instead of keeping the deployment accent.
