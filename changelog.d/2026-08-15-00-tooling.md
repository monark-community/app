- 2026-08-15: Tooling — **parallel-agent workflow** (worktrees, small commits, PRs, conflict-free changelog). Up to 8 agents were sharing one working directory and one git index ; every file edit risked colliding with another agent's in-flight change, and `CHANGELOG.md`'s single shared insertion point was a recurring merge hotspot. [CLAUDE.md](CLAUDE.md) now documents the fix as the required workflow (§ Parallel work): start every task in its own `git worktree` (`claude --worktree <name>`, built into the CLI) on its own `<type>/<slug>` branch, commit small and often since isolation removes the risk of catching someone else's WIP, and land as a PR into `develop` instead of a direct push, with the existing CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) as the real gate rather than a local run against a shared tree. CHANGELOG entries move from direct edits to per-PR fragments under [changelog.d/](changelog.d/README.md) (one new file per PR, so two branches can never conflict on the same line) ; `pnpm changelog:compile` ([tools/compile-changelog.ts](tools/compile-changelog.ts)) folds pending fragments into `CHANGELOG.md` under `## [Unreleased]`, newest first, and runs automatically on every push to `develop` ([.github/workflows/changelog-compile.yml](.github/workflows/changelog-compile.yml)) so no PR ever touches the compiled file directly.
