- 2026-05-08: Integration-suite rescue + post-merge threshold gate. The first merged-coverage run on local (after the merge infra landed earlier today) surfaced that 6 of 8 integration suites had pre-existing test bugs that turbo's "bail on first failure" had been hiding ; only one package's failure ever surfaced in CI logs while the rest were silently cancelled. This batch fixes every one and lands a CI gate that breaks the build if any package drops below its measured baseline.
  - **Pre-existing test bugs found + fixed.** Six categories : (1) `db.role.upsert({ where: { key_organizationId: { key, organizationId: null } } })` — Prisma rejects null in compound-unique `where` clauses even when the underlying `@@unique([key, organizationId])` constraint allows null-distinct rows in PG ; replaced with `findFirst({ where: { key, organizationId: null } })` + create across [packages/rbac/tests/integration/write.test.ts](monark/app/packages/rbac/tests/integration/write.test.ts), [read.test.ts](monark/app/packages/rbac/tests/integration/read.test.ts), [role-crud.test.ts](monark/app/packages/rbac/tests/integration/role-crud.test.ts), [packages/organizations/tests/integration/invites.test.ts](monark/app/packages/organizations/tests/integration/invites.test.ts), [packages/notifications/tests/integration/subscribers.test.ts](monark/app/packages/notifications/tests/integration/subscribers.test.ts). (2) `seedUser` in [packages/users/tests/integration/data.test.ts](monark/app/packages/users/tests/integration/data.test.ts) used `??` on `emailVerifiedAt` / `disabledAt` / `deletedAt`, which converts an explicit `null` override back to the default value (since null is nullish) ; switched to `'key' in overrides` so explicit-null seeds round-trip. (3) `subscribers.test.ts` truncated `Role` in `afterEach` but seeded built-in roles in `beforeAll`, so every spec after the first failed to find SYSADMIN/ADMIN ; moved seeding to `beforeEach`. (4) `dispatch.test.ts` never called `registerCoreNotificationKinds()` so `notify("auth.password-changed", …)` short-circuited with empty deliveryIds ; added the registration call. (5) `read.test.ts` imported `assignRole` from `data.ts` instead of `write.ts` ; corrected the import. (6) `RoleAssignment_roleId_fkey` is `ON DELETE RESTRICT` in the migration despite the schema declaring `Cascade` (drift) ; reordered every rbac test's `afterEach` to clear `RoleAssignment` before `Role` to satisfy the constraint. Several smaller fixes too : `role-crud.countActiveAssignments` test referenced fake user IDs via `createMany` ; `write.test.ts` referenced fake `grantedById` / `revokedById` actor IDs ; both now seed the corresponding User rows. The `webhooks/rotateEndpointSecret` function returned `Promise<void>` but the integration test expected the updated row ; promoted the return type to `Promise<EndpointWithSubs>` (the router caller already discarded the value, so no other callers affected). The `api/server` cron-auth happy-path expected `body.processed` but `processExpiredDeletions` returns `{ attempted, succeeded, failed }` ; updated the test assertion to match the actual shape.
  - **Post-merge threshold gate** ([tools/merge-coverage.ts](monark/app/tools/merge-coverage.ts)). Per-package floors live in a `THRESHOLDS` map at the top of the merge script ; after the merge produces each package's `coverage-final.json`, the script reads the merged percentages and exits non-zero if any metric dips below its floor. Floors are set 5pts below the measured baseline (rounded to nearest 5%) so a regression breaks the build but the floor doesn't sit on the current number. Per-metric instead of single-floor because measured branches and lines diverge meaningfully (e.g. `services/api` is 73% lines but 53% branches, `services/web` is 8% lines but 89% branches because the few covered files are well-tested). Vitest's per-run `coverage.thresholds` config stays commented out — the merged number is what matters, and per-run thresholds would either fail spuriously (unit-only run for a package whose data layer is integration-tested) or duplicate the merge-script gate.

The threshold gate locks in the measured baseline ; any future change that drops a metric below its floor breaks `pnpm coverage:merge` and the corresponding CI step, so coverage erosion can't slip past review. Floors will ratchet up as we add suites against the surfaces still under-covered (the test plan calls out `services/web` action handlers + `users` data layer + `feature-flags` write/sync paths as the next batch).
