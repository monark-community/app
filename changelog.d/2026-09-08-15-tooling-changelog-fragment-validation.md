- 2026-09-08: Tooling: **CI now validates changelog fragments**, and three broken ones are fixed. [compile-changelog.ts](tools/compile-changelog.ts) already rejected a fragment whose links are written relative to `changelog.d/` — they compile into `CHANGELOG.md` at the repo root, so a leading `../` points one level above the repo and the link is dead once compiled. Nothing ran that rule on a PR, so three fragments landed with it broken and took the whole `Compile changelog` workflow down with them : because it runs post-merge on `develop` and its failure is not a check on anyone's commit, `CHANGELOG.md` silently stopped being regenerated. The existing `--check` mode is the wrong gate for a PR — it compares against `CHANGELOG.md`, which a branch deliberately leaves stale — so this adds `--validate`, which runs the per-fragment rules and nothing else, exposed as `pnpm changelog:check` and wired into the `repo-checks` job in [ci.yml](.github/workflows/ci.yml).
