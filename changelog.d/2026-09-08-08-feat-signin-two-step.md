- 2026-09-08: Split email sign-in into two steps. [/signin](<services/web/src/app/(anon)/signin/page.tsx>) now asks for an address, then a password ; the social buttons sit above the first step and disappear once an address is entered, so the screen the user lands on offers one field rather than four. Step one is deliberately local: it makes no server call, so advancing reveals nothing about whether an account exists, the same stance `requestPasswordResetAction` takes. Both steps live in one `<form>` and step two carries a hidden `autocomplete="username"` input, so password managers still see an identity + secret pair. The form moved into [`SignInFormView`](<services/web/src/app/(anon)/signin/signin-form-view.tsx>), which has no server action in its import graph and is therefore mountable by the screenshot harness and by component tests. Worth being clear about what this is not: step two still posts email + password to the same action, so it is not a meaningful bot defence, only a tidier first screen and the shape sign-in would need to branch on an address later.
- 2026-09-08: Added a crossfade between auth steps. [`AuthStepTransition`](services/web/src/components/auth-step-transition.tsx) holds the outgoing content frozen while it fades, swaps, then fades the new step in, easing the wrapper's height between the two measured sizes so the card resizes instead of jumping. The card itself never unmounts, so sign-in reads as one surface changing its mind. Between _routes_ (sign-in to sign-up, sign-in to forgot-password) an [`(anon)/template.tsx`](<services/web/src/app/(anon)/template.tsx>) fades each screen in on arrival ; that is an approximation, not a true crossfade, because the outgoing screen is gone before the incoming one mounts. A single card persisting across routes would mean hoisting `AuthScreen` into a shared layout and unifying the `(anon)` and `/auth/*` route groups, which each render their own copy today. Both transitions honour `prefers-reduced-motion`.
