- 2026-08-02: Calendar — added per-user view settings: hide/show weekends, first day of week (Sun/Mon), default view, 12h/24h time format, and a working-hours highlight, edited from a new "view options" popover in the calendar toolbar ([calendar-shell.tsx](<monark/app/services/web/src/app/(authed)/calendar/calendar-shell.tsx>)). Stored via the users metadata sidecar as a single JSON blob (new `calendarRouter.settings.get/set/reset`, [server/index.ts](monark/app/packages/calendar/src/server/index.ts)), gated on `ctx.userId` only since it's self-owned data — the generic `trpc.users.metadata.*` procedures were not usable here since they `requirePermission` unconditionally even for a caller's own data. Consolidated three duplicated, hardcoded-Sunday-first `getWeekStart` copies (and two duplicated weekday-label arrays) into a new shared [date-utils.ts](monark/app/packages/calendar/src/client/date-utils.ts), also fixing a latent bug where month view's weekend tinting was column-index-based (silently wrong once week-start becomes configurable) rather than date-based. Hiding weekends does true column filtering (weekday columns expand to fill the width, not just CSS-hidden) across week and month view's multi-day/all-day event layout math. All defaults reproduce prior hardcoded behavior exactly, so this ships additive with no visible change until a user opens the popover. 17 new unit tests for the date-math edge cases ([date-utils.test.ts](monark/app/packages/calendar/tests/date-utils.test.ts)).
