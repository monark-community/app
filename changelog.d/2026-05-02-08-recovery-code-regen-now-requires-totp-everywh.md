- 2026-05-02: Recovery-code regen now requires TOTP everywhere ; the no-TOTP shortcut shipped earlier in the reminder modal is removed. The shortcut (gated on a recent unacknowledged recovery-code use) made it possible for an attacker who stole one recovery code to mint a fresh batch and lock the legitimate user out of the recovery path entirely — a one-shot incident upgraded to persistent recovery-code takeover. Industry norm (Google, GitHub, AWS) is TOTP-required for regen, full stop ; the lost-authenticator user proceeds via account recovery (support / ID verification), not in-app self-service. Dropped from server: `regenerateRecoveryCodesAfterUse`. Dropped from tRPC: `auth.totp.regenerateRecoveryCodesAfterUse`. Modal: in `acknowledgeLow` mode the "Regenerate now" button now reveals the inline TOTP input (same flow as `suggestRegen` + `mustRegenerate`) instead of firing immediately ; in `mustRegenerate` the `hasUnacknowledgedUse` branch is collapsed away — every regen path now goes through `regenerateRecoveryCodes({ code })`. The 0-codes blocking modal stays blocking ; users without authenticator access have to go through out-of-band account recovery, which is the correct dead-end.
