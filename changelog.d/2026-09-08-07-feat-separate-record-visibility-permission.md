- 2026-09-08: RBAC / Data Models: **split row visibility out of `data-models.manage-schema` into its own capability**, `data-models.view-all-records`. The router's [`recordAccessContext`](packages/data-models/src/server/router.ts) resolved its row-level `bypass` from `manage-schema`, so "can add a field to a model" also silently meant "can read every record in it, including rows a colleague restricted via `DataRecordRoleAccess`". Those are different powers, and conflating them makes an HR / payroll / legal data wall impossible to express: there was no way to have a data steward who shapes a database without reading everyone's rows. Visibility now has its own permission, checked at all four bypass sites ([recordAccessContext](packages/data-models/src/server/router.ts), the [watcher fan-out](packages/data-models/src/server/record-watch-subscriber.ts), the [global-search source](packages/data-models/src/server/search-source.ts), and the automation [data nodes](packages/automation/src/server/nodes/data.ts)) ; `manage-schema` keeps every schema-editing gate it already had. This follows how mature systems separate the two (Salesforce gates sharing-rule bypass on an explicit `View All Data` rather than on being an admin ; Postgres has `FORCE ROW LEVEL SECURITY` so even a table owner is subject to RLS). **The upgrade is a no-op**: migration [20260908120000_split_record_visibility_permission](packages/db/prisma/migrations/20260908120000_split_record_visibility_permission/migration.sql) backfills the new permission onto every role that currently holds `manage-schema`, so nobody loses visibility they have today ; the grant is simply now revocable. Built-in ADMIN / SYSADMIN are deliberately not backfilled, since `hasPermission` short-circuits for them. Eight new integration tests cover both halves of the split, the 404-not-403 leak invariant, and the backfill itself, which is executed **from the migration file on disk** so the test fails if the statement is ever edited into something that stops backfilling. Groundwork for MQL-scoped record permissions, where a revocable visibility capability is what makes a scope meaningful.
