- 2026-08-03: List screens — **simplified the crowded mobile toolbar app-wide.** On a phone a list used to stack ~6 controls above the rows (search/query, filters, sort, follow, columns gear, create). It now collapses to at most three, plus a floating action button, while desktop stays byte-for-byte the same. New shared pieces in [components/patterns](monark/app/services/web/src/components/patterns): **`ListMobileBar`** (`md:hidden` consolidated bar — a `lead` control, an optional 🔍-expandable search, and one ⋯ options trigger), **`CreateFab`** (mobile-only thumb-reachable create button, pinned bottom-right, rendered only when no detail panel/bulk bar occupies the screen), plus **`TableTools`** gaining a `mode="auto"|"inline"|"sheet"` (decoupled from the viewport so both forms mount behind CSS wrappers) and an `extraSections` slot that appends a "Follow this list" row into the mobile options sheet. [`FilterBar`](monark/app/services/web/src/components/patterns/filter-bar.tsx) gained an **opt-in** `mobileOptions` prop: when set, its roomy row goes `hidden md:flex` and a `ListMobileBar` (search leads, `mobileOptions` is the ⋯ sheet) takes over on mobile — omitting it keeps the old behaviour, so the change is additive. Wired the data-model record list ([records-list.tsx](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/records-list.tsx>)) as a bespoke **Views-first** bar (the saved-[`ViewsMenu`](<monark/app/services/web/src/app/(authed)/data/models/[modelKey]/views-menu.tsx>) picker leads via a new `asLead` full-width trigger that names the active view, the MonarkQL query field is one 🔍 tap away, sort+columns+follow live in the ⋯ sheet, create is the FAB), and the admin lists (organizations, users, rbac roles, webhooks, data models, secrets) via the `FilterBar mobileOptions` path (service-accounts left as-is — search + create only, already uncluttered).
