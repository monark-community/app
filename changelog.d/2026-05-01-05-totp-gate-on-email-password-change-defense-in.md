- 2026-05-01: TOTP gate on email + password change. Defense-in-depth on top of the existing current-password re-entry: when the user is TOTP-enrolled, both [`changePasswordAction`](<monark/app/services/web/src/app/(authed)/account/actions.ts>) and [`requestEmailChangeAction`](<monark/app/services/web/src/app/(authed)/account/actions.ts>) require a fresh authenticator code (verified through `auth.totp.verifyCode`) before applying the change. Without it, an attacker holding a live session AND the current password could rotate either credential and lock the legitimate user out before they noticed. Non-enrolled users are unaffected ; the code field only renders when `auth.totp.status` reports enrolled. New error codes `totpRequired` + `invalidTotpCode` on both actions ; matching i18n strings (en + fr) under `account.password.{labels.totpCode, totpHint, errors.totpRequired, errors.invalidTotpCode}` + `account.emailChange.{labels.totpCode, totpHint, errors.totpRequired, errors.invalidTotpCode}`.
