- 2026-09-08: Added social sign-in to `@monark/auth`, with GitHub as the first provider; a "Continue with GitHub" button on [/signin](<../services/web/src/app/(anon)/signin/page.tsx>) + [/signup](<../services/web/src/app/(anon)/signup/page.tsx>) driven by the anon-safe `auth.oauth.providers` query, a [/auth/callback](../services/web/src/app/auth/callback/route.ts) route that trades the PKCE code for a session, and [`provisionOAuthUser`](../packages/auth/src/server/oauth.ts) which creates the shadow `User` row Supabase never told us about (idempotent, re-reads identity from the Supabase admin API rather than trusting the caller, emits `user.signed-up` with the new `provider` field). Password and social sign-in now converge on [`completeSignIn`](../services/web/src/lib/complete-sign-in.ts) so device recognition, the TOTP gate, pending invites and the deletion-grace bounce can't be skipped by a second entry point. A provider-verified email is required (`email-unverified` refusal) and an address already owned by another `User` row is refused case-insensitively (`email-collision`) rather than guessed at; both surface as banners on /signin. Accounts with no password get a "Set a password" variant of the security card ([`setPasswordAction`](<../services/web/src/app/(authed)/account/actions.ts>), which refuses once a password exists) plus a read-only "Connected accounts" list, and email change defers until a password exists. Configured per deployment through the api's `AUTH_OAUTH_PROVIDERS` env plus the `[auth.external.github]` stanza in [supabase/config.toml](../supabase/config.toml) (shipped disabled), behind the `auth.oauth` kill-switch flag. Verified end to end against a real GitHub OAuth app. Nothing in the provisioning path is provider-specific, so Google and Microsoft follow as their own changes stacked on this one; Apple stays deferred.
