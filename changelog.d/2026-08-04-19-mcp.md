- 2026-08-04: MCP — **`@monark/mcp`, a Model Context Protocol server** that exposes Monark to AI agents (Claude Desktop, Cursor, …) as native tools ([services/mcp](monark/app/services/mcp)). It's a **thin stdio client of the public REST API** : each of its 9 tools (`monark_whoami`, `monark_list_models`, `monark_get_model`, `monark_list_model_fields`, `monark_list_records`, `monark_get_record`, `monark_create_record`, `monark_update_record`, `monark_delete_record`) is one authenticated call to a `/api/v1` endpoint, so **all auth, RBAC, the per-key permission ceiling, service-account rules, and rate limits are enforced server-side exactly once** — the MCP layer holds no authorization logic of its own and works against any Monark deployment. Config is two env vars the agent host passes (`MONARK_API_URL`, `MONARK_API_KEY` — an `mrk_` key) ; the server acts as that key, so a limited/service-account key scopes what the agent can do. Structure : `config` (validate env) → `client` (`MonarkClient` over `/api/v1` + `MonarkApiError`) → `tools` (agent-facing descriptions + zod input) → `server` (SDK `registerTool` wiring, JSON result / `isError` on failure) → `index` (stdio entrypoint ; diagnostics to stderr, never stdout). 17 tests : the client (request building, query omission, error mapping, 204), the tool→REST mapping, config validation, and a **protocol-level smoke test** driving a real MCP `Client` over the SDK's in-memory transport (lists the 9 tools, calls one, maps an API error to `isError`, rejects bad input before the client). `typecheck` (25/25) + `eslint` + all gates green ; CLI errors cleanly when unconfigured. This is the third leg of the Public API / MCP / BYOA plan, and it leans entirely on the REST facade + key model already shipped. Follow-ups (noted in the [README](monark/app/services/mcp/README.md)) : a bundled `npx @monark/mcp` binary, MCP resources/prompts, and a remote HTTP/SSE transport.
