- 2026-08-02: Public API (integration tests + error-mapping hardening) — an end-to-end HTTP suite for `/api/v1` that drives the **real Express app over supertest** against a Postgres testcontainer, with a real `mrk_` key authenticating a real org-ADMIN owner ([public-api.test.ts](monark/app/services/api/tests/integration/public-api.test.ts)). 13 cases cover the whole request path together : the unauthenticated-but-flag-gated `openapi.json`, auth (no key / bad key → 401, valid key → 200 + `X-RateLimit-*` headers), reads (`/models`, `/models/:key/records`, `/records/:id`, unknown id → 404), a write with a write-scoped key (200), scope enforcement (read-only key → 403), body validation (→ 400), revocation (revoked key → 401), and the `public-api.enabled` kill switch (flag off → 404 even with a valid key). Building the suite surfaced a real robustness gap : the facade's error→HTTP mapping ([mount.ts](monark/app/services/api/src/public/mount.ts)) classified errors with `instanceof`, which is unreliable when an error crosses package boundaries (a domain error thrown inside a tRPC procedure, re-wrapped by the caller) or when the module graph holds more than one copy of a class — so a `NotFoundError` re-wrapped by the caller fell through to a 500. Reworked `sendError` to classify by **shape** (`name` / `code` / `statusCode` / `issues`) instead of `instanceof`, preferring a wrapped domain error's own status/code/message ; every case now maps correctly regardless of which module instance minted the error. Full suite green (24 api integration tests incl. the prior 11 server tests) ; `typecheck` (all packages) + `check:tiers` / `check:modules` / `check:i18n`.
