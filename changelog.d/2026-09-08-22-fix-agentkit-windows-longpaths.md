- 2026-09-08: Tooling — `agentkit wt rm` now survives Windows' 260-character path limit. pnpm's `node_modules/.pnpm/<pkg>@<version>_<hash>/…` routinely reaches 290 characters, so `git worktree remove` died with `Filename too long` partway through deleting a worktree ; worse, it had already deregistered the worktree by then, leaving a directory that `git worktree remove` would no longer touch (`is not a working tree`) and that nothing else cleaned up, with its port slot still reserved. Three fixes: every git call the kit makes now passes `-c core.longpaths=true` on Windows, scoped per invocation so the kit does not depend on a global config the operator may never have set ; `remove()` recognises the orphaned-directory state and owns the cleanup instead of refusing it ; and when git still cannot delete the tree, the fallback is `robocopy` mirroring an empty directory onto it, which is the only thing on Windows that reliably clears a deep `node_modules` (both `fs.rmSync` and `Remove-Item` give up partway, even through the `\\?\` device path). The port slot is released in every one of those paths, including when the directory is already gone. See [.claude/agentkit/lib/worktree.mjs](.claude/agentkit/lib/worktree.mjs).
