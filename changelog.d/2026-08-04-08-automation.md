- 2026-08-04: Automation — the event-trigger picker no longer offers `automation.*` events (`automation.created` / `updated` / `deleted` / `run-started` / `run-succeeded` / `run-failed`). The run-enqueue subscriber ignores those (`startsWith("automation.")`) to avoid feedback loops, so they were dead options : selecting one produced an automation that could never fire. Extracted a shared `isTriggerableEventType(type)` predicate in [subscriber.ts](monark/app/packages/automation/src/server/subscriber.ts), used by both the subscriber and the picker's `eventTypes.list` in [router.ts](monark/app/packages/automation/src/server/router.ts), so the offered set can't drift from the fireable set. The same predicate also drops `feature-flag.flipped`, which is unroutable as a trigger — its org / user is nested under `scope` (not the top-level `resolveEventOrgIds` reads) and a global flip has no org at all, so it too could never fire. The events stay registered and webhook-subscribable ; only the automation trigger picker hides them. `tsc` + 47 automation unit tests green.
