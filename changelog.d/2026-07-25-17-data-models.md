- 2026-07-25: Data models — a `FORMULA` field's result type is now **inferred**, not configured. Dropped the `resultType` picker from the schema builder's formula editor ([formula-config.tsx](<monark/app/services/web/src/app/(authed)/admin/data-models/[id]/formula-config.tsx>)) and the `resultType` key from the field config ([field-types.ts](monark/app/packages/data-models/src/contracts/field-types.ts), config is now just `{ expression }`). A new `inferResultType` ([formula.ts](monark/app/packages/data-models/src/contracts/formula.ts)) derives the type from the expression's outermost operation (comparisons/logic → BOOLEAN, arithmetic → NUMBER, `&`/text functions → TEXT, date functions → DATE; a bare reference or a mixed-branch `if`/`coalesce` falls back to TEXT). The override is an explicit cast — four new functions `toNumber` / `toString` / `toBool` / `toDate` both coerce the value and pin the type from the outermost position. Compute-on-write ([data.ts](monark/app/packages/data-models/src/server/data.ts)) and the client `FieldDef` adapter ([data-field-adapter.ts](monark/app/services/web/src/components/fields/data-field-adapter.ts)) now compute the type via `inferResultType` instead of reading it from config ; the editor shows the inferred type read-only as a badge. Feels more natural (like Notion) and removes a drift-prone redundant field. Updated i18n (`…formula.resultLabel` replaces `resultType`, help text documents the casts, en+fr) and the Prisma enum comment. Tests: engine unit specs gained cast-function + `inferResultType` coverage ; integration configs dropped `resultType` (inference yields the same types). RBAC/events/notifications/webhooks/flags unchanged (pure refactor of an existing additive field).
