- 2026-07-27: Automation — pre-flight (pre-run) validation, shared by the editor and the server. A new pure, descriptor-driven validator ([contracts/validate.ts](monark/app/packages/automation/src/contracts/validate.ts) `validateGraph`) checks a graph before it runs: a **required input** that's neither filled nor wired, **no trigger** / more than one, a **trigger with no event** (satisfied by the node's `event-type` field in the editor or the automation's stored `triggerEventType` on the server), an **orphan** node not reachable from the trigger (warning), an unknown node type, and a **cycle** (error today; a comment marks where deliberate loops will be exempted once loop nodes with exit conditions land). Because it's serializable it runs both places: the editor imports it (via the `@monark/automation/contracts` path-mapped source) to show a live **"N issues"** toolbar dropdown — each row jumps to its node — mark the offending config field with a red asterisk, and **disable Run while there are errors** ([automation-editor.tsx](<monark/app/services/web/src/app/(authed)/automation/[id]/automation-editor.tsx>)) ; the server runs the same check in `runNow` ([router.ts](monark/app/packages/automation/src/server/router.ts) `assertRunnable`) and rejects a misconfigured graph up front with an itemized `ValidationError` (400) instead of letting a node blow up mid-run. Warnings (orphans) inform but never block. New `automation.editor.preflight.*` i18n (en + fr) ; 9 validator unit tests + the existing 15 integration tests green ; `typecheck` (web + automation) + `lint` + `check:i18n` (1611 keys × 2) green.
