- 2026-07-05: Shared UI — extracted a standard `DragHandle` chip for resizable / draggable edges. The little pill grip was hand-rolled in three places with drifting styles ; it now lives once in [`@monark/components/ui/drag-handle`](monark/app/packages/components/src/ui/drag-handle.tsx) and is reused by the calendar event's bottom resize handle ([day-event-block.tsx](monark/app/packages/calendar/src/client/ui/day-event-block.tsx), which also dropped a duplicated inline copy and its `resizeHover` state), the detail-panel resize edge ([table-detail-layout.tsx](monark/app/services/web/src/components/patterns/table-detail-layout.tsx), whose previously-invisible edge now shows the chip on hover / drag), and the data-table column resize edge ([data-table.tsx](monark/app/services/web/src/components/patterns/data-table/data-table.tsx)). `DragHandle` renders the hit area, reveals its grip on hover (always on touch) unless `active`, and takes an `orientation` (grip shape + resize cursor), an optional `color` for the calendar's per-event tint, and an optional `highlight` that tints the whole strip a neutral `muted-foreground/20` on hover / drag (a revival of the panel's old hover rail, recoloured neutral, enabled on the detail-panel edge; off elsewhere). The neutral grip fill is a fully opaque `color-mix` tone rather than a translucent `muted-foreground/40`, so it holds its contrast over the tinted rail instead of washing out. The upstream `@monark/ui` drawer grabber ([ui/components/ui/drawer.tsx](monark/ui/components/ui/drawer.tsx)) was aligned to the same grip visual as plain markup (it sits outside the app's module graph). Registered the shared package with an `@source` directive in [globals.css](monark/app/services/web/src/app/globals.css) so Tailwind v4 generates classes authored there. The calendar package takes a new `@monark/components` dependency (a non-tiered UI package, so no boundary crossed).
