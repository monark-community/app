- 2026-05-05: RBAC built-ins split into `SYSADMIN` (platform-tier) + `ADMIN` (org-tier). The previous single `ADMIN` role overloaded both scopes ; an assignment's `organizationId` decided which kind of admin you were, which made "two admin permissions" awkward to reason about. The split puts each tier on its own row with locked scope :
  - **`SYSADMIN`** ; platform-only (assignment.organizationId must be null), code-side "all permissions across every org" short-circuit, never UI-assignable. Granted via the new [tools/sysadmin.ts](monark/app/tools/sysadmin.ts) CLI (`grant` / `revoke` / `list` subcommands) or a direct SQL insert. The tRPC `adminAssignRole` and `adminRevokeRole` procedures both refuse the SYSADMIN role with a `FORBIDDEN`, so an org-tier admin can't escalate or de-platform the sysadmin tier through the admin UI. `listRolesForOrg` filters SYSADMIN out, so it never appears in /admin/rbac or in the user-detail role picker.
  - **`ADMIN`** ; org-only (assignment.organizationId must be non-null), same code-side "all permissions in this org" short-circuit. Listed in /admin/rbac and assignable via /admin/users like any other org-tier role. The data layer enforces scope at write time : `assignRole` rejects SYSADMIN with a non-null orgId and ADMIN with a null orgId.
  - Permission resolution short-circuits on either built-in via a shared `BUILTIN_ALL_PERMISSIONS_KEYS` set ; `findActiveAssignments` includes platform-tier SYSADMIN regardless of the requested orgId so a sysadmin passes every org-scoped check, ADMIN inclusion is gated on the assignment's orgId matching the requested one.
  - Schema migration at [packages/db/prisma/migrations/20260505160000_split_sysadmin_admin_roles](monark/app/packages/db/prisma/migrations/20260505160000_split_sysadmin_admin_roles/migration.sql) seeds the new SYSADMIN row and repoints every existing platform-tier (organizationId IS NULL) ADMIN assignment to it. Org-tier ADMIN assignments stay as-is.
  - `validateRoleKey` in the rbac write layer now reserves both `ADMIN` and `SYSADMIN` so operators can't accidentally create a custom role colliding with a code-side guard.
