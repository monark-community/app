# services/web — Vercel deploy notes

The web service deploys to Vercel. [vercel.json](./vercel.json) carries the deploy spec ; this file documents the choices it encodes and the manual UI steps that don't fit in JSON.

## Project setup (one-time)

In the Vercel dashboard :

1. **Import** the GitHub repo ; pick **`services/web`** as the Project Root. Vercel auto-detects pnpm + workspaces from there.
2. **Framework Preset :** Next.js (auto-detected).
3. **Region :** pin to a single region (Project Settings → Functions → Region) that matches the api's Render region — cross-region tRPC calls otherwise add 50–200ms per round-trip.
   - api on Render `oregon` → Vercel `sfo1` or `pdx1`
   - api on Render `ohio` → Vercel `iad1` or `cle1`
   - api on Render `frankfurt` → Vercel `cdg1` or `fra1`
4. **Environment variables :** the browser-visible ones live in
   [`services/web/.env.example`](./.env.example) — that file, not the api's, is
   the list to work from (the api's `.env.example` carries the server-side
   twins). Everything without a `NEXT_PUBLIC_` prefix stays server-only on
   Render, except the two Supabase server values this service needs for its
   own server actions. At minimum :
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `NEXT_PUBLIC_API_URL` (the Render web service URL, e.g. `https://api.monark.io`)
   - `NEXT_PUBLIC_APP_URL` (the Vercel URL, e.g. `https://app.monark.io`)
   - `SUPABASE_URL` + `SUPABASE_SECRET_KEY` — **server-only**, never
     `NEXT_PUBLIC_*` ; the browser must not see the secret key.
   - The `NEXT_PUBLIC_BRANDING_*` set, mirroring the `BRANDING_*` values on
     Render, so page titles, the wordmark and the brand colour match on the
     browser side. **Quote any hex value** (`NEXT_PUBLIC_BRANDING_PRIMARY="#2563EB"`) —
     an unquoted leading `#` is read as a comment and resolves to an empty
     string. See [white-label.md](../../docs/technical-documentation/white-label.md).

## What's encoded in vercel.json

- **`buildCommand`** runs from the workspace root so pnpm sees the workspace + the `@monark/*` packages this service depends on. `pnpm gen` regenerates the event + router glue ; without it a fresh checkout would build against a stale generated router.
- **`installCommand`** runs `pnpm install --frozen-lockfile` at the workspace root so every workspace package resolves. Vercel caches `node_modules` between builds when the lockfile is unchanged.
- **`ignoreCommand`** skips the build when the diff doesn't touch `services/web` or any `@monark/*` package it depends on. Vercel runs the command against the last successful deploy ; non-zero exit = build, zero exit = skip. Saves a deploy + a cold start when only api / docs / unrelated packages change.

## Security headers

HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, and the UA-CH `Accept-CH` / `Critical-CH` opt-in are all generated by [next.config.ts](./next.config.ts)'s `headers()` function. Vercel evaluates that at build time and serves the headers from the edge cache, so middleware doesn't run for every request just to attach them.

`headers()` returns an empty array in dev (`NODE_ENV !== "production"`) ; HSTS on localhost would lock subsequent http://localhost requests, and the strict CSP would block Next's HMR runtime + the dev error overlay.

The CSP's `connect-src` is built from `NEXT_PUBLIC_API_URL` + `NEXT_PUBLIC_SUPABASE_URL` at build time ; if either env var is missing the resulting CSP only allows `'self'` and the app immediately surfaces the misconfiguration.

## Cron

The web service has no scheduled jobs. The api's two crons (`process-account-deletions`, `sweep-webhook-deliveries`) live on Render — see [../../render.yaml](../../render.yaml).
